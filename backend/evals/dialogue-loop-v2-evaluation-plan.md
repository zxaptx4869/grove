## 模型与快照条件

- 两臂文本模型固定为 `deepseek/deepseek-chat`，向量模型固定为
  `doubao/doubao-embedding-vision-251215`；配置必须由应用现有设置和密钥存储读取。
- 不改模型、温度、输出上限或提示词后付费重跑。文本输出上限保持每次 2000 token。
- 运行开始时从 demo 开发库制作一个只读一致 seed，再复制为新旧两臂独立数据库；两臂
  Provider 配置、身份、Workspace、业务数据和附件指纹必须相同。
- 新快照的业务指纹若与第一版不同，报告必须标为非严格数据对照，不把差异归因给架构；
  不为追求第一版条数而向原库或副本写入测试 Entry。
- 预检至少要求“房子装修”和“新疆旅行”项目存在，房子装修有不少于五条正式记录；
  所有预期数量和排序继续由快照独立 SQL 生成，不硬编码条数或 Entry ID。

## 固定输入

原三组 A-C 保持不变：

| 组 | 四轮输入 |
|---|---|
| A | 我现在知识库里一共多少条知识 → 分项目汇总给我 → 其中房子装修项目有多少条 → 回到全部项目，分别统计数量 |
| B | 甲醛是什么，我知识库里有说甲醛哪里来的，以及怎么除甲醛吗 → 环保等级呢 → 我的知识库里关于这些等级有哪些记录 → 只根据我的知识库总结这些等级，没有的就说没找到 |
| C | 列出房子装修项目最近更新的五条知识 → 第三条展开说说 → 先不查知识库，聊聊怎样记笔记更容易复习 → 回到刚才那个五条列表，第三条的来源是什么 |

两组未写入 Agent 提示词的表达变体：

| 组 | 四轮输入 |
|---|---|
| D | 先告诉我房子装修项目一共有多少条正式记录 → 换成新疆旅行项目呢 → 这个项目里只算 method 类型 → 取消类型限制，回到这个项目的全部正式记录 |
| E | 把房子装修项目最近更新的五条记录列给我 → 展开第二项 → 先别查库，聊聊怎样安排间隔复习 → 回到前面的列表，第二项来自哪份材料 |

执行规模为五组 × 四轮 × 两臂，最多 40 条用户消息，只跑一批，不自动追加、补跑或
重复。入口为 `.venv/bin/python -m evals.dialogue_loop --compare --live --suite v2`，仅在
用户另行批准后使用。

## 冻结预算

| 层级 | 第二版上限 |
|---|---|
| 每轮文本请求 | 12 次，含重试和一次预留收尾 |
| 每轮向量请求 | 4 次 |
| 新循环工具动作 | 8 次，并发最多 2 |
| 每轮材料 | 最多 30 个不同 Entry、20 个 Evidence |
| 输入 | Provider 单请求 12000 token；确定性估算资料软阈值 9000 |
| 输出 | 每次 2000 token |
| 时间 | 求解 120 秒，预算内收尾最多 15 秒 |
| 整批 | 文本 192 次、向量 64 次、用户消息 40 条 |

长度估算覆盖结构化消息、工具 schema、输出 schema 和本轮新增工具材料，按 JSON UTF-8
字节数除以 3 向上取整。它只用于保守门禁；实际 token 以 Provider／框架 usage 为准，
缺失时标记未知。第二版增加消息数但不增加整批模型请求预算，达到硬上限即停止未执行项。

## 停止与验收

- 权限、Workspace、原库隔离、业务指纹或两臂 Provider 一致性失败时不启动真实调用。
- 相同基础设施异常第二次发生、整批预算耗尽或业务材料变化时停止整批，不补跑。
- 单轮模型／工具失败保留原始终态；依赖列表未产生的追问标记 blocked。
- 每轮核对明确总数、项目与数量对应关系、准确列表顺序、当前 Evidence 和实际条件；
  每组另评整段四轮任务是否完成。
- 自动检查通过仍不等于语义理解通过。真实报告需人工逐轮审阅，并继续区分架构效果、
  共享工具缺陷和旧流程数据库问题。
