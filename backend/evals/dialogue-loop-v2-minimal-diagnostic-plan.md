# 统一对话循环第二版最小真实诊断清单

## 状态与目的

- 状态：等待用户另行批准；本清单不授权真实模型调用。
- 标识：`prototype-v2-request-diagnostic-v1`，只诊断请求规则、输入估算和错误可观测性，
  不评价整段语义通过率，也不替代 A-E 固定对照。
- 沿用 `deepseek/deepseek-chat` 和 `doubao/doubao-embedding-vision-251215`，密钥只从应用配置读取。
- 运行前重新执行无模型预检和彩排，并要求 demo 业务指纹与
  `prototype-v2-20260907-160103` 相同；不同时只报告不可比，不写入原库补齐数据。

## 最小输入与受控收尾

只运行新循环：

| 子集 | 输入 | 诊断目的 |
|---|---|---|
| A1-A2 | “我现在知识库里一共多少条知识” → “分项目汇总给我” | 覆盖首轮、续聊、统计工具及可能的结构化纠正 |
| B1-B2 | “甲醛是什么，我知识库里有说甲醛哪里来的，以及怎么除甲醛吗” → “环保等级呢” | 覆盖工具较多的请求、历史增长和软阈值判断 |

若上述请求没有自然触发收尾，在同一隔离副本中使用程序已核验的 A 组统计材料执行一次受控无工具
收尾探针。探针只验证完整 instructions 与追加收尾指令是否同时到达模型边界，不计作用户语义结果，
且同样最多派发一次。

## 冻结预算与停止条件

- 最多 4 条用户消息；文本请求最多 20 次，向量请求最多 8 次，受控收尾包含在文本总额内。
- 每轮仍为文本 12、向量 4、工具 8、求解 120 秒、收尾 15 秒；输入软阈值 9000、硬上限 12000 token。
- 达到任一预算、业务指纹变化、Provider 不一致或相同基础设施异常第二次发生即停止；只跑一次，
  不补跑、不调参、不更换模型。

## 可回答的问题

- 每个已派发的主 Agent 请求是否都记录一个当前规则指纹、零个历史 system；纠正请求是否保持相同规则。
- 独立收尾是否同时具备当前完整规则和追加收尾指令，且仍只派发一次。
- Provider 形状估算对已派发请求的最小值、最大值和总体误差是多少；B1-B2 是否仍因明显高估触发收尾。
- 若自然出现 schema、引用、截断或 Provider 错误，报告能否保留具体类别、公开响应和异常链。

本诊断不能回答 C 组泛称类型误解是否修复，也不能回答新旧流程整体质量或正式接入价值。被门禁拦截的
请求仍没有真实 usage，只能报告估算和“实际未知”。
