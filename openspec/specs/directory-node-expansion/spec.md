# directory-node-expansion Specification

## Purpose
支持对现有目录节点进行 AI 拓展，基于节点、子树与项目上下文生成完整目标子树草稿，展示新增/保留差异供用户确认后应用。
## Requirements
### Requirement: 节点拓展入口
系统 MUST 在知识空间目录树节点的更多操作菜单与内容区（选中节点时）提供「AI 拓展」入口，MUST 由用户手动触发，MUST NOT 自动执行；发起时 MUST 校验目标节点属于当前 Workspace 的项目。项目已存在活跃草稿时，发起其他节点的拓展 MUST 先提示“将覆盖当前未应用的草稿”，用户确认后重开，未确认 MUST 保持原草稿不变。

#### Scenario: 树菜单发起拓展
- **WHEN** 用户在知识空间目录树某节点的更多操作菜单点击「AI 拓展」
- **THEN** 打开该节点的拓展工作区，针对该节点生成候选目标子树，不修改正式目录

#### Scenario: 内容区发起拓展
- **WHEN** 用户选中某节点后在内容区点击「AI 拓展」
- **THEN** 行为与树菜单发起一致，打开同一节点的拓展工作区

#### Scenario: 活跃草稿覆盖确认
- **WHEN** 项目已有活跃草稿且用户对另一节点发起拓展
- **THEN** 提示“将覆盖当前未应用的草稿”，确认后重开草稿并指向新目标节点，取消则保持原草稿

### Requirement: 拓展草稿生成
系统 MUST 在发起拓展时创建或复用目标节点归属的 `DirectoryDraft`（`kind=expand`、`target_node_id` 指向目标节点），跳过澄清直接进入异步生成，不触碰正式节点。Agent 输入 MUST 包含目标节点路径与说明、现有子树、Project Context 快照与相关 Entry（目标节点子树全部，最多 40 条、每条内容截断 200 字，超出标注截断）。Agent 输出 MUST 为目标节点下的完整目标子树（含应保留的现有子节点）；目标节点自身与保留节点的名称、说明 MUST NOT 被修改。生成来源 MUST 记录 provider、model 与 is_fallback，降级 MUST 显式标记。

#### Scenario: 跳过澄清直接生成
- **WHEN** 用户对某节点发起拓展
- **THEN** 草稿跳过澄清直接进入生成，最终进入待确认状态

#### Scenario: 完整目标子树包含现有子节点
- **WHEN** 目标节点已有子节点且 Agent 生成目标子树
- **THEN** 目标子树包含应保留的现有子节点，而非仅新增节点

#### Scenario: 目标节点自身固定
- **WHEN** Agent 生成目标子树
- **THEN** 目标节点自身的名称与说明保持不变，不随 AI 输出改变

#### Scenario: 相关 Entry 截断
- **WHEN** 目标节点子树内 Entry 超过 40 条或单条内容超过 200 字
- **THEN** 输入按上限截断并标注截断，优先保留直接挂载与最近更新的 Entry

#### Scenario: 生成来源可追溯
- **WHEN** 拓展草稿由 Agent 生成
- **THEN** 草稿记录 provider、model 与 is_fallback，降级时显式标记而非静默

### Requirement: 递归差异展示
系统 MUST 对目标节点现有子树与草稿目标子树按规范化名称递归计算差异并随草稿响应返回，差异项包括 `新增`、`保留` 与 `建议移除`；两边都有的节点为保留并递归比较 children，只在草稿侧的为新增，只在现有侧的为建议移除。建议移除 MUST 默认勾选；子树含正式 Entry 的移除项 MUST 禁用勾选并显示阻断数量；存在受保护移除时 MUST 向用户提示含正式知识的节点无法由 AI 移除。

#### Scenario: 新增与移除并存
- **WHEN** AI 目标子树在现有子节点基础上新增节点并省略某现有节点
- **THEN** 差异面板分别标记新增与建议移除，保留节点可展开查看内部差异

#### Scenario: 建议移除默认勾选
- **WHEN** 差异面板展示建议移除项
- **THEN** 移除项默认勾选，用户可取消勾选以保留该节点

#### Scenario: 受保护移除不可勾选
- **WHEN** 某建议移除节点子树存在正式 Entry
- **THEN** 该移除项禁用勾选并显示阻断数量，用户无法通过 AI 移除

#### Scenario: 对话应用后差异刷新
- **WHEN** 对话微调应用了新的目标子树
- **THEN** 差异快照按新目标子树重新计算并返回，面板显示最新状态

### Requirement: 拓展确认应用
系统 MUST 在用户确认后单事务应用拓展：校验草稿为 `pending_confirm`、目标节点仍存在且属于该项目、草稿树合法（parent 引用、无环、名称长度、新增节点数与层级上限）、勾选的移除项均为未阻断的建议移除；成功后 MUST 创建勾选的新增节点（根级追加到目标节点现有子节点之后，深层按草稿父子关系）、删除勾选的建议移除子树、标记草稿为 `confirmed` 并触发项目上下文刷新。任一校验失败 MUST 整批回滚，正式目录不变，草稿保持待确认可修正重试。

#### Scenario: 成功应用拓展
- **WHEN** 用户勾选新增节点与建议移除项并确认应用
- **THEN** 系统创建新增节点、删除勾选的移除子树、保留其余节点，草稿标记已确认并触发上下文刷新

#### Scenario: 受保护移除导致回滚
- **WHEN** 确认请求包含受保护的建议移除项
- **THEN** 整批回滚，不创建也不删除任何节点，草稿保持待确认并返回阻断数量

#### Scenario: 目标节点已删除拒绝应用
- **WHEN** 确认时目标节点已被删除
- **THEN** 请求失败，草稿置为已放弃，提示重新发起拓展

### Requirement: 拓展对话微调
系统 MUST 在拓展草稿进入 `pending_confirm` 后开放对话调整，沿用会话轮数上限 30；发送消息时 MUST 把会话全部消息与当前目标子树交给 Directory Agent；Agent 返回完整更新后的目标子树时 MUST 自动替换草稿节点并刷新差异，纯讨论 MUST 不改变草稿。

#### Scenario: 对话返回新目标子树
- **WHEN** 用户在拓展对话中要求调整并提交消息
- **THEN** Agent 返回更新后的完整目标子树，草稿节点与差异快照随之刷新

#### Scenario: 纯讨论不改树
- **WHEN** Agent 只返回回复文字而不返回新目标子树
- **THEN** 草稿目标子树保持不变，仅追加助手回复

#### Scenario: 会话轮数上限
- **WHEN** 拓展草稿会话轮数达到 30
- **THEN** 后续消息被拒绝并提示重新发起
