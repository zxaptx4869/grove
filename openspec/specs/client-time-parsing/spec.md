## Requirements
### Requirement: 服务端时间解析口径统一

Web 与原生端 MUST 通过各自一处共用时间工具把服务端时间串解析为时间点，MUST NOT 在展示点各自实现解析或各自补时区。解析口径 MUST 为：串带 `Z` 或 `±HH:MM` 偏移时按该偏移解析；不带偏移时按 UTC 解释（兼容历史裸串与直接读取数据库值的场景）；两者对同一时刻 MUST 得到相同结果，MUST NOT 出现二次偏移。解析失败 MUST 走调用方的兜底文案，MUST NOT 渲染 `Invalid Date`。展示格式（Intl 选项与文案）由各展示点决定，共用工具只负责解析。

#### Scenario: 不带时区的串按 UTC 解析

- **WHEN** 客户端拿到不带时区的服务端时间串 `2026-09-29T07:23:51`
- **THEN** 解析出的时间点与 `2026-09-29T07:23:51Z` 相同，在东八区渲染为 15:23

#### Scenario: 带偏移的串不重复偏移

- **WHEN** 客户端拿到 `2026-09-29T07:23:51Z` 或 `2026-09-29T07:23:51+00:00`
- **THEN** 解析出的时间点与不带时区的同一串一致，不再次叠加时区偏移

#### Scenario: 无法解析的串走兜底

- **WHEN** 服务端时间串为空或不是合法时间
- **THEN** 展示点显示各自的兜底文案（如空串、`—`、`时间未知`），不显示 `Invalid Date`

### Requirement: 各展示点复用同一解析实现

系统 MUST 让下列展示点全部复用共用时间工具，MUST NOT 在生产代码里保留第二份「缺时区就补 Z」实现；后续新增展示服务端时间的入口 MUST 同样复用该工具。Web 收口点：项目上下文生成时间、条目版本历史时间、条目列表日期、知识 Agent 对话更新时间、审阅来源时间、来源详情创建时间、对话工作台时间。原生端收口点：知识 Agent 条目详情更新时间、知识 Agent 历史相对时间、来源时间文案。

#### Scenario: Web 七个展示点都有解析断言

- **WHEN** 用同一个 UTC 时间串渲染项目上下文面板、版本历史抽屉、条目列表、知识 Agent 页面、审阅页、来源详情与对话工作台
- **THEN** 七处都按 UTC 解析（东八区下与直接解析带 `Z` 的串结果一致），且没有一处出现 8 小时偏移

#### Scenario: 原生端三个展示点都有解析断言

- **WHEN** 用不带时区的 UTC 串渲染条目详情的更新时间、历史列表的相对时间与来源列表时间文案
- **THEN** 三处都按 UTC 解析，刚结束的对话显示「刚刚」而非「8 小时前」

#### Scenario: 新增展示点复用同一实现

- **WHEN** 后续在 Web 或原生端新增展示服务端时间的位置
- **THEN** 该位置通过共用时间工具解析，不需要再写一份补 Z 兜底
