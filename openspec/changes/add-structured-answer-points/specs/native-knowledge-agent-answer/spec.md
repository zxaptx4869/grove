## ADDED Requirements

### Requirement: 回答正文的要点卡渲染
原生 App MUST 在 `answer.points` 非空时把回答正文渲染为要点卡：分组标题、要点正文，并在每条要点正文后以极小上标序号标记其引用；MUST 在 `points` 缺失或为空时回退为现有纯文本正文 + 底部来源条，历史回答不得出现回归或伪富文本。

#### Scenario: 新回答带结构化要点
- **WHEN** 回答包含 `points` 且至少一条有效要点
- **THEN** 页面按分组标题展示每条要点，正文后显示极小上标序号（同一要点多条引用时并列多个序号），不显示逐条来源按钮

#### Scenario: 历史回答无要点
- **WHEN** 回答不包含 `points`（历史数据或旧模型输出）
- **THEN** 页面保留现有纯文本正文与底部来源条，不显示空要点区

#### Scenario: 分组标题与编号可读
- **WHEN** 要点存在 `section` 分组
- **THEN** 分组标题以更醒目的样式展示，上标序号读屏可朗读

### Requirement: 按序号的来源区可核验可访问
原生 App MUST 在要点卡底部按序号列出全部引用来源，每条来源为可点击行（最小触控高度 44），点击后展示对应 Source 原文与 Entry 摘要；MUST NOT 把 AI 即时回答、草稿或 Candidate 标为正式知识。

#### Scenario: 点击来源序号行
- **WHEN** 用户点击要点卡底部来源区中某个序号对应的来源行
- **THEN** 打开证据原文 Sheet，展示该序号引用的 Entry 与 Source 原文，来源关系由应用层校验

#### Scenario: 触控与读屏
- **WHEN** 用户使用读屏或小尺寸触控
- **THEN** 来源区行提供 `查看引用 {序号}：{Entry 标题}` 语义且最小触控高度为 44

#### Scenario: 同一来源被多条要点引用
- **WHEN** 多条要点引用同一条 Evidence
- **THEN** 来源区只出现一次该来源并共享同一序号，不重复占行

#### Scenario: 语义不混淆
- **WHEN** 回答、草稿与待确认 Candidate 同屏出现
- **THEN** 要点卡保持「基于正式知识」的即时回答语义，不出现「已归档」或「正式知识」文案
