## Why

Grove 当前的搜索是纯关键词子串匹配，只能命中字面相同的词。当用户记不清原文、用不同说法表达同一含义时（如「地漏返味」与「下水道防臭」），找不到已确认的知识。P1 的差异化能力之一是「语义搜索和相似知识推荐」，需要在关键词搜索之上补充按语义找知识的能力，帮助用户在整理完成后回来回忆、发现相关知识。

## What Changes

- 新增语义搜索：用户用自然语言查询，系统先确定性召回候选 Entry，再由文本模型做语义重排，返回按语义相关度排序的正式 Entry，并带简短相关理由。
- 新增相似知识推荐：在 Entry 详情侧栏展示同一项目内语义相关的其他正式 Entry。
- 语义搜索与关键词搜索并存，不替换：语义搜索作为搜索框的显式开关入口，结果可识别其检索模式。
- 采用「确定性召回 + LLM 语义重排」路线，不引入 embedding / 向量存储（详见 design.md）。

## Capabilities

### New Capabilities
- `semantic-search`：项目内与全局的语义搜索，按语义相关度返回已确认 Entry。
- `similar-entry-recommendation`：在 Entry 详情中推荐同一项目内语义相关的其他正式 Entry。

### Modified Capabilities
（无）

## Non-Goals

- 不引入 embedding / 向量库 / ANN 检索（本次明确排除，待真实数据验证召回缺口后再单独评估）。
- 不做搜索结果问答（属于后续 `add-reader-agent-with-citations`）。
- 不做组合筛选、标签、批量管理（P2）。
- 不做跨 Workspace 检索、外部知识 / 联网搜索（P3）。
- 不改造已归档 `entry-relation-suggestions` 的关系判定语义。
- 相似知识推荐仅限当前项目，不做跨项目相似推荐（跨项目发现由全局语义搜索承担）。
- 不改变 Entry 归属，不自动写入或覆盖正式记录。

## Impact

- 后端：新增语义检索服务与语义重排 Agent，新增语义搜索 / 相似推荐 API 与 schema；复用现有 AI 文本模型抽象，无新增第三方依赖。
- 前端：搜索页增加「语义搜索」开关；Entry 详情增加「相关知识」侧栏。
- 数据库：无新增表（语义检索实时计算，不持久化向量）。
- 可观测性：语义重排需记录 provider / model / fallback 状态，未配置密钥时明确降级，禁止静默降级。
