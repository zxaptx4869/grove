## Why

知识 Agent 底座已经能持久化对话和可信地回答独立问题，但同一对话中的每条消息仍被当成全新问题；“为什么？”“那另一个方案呢？”这类自然追问既缺少独立检索语义，也无法复用上一轮已发现的主题对象。原生 App 以对话为主，Web 也将使用同一入口，因此下一步需要先建立可解释、可纠正且不把聊天内容冒充正式知识的连续追问能力。

## What Changes

- 为每条新消息增加上下文决策：判断为继续当前主题、开始新话题或需要用户澄清；客户端可用 `auto`、`continue`、`new_topic` 显式覆盖自动判断，Run 响应返回实际决策、主题标签与是否降级。
- 新增版本化显式工作集：只保存当前主题涉及的正式 Entry 标识、来源 Run、使用原因和范围快照，不把历史助手回答保存为事实；每个 Run 固化输入工作集版本，成功后原子生成下一版本。
- 追问时基于有限的近期消息和当前主题把省略、指代问题改写为可独立检索的查询；历史消息只用于理解用户意图，回答事实仍必须来自当前范围内重新校验的正式 Entry 与本 Run 新生成的 Evidence。
- 扩展固定执行图为“上下文决策 → 必要时澄清 / 工作集种子与新检索合并 → 读取 Entry 与 Source Evidence → 回答 → 更新工作集”；不引入模型自由选择工具或无限循环。
- 范围切换时关闭当前工作集；新话题替换而非污染旧工作集。取消、失败和纯澄清不得推进上下文；知识不足的新话题可以保留一个不含 Entry 的主题版本，但无有效引用时不得把召回项写入工作集。
- 硬化知识 Agent 基础契约：全部引用被丢弃时回答不得保持 `completed`；工具空结果不误报 fallback，工具错误或部分失败必须进入 Run 降级汇总。
- 更新 Agent 与 AI 阅读权威专题，明确连续追问、显式工作集、用户纠正和有限上下文边界。

### Non-Goals

- 不实现 Web 或原生 App 对话界面、消息引用手势、流式文本、推送或离线恢复；客户端接入继续拆成独立 change。
- 不把整段聊天记录、历史助手回答或历史摘要直接当成知识事实，也不建设长期个人记忆、跨对话记忆或用户画像。
- 不实现模型自主制定研究计划、多轮改写搜索、主动寻找反例或开放式工具循环；受限自主调查属于下一阶段。
- 不提供知识新增、修改、移动、删除、合并或保存回答工具；写入仍只能通过后续 Candidate / Draft 工具并由用户确认。
- 不跨 Workspace 或跨范围沿用工作集；范围切换后的旧上下文只保留为历史审计记录。
- 不引入外部队列、向量数据库、新 Agent SDK 或多 Agent 协商。

## Capabilities

### New Capabilities

- `knowledge-agent-follow-up`: 自动/显式上下文决策、追问改写、澄清响应、决策可见性与安全降级。
- `knowledge-agent-working-set`: 对话当前主题的版本化正式 Entry 工作集、Run 输入快照、更新/替换/关闭规则与范围隔离。

### Modified Capabilities

- `knowledge-agent-conversation`: 消息提交增加上下文模式，消息与 Run 返回上下文决策；范围切换同时关闭当前工作集。
- `knowledge-agent-run`: 固定执行图增加上下文决策分支与工作集版本快照，有限历史只用于理解意图；可观测性增加分类/改写阶段。
- `knowledge-agent-read-tools`: 已发现集合可由当前工作集的正式 Entry 作为受控种子，但每轮仍须重新校验范围、对象和证据。
- `reader-qa`: 召回合并工作集种子与当前问题的新检索；连续回答仍只接受本 Run Evidence，引用全部失效时必须降级。

## Impact

- 后端新增对话上下文版本、工作集 Entry 及 Run 上下文决策/快照字段的模型与 Alembic 迁移。
- 扩展知识 Agent schemas、消息提交 API、上下文决策 Agent、Runner、只读工具、Worker 恢复和逐阶段可观测性。
- 复用现有对话、Run、混合检索、Evidence、`AIProvider` 与进程内 Worker；不新增外部依赖。
- 调整 `backend/app/services/knowledge_agent/evidence.py` 和 `observability.py`，修复底座验收发现的两处契约缺口并补回归测试。
- 更新 `docs/产品蓝图/Agent架构与AI边界.md` 与 `docs/产品蓝图/目录与知识空间.md`。
- 本 change 只以 API、自动测试和手动走查验收；后续 Web/App 接入可直接消费上下文决策、主题与澄清响应。
