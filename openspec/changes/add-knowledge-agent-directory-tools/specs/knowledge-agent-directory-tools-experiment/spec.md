## ADDED Requirements

### Requirement: 目录工具读取真实 Project 与 Node 直接子级
统一循环原型 MUST 通过应用白名单只读工具查询真实 `Project`/`Node` 数据；根级查询 MUST 只返回 `parent_id IS NULL` 的一级目录，父节点查询 MUST 只返回该节点的直接子目录，并按产品目录树的同级顺序稳定返回。工具 MUST 返回真实节点 ID、名称、父节点关系、路径、项目身份、总数、返回数、是否还有更多及完整性，且没有 Entry 的空目录也 MUST 包含在内。

#### Scenario: 查询项目一级目录
- **WHEN** 用户询问指定项目的一级目录数量和名称
- **THEN** 工具返回该项目根下全部直接 Node，数量来自同一完整 Node 集合，不从 Entry、知识类型或搜索结果推算

#### Scenario: 空目录与后代边界
- **WHEN** 一级目录既包含没有 Entry 的空目录，也包含拥有多层后代的目录
- **THEN** 空目录被计入，后代节点不计入一级目录总数

#### Scenario: 查询直接子目录
- **WHEN** 工具以合法父节点查询目录
- **THEN** 只返回该父节点的直接子目录，并提供父节点真实身份与路径

#### Scenario: 目录为空
- **WHEN** 合法项目根或父目录没有直接子目录
- **THEN** 工具返回 `empty`、总数和返回数均为 0、完整性为 `complete`，不将其记录为错误或未执行

#### Scenario: 一次聚合真实叶子节点
- **WHEN** 用户要求统计指定项目目录树中没有任何子节点的叶子 Node
- **THEN** 目录工具在服务端一次读取授权项目的真实 Node 集合，返回真实叶子节点总数和按一级目录划分的权威统计，不把直接子目录数或 Entry 数冒充叶子节点数

### Requirement: 服务端固化目录访问范围与错误语义
目录工具 MUST 从 `RunToolContext` 获取 owner 与 Workspace，服务端 MUST 校验该 owner 的 Workspace 成员关系、项目归属和父节点归属；模型参数不得覆盖可信身份或 Workspace。工具 MUST 区分无 Workspace 访问权、当前 Workspace 中项目不存在或名称歧义、父节点不属于指定项目，并不得泄露其他 Workspace 对象详情。

#### Scenario: 跨 Workspace 项目名称
- **WHEN** 模型提交只存在于其他 Workspace 的项目名称
- **THEN** 工具在当前 Workspace 内返回项目不存在，不查询或泄露其他 Workspace 的目录

#### Scenario: owner 无 Workspace 成员关系
- **WHEN** 可信上下文中的 owner 不属于该 Workspace
- **THEN** 工具返回 `denied` 与无访问权限原因，且不执行项目或节点结果查询

#### Scenario: 错误父节点归属
- **WHEN** 父节点 ID 属于另一个项目或 Workspace
- **THEN** 工具返回父节点不属于指定项目，不回退到根级查询，也不泄露该节点的名称或路径

#### Scenario: 同名目录与不同项目节点
- **WHEN** 同级存在同名目录，或其他项目存在相同名称节点
- **THEN** 结果仍以项目 ID、节点 ID、父节点 ID 和稳定位置区分对象，其他项目节点不进入结果

### Requirement: 目录结果支持按实际展示顺序自然追问
统一循环 MUST 为目录结果建立与 Entry 列表分离的会话句柄和 1-based 实际展示顺序；涉及“第几个目录”的追问 MUST 由程序使用目录结果句柄与位置解析真实 Node ID，再重新执行当前轮权限及归属校验。历史 MUST 只保留继续指代所需的项目、父节点、节点身份、路径、顺序、数量和完整性，不持续注入整棵树或 Entry 正文。

#### Scenario: 追问第二个目录
- **WHEN** 上一轮实际展示一组有序一级目录，下一轮询问“第二个目录下面有哪些子目录”
- **THEN** 程序从该目录结果的第二项取得真实 Node ID 并查询其直接子目录，不使用 Entry 列表顺序或模型猜测的 ID

#### Scenario: 伪造或过期目录句柄
- **WHEN** 模型提交不属于当前会话的目录句柄、非目录结果句柄或越界位置
- **THEN** 程序拒绝调用并记录 `denied`，不读取任何节点

### Requirement: 结果元数据和确定性渲染保留领域语义
程序 MUST 为统计、Entry 列表和目录列表保存权威结果语义，至少包括查询对象、项目及筛选范围、分组维度、总数、返回数、完整性以及类型和维度的中文显示名称。模型可以安排混合块顺序和补充解释，但 MUST NOT 通过自定义标题改变工具事实；实验工作台 MUST 使用程序生成的权威标题、桶标签和范围信息展示结构化结果。

#### Scenario: main_type 不得显示成目录统计
- **WHEN** 工具结果是按 `main_type` 对正式 Entry 分组，而模型把块标题写成“一级目录”
- **THEN** 结构化结果仍显示为“按知识类型统计”，查询对象为正式记录，并使用知识、方法、参数、提醒等权威中文类型名

#### Scenario: 目录列表显示真实范围和完整性
- **WHEN** 根级目录查询完整返回 N 个节点
- **THEN** 结果块显示指定项目的“一级目录”、总数 N、返回 N 和完整，并保持节点真实顺序

#### Scenario: 分页或截断不冒充总数
- **WHEN** 任一未来或现有查询返回数量少于总数或完整性不是 complete
- **THEN** 程序分别显示总数与本次返回数（总数未知时明确未知），不得用本页长度冒充完整总数

#### Scenario: 混合回答保持块顺序
- **WHEN** 回答同时包含文字、统计、Entry 列表、目录列表和来源
- **THEN** 工作台按统一回答块顺序展示所有合法结果，不退回为互斥结果形态

### Requirement: 目录工具继承统一循环资源与失败边界
目录工具 MUST 通过现有只读 dispatcher 与统一循环事务锁执行，继承工具动作预算、超时、取消、结果字节限制、审计及失败记录；本 change MUST NOT 提高任何模型、工具、读取或时间预算。一次目录工具失败 MUST 终结为可诊断状态，并允许同一实验会话的后续轮次按既有设计继续。

#### Scenario: 工具预算耗尽
- **WHEN** 目录请求发生在本轮工具动作预算已经耗尽之后
- **THEN** 请求不执行，沿用统一预算停止与最多一次无工具收尾机制

#### Scenario: SQLite 事务保护
- **WHEN** 模型在同一响应并发提出目录和其他真实只读工具
- **THEN** 数据库读取与审计写入使用统一循环共享事务锁串行提交，不绕开第一批保护

#### Scenario: 目录工具失败后续聊
- **WHEN** 一轮目录工具因非法父节点或执行异常失败并完成终态记录
- **THEN** 下一轮仍可使用同一会话与累计预算执行合法查询，失败不遗留锁或孤立事务

### Requirement: 统一循环区分任务终态
统一循环和实验工作台 MUST 区分 `completed`、`partial_completed`、`unsupported`、`denied` 与 `failed`。完整满足用户请求时 MUST 使用 `completed`；已有当前轮可靠结果但因预算、超时、能力或收尾限制未完成时 MUST 使用 `partial_completed`；当前白名单工具无法支持目标对象且没有目标结果时 MUST 使用 `unsupported`；权限、Workspace 或项目范围拒绝时 MUST 使用 `denied`；只有 Provider、数据库、持久化或其他系统故障且无法形成更准确终态时才 MUST 使用 `failed`。预算耗尽 MUST NOT 默认归为 `failed`。

#### Scenario: 工具预算耗尽但已有可靠结果
- **WHEN** 当前轮已有真实工具结果，后续工具因动作预算不足而未派发
- **THEN** 轮次终态为 `partial_completed`，保留已验证结果并记录预算停止原因和未完成步骤

#### Scenario: 权限拒绝与系统异常分离
- **WHEN** 工具分别返回 Workspace/项目权限拒绝和数据库执行异常
- **THEN** 前者终态为 `denied`，后者终态为 `failed`，页面显示不同状态与原因

#### Scenario: 空结果不是失败
- **WHEN** 合法完整查询返回 `empty`
- **THEN** 轮次可以完整回答“没有结果”，不得仅因零项而标记 `failed`、`denied` 或 `unsupported`

### Requirement: 预算和收尾失败进入确定性兜底
统一循环 MUST 在工具、Entry、Evidence、文本、向量或时间预算不足时停止继续派发普通动作，保存当前轮已完成的结果、未完成步骤和明确原因，并在预算允许时最多尝试一次无普通工具收尾模型请求。收尾请求无预算、超时、Provider 失败或输出校验失败时，程序 MUST 不调用模型地生成合法结构化 blocks；兜底 MUST 只引用当前轮存在且类型正确的 result/evidence handle。

#### Scenario: 收尾模型输出非法工具调用
- **WHEN** 独立收尾请求返回工具调用而不是合法回答，且不能再次请求模型
- **THEN** 程序生成包含已确认结果、未确认部分、停止原因和继续建议的确定性回答，不向用户返回空错误或只有“本轮未完成”

#### Scenario: 收尾请求没有文本预算
- **WHEN** 求解停止时本轮或整批文本请求预算已耗尽
- **THEN** 系统不再派发模型请求，直接生成确定性兜底并保留准确的 `not_dispatched` 诊断

#### Scenario: 当前轮与历史轮引用隔离
- **WHEN** 当前轮没有取得某个统计、目录列表或 Evidence，但历史轮存在对应句柄
- **THEN** 确定性兜底不得把历史句柄或历史结果呈现为当前轮已确认结果

#### Scenario: 未知工具调用数量
- **WHEN** 运行时异常使工具诊断未能确定
- **THEN** 工作台持久化并显示“未知”，不得将 `null` 或缺失值显示为 0 次调用

### Requirement: 能力不足和递归任务受确定性保护
统一循环 MUST 根据白名单能力与确定性任务状态尽早识别不可支持或可能超过剩余资源的递归、分页和批量读取任务。系统 MUST 防止在预算耗尽后继续生成大量工具调用，并 MUST 避免在同一 continuation 中重复查询同一父节点。若已取得目标的一部分则返回 `partial_completed`，否则返回 `unsupported`，且不得用其他统计维度代替用户目标。

#### Scenario: 没有目标聚合能力
- **WHEN** 用户要求整树叶子节点总数，而当前可用工具只能列出直接子目录
- **THEN** 系统在已有局部目录时返回 `partial_completed`、否则返回 `unsupported`，并明确已查询节点数不等于叶子节点总数

#### Scenario: 剩余预算不足以继续递归
- **WHEN** 待查询父节点数明显多于本轮剩余工具预算
- **THEN** 系统在派发超预算调用前停止，保存待查询父节点和已确认节点，并生成部分完成回答

#### Scenario: 纠正错误叶子统计
- **WHEN** 用户指出某个被当作叶子的节点实际仍有子节点
- **THEN** 系统不得继续沿用上一轮未经整树工具确认的叶子总数，并应使用权威叶子聚合或从未完成状态继续核验

### Requirement: continuation 保存最小可续状态
对可分步执行的目录、分页和批量读取任务，统一循环 MUST 保存任务类型、可信项目范围、已完成步骤、已确认对象、待处理对象和停止原因；下一轮明确要求继续时 MUST 从未完成位置继续而非重复已完成动作。若具体任务不可自动恢复，回答 MUST 明确只能重新发起查询，不得声称已经保存可续任务。

#### Scenario: 下一轮继续目录核验
- **WHEN** 上一轮部分完成并保存待查询父节点，用户下一轮要求“继续核验刚才的目录”
- **THEN** 系统恢复相同项目和任务类型，跳过已查询父节点并从待处理节点开始执行

#### Scenario: 部分完成后普通问题
- **WHEN** 上一轮因预算部分完成，下一轮提出无关的普通合法问题
- **THEN** 新问题正常执行，旧 continuation 不污染其结果、范围或终态

### Requirement: 正式记录类型口径和既有结果能力不回退
统一循环 MUST 继续将用户泛称“知识”“知识库记录”解释为全部正式 Entry 类型，只有显式指定 `knowledge`、`method`、`parameter` 或 `reminder` 时才设置类型筛选。新增目录能力 MUST NOT 改变既有 Entry 排序、来源当前轮核验、统计完整性或文字/统计/列表/来源混合回答能力。

#### Scenario: 泛称知识覆盖全部正式类型
- **WHEN** 用户询问某项目有多少条“知识”且未显式指定内部类型
- **THEN** Entry 查询的 `main_types` 为空并覆盖全部正式类型

#### Scenario: 显式类型筛选
- **WHEN** 用户明确只查询 `method` 类型
- **THEN** Entry 查询仅包含 `method`，权威元数据将其显示为“方法”筛选

#### Scenario: 既有 Entry 列表与来源回归
- **WHEN** 用户查询有序 Entry 列表、展开其中一项并读取来源
- **THEN** 实际 Entry 顺序、当前轮 Evidence 校验和混合回答保持既有合同

### Requirement: 已知目录名称或路径可直接定位真实 Node
目录工具 MUST 在指定的唯一项目内支持按目录名称或完整路径直接定位。精确名称 MUST 优先于包含匹配；名称命中多个节点时 MUST 返回完整路径候选并标记歧义，不得任意选择。路径 MUST 逐级匹配真实父子关系。每个候选 MUST 返回 Node、项目、父节点、完整路径、深度和叶子状态；`is_leaf=true` 只能来自服务端对同一项目完整 Node 集合的子节点确认。结果 MUST 同时返回总数、返回数、是否还有更多和完整性。

#### Scenario: 精确名称定位深层目录
- **WHEN** 用户在“房子装修”项目查找名为“瓷砖地材”的目录
- **THEN** 工具不遍历根级结果即可返回真实 Node ID 与“设计规划 / 风格设计 / 材质选择 / 瓷砖地材”完整路径

#### Scenario: 完整路径消除同名歧义
- **WHEN** 同项目存在多个“瓷砖地材”，用户提交其中一条完整路径
- **THEN** 工具只返回父子链完全匹配该路径的 Node，不混入同名节点

#### Scenario: 同项目同名目录
- **WHEN** 精确名称匹配同项目多个 Node
- **THEN** 工具返回 `ambiguous` 和每个候选完整路径，要求用户补充路径，不把任一候选冒充唯一结果

#### Scenario: 不同项目同名隔离
- **WHEN** 另一个项目或 Workspace 也存在同名目录
- **THEN** 结果只包含指定项目且当前 Workspace 可访问的 Node

#### Scenario: 定位不存在与项目不存在
- **WHEN** 目录名称或路径不存在，或指定项目不存在
- **THEN** 前者返回完整 `empty`，后者返回明确项目错误，不以根级目录或相似 Entry 代替

#### Scenario: 定位结果被截断
- **WHEN** 名称候选超过服务端返回上限
- **THEN** 工具返回真实 `total_count`、有界 `returned_count`、`has_more=true` 和非完整状态，不声称候选完整

### Requirement: 定位结果可作为真实 Entry 节点范围
统一循环 MUST 只从当前会话的目录结果句柄解析真实 Node ID，并由共享服务重新校验 Node 属于可信 Workspace 与指定项目。定位后 MUST 能按该节点直接范围或明确子树范围查询正式 Entry；统计或列表不得从目录名语义相关性结果推算。后续对“这个目录”的追问 SHOULD 复用已有句柄和 Node，不重复名称查找。

#### Scenario: 定位后查询目录 Entry
- **WHEN** 已唯一定位“瓷砖地材”并要求列出或统计该目录下正式记录
- **THEN** 程序按真实 Node ID 的 direct 或 subtree 范围执行现有 Entry 查询，结果继续受 Workspace、项目、预算和完整性约束

#### Scenario: 路径或 Node 越权
- **WHEN** 路径、目录句柄或其 Node 不属于指定项目或可信 Workspace
- **THEN** 服务端拒绝查询且不泄露外部项目名称、目录名称或 Entry

#### Scenario: 后续追问复用定位结果
- **WHEN** 上一轮已定位唯一目录，下一轮询问“这个目录下面还有哪些子目录”
- **THEN** 程序复用目录结果句柄中的真实 Node ID 查询 children，不再次按名称或从根遍历

### Requirement: 候选修改稿与正式写入请求必须分离
统一循环 MUST 将“补充、完善、改写或输出一版供用户自行更新”的请求作为候选文本生成，并以 `completed` 返回；候选稿 MUST 明确尚未写入知识库，区分原记录已有内容、AI 建议补充和修改后候选版本，并说明 AI 新增内容不属于原始来源原文。统一循环 MUST NOT 为候选稿创建、修改或覆盖 Entry、Source、Evidence，也 MUST NOT 把候选稿呈现为已保存的正式记录。只有用户明确要求直接保存、覆盖或写入正式 Entry 时，才按当前只读白名单返回 `unsupported`。

#### Scenario: 输出供用户自行更新的候选稿
- **WHEN** 用户要求“帮我补充一下这条知识”或“把修改后的内容输出给我，我自己更新”
- **THEN** Agent 输出带未写入声明、原记录要点、建议补充、修改后候选版本和来源边界的候选稿，不调用 `report_unsupported` 或任何写入工具

#### Scenario: 自行更新表达优先于模糊更新动词
- **WHEN** 同一请求同时包含“帮我更新”和“输出给我、我自己更新”
- **THEN** 系统优先理解为候选稿生成，不把它误判为直接写入请求

#### Scenario: 明确直接写入仍不支持
- **WHEN** 用户要求“直接帮我更新知识库”或“覆盖原记录并保存”
- **THEN** Agent 返回 `unsupported`，不调用不存在的写入工具，也不声称正式 Entry 已被修改
