## Context

现有统一循环通过 `KNOWLEDGE_AGENT_READ_TOOL_REGISTRY`、`RunToolContext` 与 `dispatch_read_tool` 访问正式 Entry，并由实验层保存结果句柄和精简历史。Project/Node 目录树当前由项目 API 直接读取，Node 以 `parent_id` 表示层级、`position` 表示同级顺序；循环没有目录工具。现有结果块虽然从句柄取真实数值和对象，显示标题仍由模型提供，因此 `main_type` 分组可能被错误命名为一级目录。

本 change 只扩展统一循环原型及实验工作台。正式 Knowledge Agent 路由、公开 API、数据库结构和目录写入能力不变；两个既有活动 change 不归档。

## Goals / Non-Goals

**Goals:**

- 复用真实 Project/Node 模型与产品目录顺序，提供根级和直接子级只读查询。
- 在共享 dispatcher 内落实 Workspace 成员、项目和父节点归属校验，并继承审计与资源控制。
- 用目录专用结果句柄支持跨轮按实际顺序指代。
- 让程序而非模型决定统计、Entry 列表和目录列表的领域标题、范围、维度与数量语义。
- 用真实 SQLite 数据与 FunctionModel 覆盖边界，不发真实模型请求。
- 对用户明确给出的目录名称或完整路径直接定位真实 Node，并在同名时返回有界候选路径而不是任意选择。
- 将定位结果作为现有 Entry 查询的可信 Node 范围入口，支持直接目录与子树范围，并复用目录句柄完成后续追问。

**Non-Goals:**

沿用 proposal 所列非目标；尤其不增加目录写工具、独立意图/规划/覆盖模型，不提高预算，不接入旧 Agent 正式流程，不重放历史会话。

## Decisions

### 0. 名称与路径定位复用目录工具的 `find` 操作

`list_project_directories` v1 增加 `find` 操作和互斥的 `name`/`path` 条件。服务端仍先解析可信 Workspace 内的唯一项目，再一次读取该项目 Node 集合并复用既有路径构造。路径按 `/` 分段并忽略分隔符两侧空白，逐级核对父子关系；名称默认精确匹配，必要时允许 `contains`，但只要精确结果存在就不混入包含候选。结果统一返回 Node、项目、父节点、完整路径、深度、经真实子节点集合确认的 `is_leaf`、总数、返回数、`has_more` 与完整性。

名称命中多个节点时返回 `ambiguous` 状态和完整路径候选；零命中返回 `empty`。路径从项目根节点开始解析，因此路径节点无法属于其他项目；外部 Node ID 仍由既有父节点校验拒绝。候选受服务端上限约束，被截断时明确 `partial`、`has_more=true`，不得把返回数当总数。

对话表面工具不增加新的定位模型。用户明确提及目录名时直接调用 `find`，定位句柄与普通目录句柄同属 `directories` 类型；后续可以直接复用句柄中的唯一 Node，也可在歧义结果中按用户选定的实际位置解析。

完整 `not_found` 已经是指定项目范围内的确定性定位结论。循环保留该空结果句柄；若模型随后尝试从根级 `children` 回退遍历，程序不再派发重复目录查询，而是把既有句柄作为已解析结果返回。确定性目录渲染会明确显示名称或路径不存在，避免模型的冗余非法参数把真实空结果错误升级为权限拒绝。

当输入上下文软上限触发收尾转换时，完整的 `find/not_found` 结果直接由确定性渲染器收尾，不再额外派发一次模型请求；这样空结果不会因收尾阶段再次返回工具调用而降级为部分完成。

### 0.1 Entry 查询只接受程序解析的 Node 范围

现有 `query_entries` 表面工具增加 `directory_result_handle` 与 `directory_position`、`directory_scope=direct|subtree`。程序从当前会话目录结果解析真实 Node ID 和项目身份，再向共享 `query_entries` 传递内部 Node 范围；共享处理器重新校验 Node 属于可信 Workspace 和指定项目，并用现有子树辅助得到节点集合。模型不能直接提交 Node ID，也不能用目录名称作为 Entry 语义相关性条件。此增量复用现有 Entry 装配、排序、预算、审计和结果句柄，不创建第二套 Entry 查询。

### 1. 共享只读 registry 增加 `list_project_directories` v1

工具参数只包含项目引用和可选 `parent_node_id`，Workspace 与 owner 始终由 `RunToolContext` 注入。处理器先核对 WorkspaceMember，再在该 Workspace 内解析项目；父节点查询必须同时满足项目 ID。它一次加载项目节点以构造父路径，再只返回目标父级的直接子节点，排序为 `position, id`，使 position 相同时仍确定性稳定。

根节点 `parent_id IS NULL` 就是项目一级目录，不另造虚拟根节点。查询不连接 Entry，因此空目录天然保留，子孙不会进入直接子级计数。当前实现不分页，`total_count == returned_count`、`has_more=false`、完整性 complete；合同仍显式保留两个计数，避免未来分页混淆。

备选是在实验包中直接 SQL 查询 Node，但这会复制权限、审计和目录语义，无法被共享边界测试覆盖，因此不采用。公开项目树 API 保持响应合同，只复用同级稳定排序辅助函数，避免创建第二套目录数据。

### 2. 对话表面工具支持项目名称或项目 ID，并由目录句柄解析父节点

自然首问可以用唯一项目名；`list_projects` 同时返回真实项目 ID，名称歧义时模型可以要求用户选择或用 ID。目录工具的首次调用不带父节点，追问则优先携带上一轮 `directory_result_handle + position`。实验层验证句柄属于本会话且结果类型为目录，再解析 Node ID；共享处理器仍重新验证 Node 当前归属，历史不成为授权。

目录结果使用独立的 `directories` 记录类型与 `directory_list` 输出块，Entry 的 `open_list_item` 继续只接受 Entry 列表。这样即使两个列表都有“第二项”，也无法交叉解析。历史摘要只保存项目/父节点、节点 ID/名称/路径/顺序、数量、状态和完整性。

### 3. ResultRecord 保存权威 `semantics`，渲染器忽略模型自定义标题

实验适配层根据实际工具、执行参数和返回 payload 构造结构化语义：`subject`（entries/directories）、可信项目范围、筛选、`group_by`、总数/返回数、完整性及中文显示名。模型输出块仍只负责顺序和解释；兼容保留的 `label` 字段不再决定结构化标题。

确定性标题示例为“房子装修 · 一级目录”“全部项目 · 按知识类型统计”“房子装修 · 正式记录列表”。`main_type` 桶由固定映射显示为知识/方法/参数/提醒；`info_nature` 和其他合法维度也使用应用映射。原始 key 继续保留用于诊断。

这种做法不要求改变正式 API schema，也不把结果形态退回二选一。工作台只扩展现有块视图并显示总数、返回数和完整性。

### 4. 继续使用同一预算、事务锁和失败恢复

目录调用走 `_dispatch`，所以在派发前预留现有工具动作预算，并使用 `ReadToolBudget`、取消检查、字节限制、审计记录与 `LoopState.database_lock`。非法历史句柄在表面工具处以 denied 记录且不触碰数据库；共享处理器的访问/归属问题返回明确状态与错误码。任何意外异常仍由 dispatcher 归一为 error，工作台沿用第一批终态保存和下一轮恢复。

### 5. 停止状态由程序归一，模型只负责可选收尾表达

`LoopState` 保存当前轮 `StopState`：分类、机器原因码、用户可读原因、未完成步骤、是否可续以及 continuation。`run_turn` 对预算异常、超时、工具结果状态、模型输出非法和未知异常统一归类，再决定是否尝试一次 finalize-only 请求。Finalize 不允许普通业务工具；失败后直接调用确定性渲染器，不再抛出第二次错误。

确定性渲染器只遍历 `current_handles/current_evidence`，按真实 `ResultRecord.kind/status/completeness` 生成 text、statistic、list 和 evidence blocks；insufficient 块独立列出缺口、停止原因与继续建议。统计块仅接受工具直接返回的 count/value/buckets，不从列表长度推导用户目标统计。这样历史句柄、未执行事件和模型自由文本都不能制造当前轮事实。

轮次状态按证据优先级归一：授权拒绝为 `denied`；能力缺失且无部分目标结果为 `unsupported`；预算、超时或能力限制且已有可靠结果为 `partial_completed`；系统异常为 `failed`；请求完整满足才为 `completed`。持久化失败仍可覆盖外层工作台状态为 `failed`，同时保留 `solve_status`。

### 6. 递归任务使用 continuation 队列和剩余预算预检

continuation 只保存最小任务状态：任务类型、项目 ID/名称、已查询父节点 ID、已确认节点摘要、待查询父节点 ID 和停止原因，不保存正文或整棵树。每次派发前用 ledger 的剩余工具/读取预算做确定性判断；已查询父节点集合阻止重复查询。下一轮只有明确“继续”表达且任务匹配时才恢复，否则保留但不注入新问题结果。

当前第二批直接为目录工具增加 `leaf_summary` 操作：服务端在同一授权与事务边界内一次读取项目全部 Node，以“没有任何子 Node”为叶子，返回总数和按一级目录的分组统计。自然的叶子统计优先走该操作，因此正常路径不需要 continuation；递归 continuation 仍覆盖未来分页或能力降级测试，不通过提高预算掩盖问题。

### 7. 项目语义搜索使用严格范围并尊重重排结果

对话表面的 `search_knowledge` 同时接受 `all` 与 `project` 范围。用户明确给出项目名时，表面工具将请求转发到既有 `query_entries` 结构化语义入口，以项目名构造可信 Entry 集合并使用严格重排；全部项目搜索仍复用原有跨项目工具。通用搜索的重排结果非空时视为对候选的明确筛选，不再把被省略的语义候选补回列表；只有重排无结果或降级时才保留原始召回作为兜底。这样列表展示不会将瓷砖、插座等相近主题误报为墙纸知识，统计仍必须另用真实 Node/Entry 范围工具。

### 8. 区分语义结果完整性与轮次是否还有待办

结构化语义查询即使成功返回且 `has_more=false`，仍将结果集合标记为 `limited`，以避免把 top-k 相关性结果误称为授权全集；但循环只有在 `partial`/`error` 或 `limited` 且明确 `has_more=true` 时才生成未完成步骤。这样用户询问“是否有关于墙纸的知识”时可以正常完成回答，同时保留结果不是全集的事实提示；实际分页或候选截断仍会进入部分完成和可继续路径。

## Risks / Trade-offs

- [项目名允许重复，直接按名查询可能歧义] → 返回明确歧义错误；`list_projects` 暴露真实 ID，目录工具接受 ID 作为无歧义引用。
- [现有 Node.position 可能并列] → 在不改变产品 position 语义的前提下用 Node.id 作稳定回退；项目树 API 同步采用相同辅助排序。
- [模型仍可能在自由文字中口误] → 结构化块标题、维度、数值和对象由程序固定；自然语言真伪仍属于人工语义验收，不新增覆盖模型。
- [共享 registry 暴露新工具但正式流程未接线] → registry 只提供白名单执行能力，正式 planner/runner 不会自行发现未注册到其计划合同的工具；测试覆盖既有调用方。
- [确定性兜底文字比模型回答机械] → 只在模型收尾不可用时启用，优先保证事实、缺口和状态正确；工作台用结构化块维持可读性。
- [continuation 可能误污染后续问题] → 只在明确继续表达时激活，所有结果句柄仍按当前轮隔离；普通新问题不会自动消费旧队列。
- [一次加载整树在超大项目上增加结果处理] → 现有目录工具本就加载授权项目节点构造路径；叶子聚合不返回整树正文，只返回计数和有界分组。
- [同名目录候选可能很多] → 返回真实总数并设置有界候选上限；截断明确标为 partial，要求用户补充完整路径。
- [模型把目录名当作 Entry 搜索词] → 提示词要求先定位，Entry 查询的 Node 范围只从会话内目录句柄解析，服务端再校验项目归属。

## Migration Plan

无数据库迁移。先更新既有 change 并严格校验，再完成统一状态/兜底和叶子聚合测试并分段提交，随后完成工作台展示与全量相关验证。回滚可恢复新增提交；实验历史仍按既有设计只读保留，新会话使用新合同。人工验收前不归档、不推送、不合并。

## Open Questions

无阻断问题。真实模型是否总能在自然表达下选择正确目录工具留给本次人工验收；无模型测试只证明工具事实、边界和接线。
