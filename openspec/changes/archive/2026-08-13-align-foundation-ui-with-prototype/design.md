## Context

上一轮实现的后端契约和真实数据流有效，但前端只完成了功能骨架。偏差集中在：应用壳空洞、项目列表控件粗糙、项目工作台缺少原型层级、目录操作平铺工程缩写按钮、认证错误只用 toast，以及没有真正生成同视口对照截图。本 change 是 UI 校准，不改变产品范围和后端契约。

## Goals / Non-Goals

**Goals:** 将登录、注册、全局壳、项目列表、项目工作台、目录空状态和目录操作校准到产品原型的结构、密度和交互；保留真实 API 与完整状态；以截图证据完成验收。

**Non-Goals:** 不实现原型中超出本轮产品范围的业务页，不修改后端 API、领域模型、迁移或 Workspace 隔离，不做逐像素复制和内联样式迁移。

## Decisions

### 逐屏对照矩阵

| 正式页面 | 原型参考 | 必须一致 | 有意偏离 |
|---|---|---|---|
| 登录/注册 | 原型整体视觉语言 | 品牌、表单宽度、间距、控件高度、错误和提交状态 | 原型未定义认证流程细节，以 OpenSpec 为准 |
| 项目列表 | `data-page="projects"` | 左侧壳、标题区、状态分段、列表行密度、主次操作 | 不展示 Entry/Candidate 数量，只展示真实 description、node_count |
| 项目工作台 | `data-page="project-home"` 与项目导航 | 返回层级、项目标题、状态/背景区域、操作分组 | 不展示 AI 项目理解、任务、知识统计等未实现数据 |
| 目录工作区 | `data-page="knowledge"` 的目录侧栏 | 目录树密度、展开层级、空目录双入口、上下文操作 | 不展示 Entry 列表、搜索和目录 Agent 草稿 |
| 小屏阻断 | 原型阻断页 | 1023px 阻断、1024px 工作台 | 文案按当前基础能力收敛 |

### 组件策略

- 新增 `DropdownMenu` 等必要 shadcn/ui 基础组件；状态使用已有 Badge、Dialog、Button、Input、Textarea。
- `AppShell` 拆为可读组件，不再用单行 JSX；最近项目来自真实项目查询，最多显示 5 条非归档项目。
- 项目列表状态筛选使用紧凑 segmented control；行内只保留“进入项目”和更多菜单，状态变更、归档、删除进入菜单或确认对话框。
- 项目工作台采用项目上下文头 + 两栏工作区。项目元数据在独立 section 中编辑，避免所有操作挤入标题栏。
- 目录节点行仅显示展开按钮、文件夹图标、名称和更多菜单；排序在菜单中提供上移/下移，移动使用可搜索/分层选择对话框。
- API 错误在表单或数据区域内展示；toast 只用于成功反馈。

### 视觉令牌

继续使用 `index.css` 语义令牌，将原型的浅灰边界、墨色正文、绿色品牌/成功和紫色 AI 语义映射到 Grove 令牌。新增令牌只表达可跨页面复用的 surface/sidebar/brand，不硬编码原型颜色。

### 截图验收

截图输出到 `artifacts/ui-alignment/`，包含 `prototype-*` 与 `actual-*` 文件，覆盖 1280、1440、1600；另保存 1023、1024 边界截图。`artifacts/ui-alignment/README.md` 记录视口、路由、账号数据和有意偏离项。只有实际生成文件、人工读取截图且修复明显偏差后，相关任务才能勾选。

## Risks / Trade-offs

- [原型包含未实现数据] → 只复用结构与层级，用真实字段替代，不填造统计。
- [过度追求像素一致导致脆弱 CSS] → 以布局轨道、间距令牌、稳定尺寸和组件状态为验收单位。
- [最近项目增加额外请求] → 复用 TanStack Query 项目缓存，不增加后端接口。
- [截图受本地数据影响] → 使用专用本地验收账号和确定性项目/目录数据，不提交数据库。

## Migration Plan

纯前端替换，无数据库迁移。先实现基础组件与壳，再替换页面；每个阶段保持路由和真实 API 可用。出现问题可按组件回退，不影响后端数据。

## Open Questions

无。原型与蓝图已足以确定本 change 的 UI 方向。
