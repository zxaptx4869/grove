## Context

来源列表缺少统一查看入口，候选弹窗已含原文区。将候选弹窗升级为来源详情弹窗，避免重复建设；入口从「候选」（仅限有候选）扩展为「查看」（所有来源）+ 标题点击。

## Goals / Non-Goals

**Goals:**

- 一个弹窗覆盖来源材料与候选查看；
- 所有来源可查看（含无候选）；
- 图片可放大看原图；
- 保留候选证据高亮与定位。

**Non-Goals:**

- 不做独立详情页/路由；
- 不在详情做写操作；
- 不新增后端字段。

## Decisions

### D1：重命名与结构

`SourceCandidatesDialog` → `SourceDetailDialog`（文件、组件、import、测试同步改名）。弹窗标题「来源详情」，布局：头部元信息（标题、说明、状态徽标、项目、候选/正式知识数、创建时间）+ 双栏（左原文、右候选）。

### D2：图片放大

详情内图片点击打开全屏遮罩（`fixed inset-0`），显示原图（`object-contain`，最大 90vw/85vh），Esc 或点击遮罩关闭；无新依赖。

### D3：列表入口

`SourceList`：移除「候选」按钮的 `candidate_count > 0` 条件，文案改「查看」并始终显示；来源标题改为可点击（`button` 样式），点击设置 `detailSourceId` 打开详情弹窗；删除/重试按钮保留。

### D4：候选区

候选列表沿用现有交互（选中候选高亮原文 + 自动定位）；`candidate_count === 0` 时右侧显示「没有候选」空状态。

## Risks / Trade-offs

- [弹窗信息量增大] → 双栏滚动 + 弹窗加宽（`sm:max-w-4xl`），可接受；
- [标题可点击与现有删除按钮误触] → 标题独占可点击区域，操作按钮保持独立。

## Migration Plan

无后端与数据变更。
