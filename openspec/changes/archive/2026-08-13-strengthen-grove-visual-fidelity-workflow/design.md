## Context

`grove-ui-conventions` 已负责 Grove 前端实现、交互状态、桌面边界和原型验收，但当前正文只有一条“关键页面通过浏览器截图检查”和一条“三个视口对照原型”的完成阶段要求。项目列表重建实践表明，这不足以阻止代理在编码时先采用 Tailwind、shadcn/ui 或浏览器默认值，再通过用户反馈逐轮追赶原型；特别容易漏掉内容限宽、表面层级、字体字重和字体平滑等无法仅凭 DOM 或粗略截图确认的差异。

本 Change 将这次经过真实页面验证的方法固化到既有仓库级 Skill。它只改变代理工作方法，不改变产品行为或运行时代码。

## Goals / Non-Goals

**Goals:**

- 让原型覆盖页面在编码前形成可追溯的视觉基线和有意偏离清单。
- 先在 1440px 主视口收敛，再扩展到 1280px、1600px和必要的 1023/1024px，减少并行调参造成的返工。
- 将截图负责的整体视觉判断与计算样式负责的精确参数判断组合使用。
- 根据改动风险分流完整页面对齐、局部视觉调整和非视觉任务，避免流程过重。
- 保持 Skill 主文档简洁，通过单层 reference 渐进加载详细模板。

**Non-Goals:**

- 不新建第二个视觉 Skill，不复制 Grove 产品规范或主题令牌。
- 不把一次项目列表的具体像素值写成所有页面的固定值。
- 不增加截图自动化或视觉回归依赖；流程稳定并重复使用后再单独评估脚本。
- 不修改产品页面、后端、数据库、原型文件或 OpenSpec 工作流本身。

## Decisions

### 1. 增强现有 Skill，不创建重叠 Skill

视觉对齐是 Grove UI 实现与验收的一部分，触发范围与 `grove-ui-conventions` 高度重叠。将流程放入现有 Skill 能保证页面实现、调整、原型还原和 UI review 使用同一入口，避免两个 Skill 在权威来源、触发条件或验收标准上漂移。

替代方案是创建 `grove-visual-fidelity`，但会增加隐式触发不确定性和上下文成本，因此不采用。

### 2. 主 Skill 保存门禁与分流，reference 保存详细方法

`SKILL.md` 增加以下核心规则：

1. 原型对齐任务必须读取 `references/visual-fidelity-workflow.md`。
2. 编码前完成视觉基线和有意偏离，未完成不得开始页面样式实现。
3. 先在 1440px 主视口收敛，再验证其他桌面视口。
4. 完整页面对齐使用截图与计算样式双重验收；局部调整按影响范围缩小验证；非视觉任务不强制视觉矩阵。

详细字段、检查矩阵和 `design.md` 模板放进单层 reference，仅在原型还原或精确视觉任务触发时读取，避免每个 Grove UI 请求都消耗这些上下文。

### 3. 视觉基线是编码前门禁

完整页面实现或重建在修改页面样式前必须提取：全局令牌、字体、应用壳、页面边界、组件尺寸、关键状态；同时列出原型静态数据、未实现功能和演示包装等有意偏离。该门禁用于把视觉决策前置，而不是要求复制原型 HTML 或将像素硬编码进组件。

若原型或规格不能确定一个会显著改变结果的视觉决策，应在 `design.md` 记录并向用户澄清，不得静默猜测。

### 4. 1440px 作为默认收敛视口

1440px 是 Grove 桌面工作台的默认主验收视口。完整页面先在这一视口对齐结构、密度和层级，达到基线后再验证 1280px 与 1600px。这样减少三套尺寸同时调整造成的反馈噪声，同时仍满足现有多视口规格。

若用户提供的权威截图使用其他尺寸，则以该尺寸作为主视口，并在设计中记录替换原因。

### 5. 截图与计算样式承担不同验收职责

- 截图：检查结构、密度、视觉重量、留白和整体气质。
- 计算样式与边界数据：检查宽高、间距、颜色、字体栈、字号、行高、字重、边框、圆角、阴影和溢出。

不能以 DOM 存在、路由可达或单一截图替代完整页面的精确对照。用户明确要求视觉一致时，原型中已经确定的布局与样式默认视为必须对齐；只有产品规格、真实数据、可访问性或演示包装能构成有意偏离理由。

### 6. 按风险选择验收强度

- 完整流程：新页面、页面重建、原型还原、设计稿对齐、全局令牌或应用壳修改。
- 局部流程：单个组件或局部视觉精修；只提取受影响基线，至少在主视口检查相邻布局和计算样式，跨断点时再扩展视口。
- 常规流程：纯文案、数据逻辑、API 或不可见重构；不强制加载视觉 reference 或生成截图矩阵，仍执行相关功能测试。

这避免把高成本流程施加到无关任务，同时确保高风险视觉工作不能跳过测量。

### 7. Skill 元数据同步

更新 description，使“原型还原、设计稿对齐、视觉精修、视觉验收”能够触发该 Skill；更新 `agents/openai.yaml` 的短描述和默认提示，使 UI 展示与正文职责一致。继续保留隐式触发，不新增工具依赖或图标资源。

## Risks / Trade-offs

- [风险] 流程门禁增加前期时间 → 通过风险分流只对高风险视觉任务启用完整流程；前置测量减少后续返工，整体周期更短。
- [风险] 1440px 主视口被误解为唯一支持宽度 → 明确它只是收敛顺序，完成后仍验证 1280px、1600px和相关端侧边界。
- [风险] reference 变成另一套设计令牌 → 只保存测量字段与方法，不保存页面具体颜色或像素值；实际值仍来自原型、`index.css` 和当前 change。
- [风险] 计算样式检查被机械执行但未发现整体观感问题 → 要求计算样式与截图同时使用，各自不能替代另一方。
- [风险] Skill 触发过宽 → description 保留 Grove 前端上下文，并在正文明确非视觉任务不加载视觉 reference。

## Migration Plan

1. 更新 Skill 主流程、触发描述和 UI 元数据。
2. 增加单层视觉对齐 reference。
3. 运行 Skill 结构校验、OpenSpec 严格校验，并用完整页面、局部视觉和非视觉三个代表请求审查触发与分流结果。
4. 后续页面使用中继续观察；只有重复步骤稳定后再考虑自动化脚本。

回滚只需恢复 Skill、reference、元数据和主规格，无运行时或数据回滚。
