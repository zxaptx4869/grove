## Context

思维导图是 P1 最后一项能力，产品目标是把「按结构回忆知识」做成沉浸式阅读体验。现状：知识空间（`view=directory`）是 250px 树栏 + 内容区的工作台，承载节点管理与卡片/列表浏览；原型假稿把思维导图做成知识空间内的 Tab，且保留应用壳侧栏。本 change 将其改为独立的项目级沉浸式阅读视图。

当前可复用资产：
- `GET /api/projects/{id}/tree` 返回嵌套目录树，节点含直接 Entry 数 `entry_count`；
- `GET /api/projects/{id}/nodes/{nodeId}/entries?scope=direct|descendants` 支持按节点范围读取 Entry；
- `GET /api/entries/{id}` 与 AI 阅读的 `EntryPreviewDialog` 提供 Entry 详情展示；
- 前端 `HighlightText` 提供转义正则 + 染字高亮；
- `AppShell` 主栏已有 52px 顶栏占位，可复用为思维导图极简阅读栏。

## Goals / Non-Goals

**Goals:**
- 提供与 `view=directory`、`view=ai-read` 平级的独立思维导图视图，进入后无壳全宽、沉浸阅读；
- 画布左→右树形布局，节点显示「直接数 / 子树数」，支持展开/收起、聚焦子树、搜索高亮；
- 点击节点在阅读侧栏查看知识，支持「包含子树」（本节点 + 严格后代）范围，条目可打开详情；
- 阅读与目录管理通过「在知识空间中打开」衔接，思维导图内无任何管理入口；
- 最小后端改动：Entry 读取新增 `scope=subtree` 口径，无数据模型变更、无新增依赖。

**Non-Goals:**
- 不做节点创建、编辑、移动、排序、删除或拖拽；
- 不在画布/侧栏创建、编辑、归档 Entry，不处理 Candidate；
- 不接入 AI 拓展与目录草稿/调整流程；
- 不做画布缩放/平移/虚拟化与通用脑图编辑；
- 不改变目录树侧栏现有徽标形态；
- 思维导图内不提供项目内 Entry 搜索框（搜索边界：画布搜索只匹配节点名称）。

## Decisions

### 1. 独立沉浸式视图，而非知识空间内 Tab（对原型的偏离）
原型将思维导图作为知识空间内的「目录浏览 | 思维导图」Tab。本 change 采用独立项目级视图 `view=mindmap`。

理由：
- 目录浏览是管理态（树栏、搜索、卡片/列表工具栏都是操作件），思维导图是阅读态；两者共用工作台会互相挤压，1440px 下去掉树栏和侧栏后画布不足 700px；
- 独立视图可隐藏应用壳左侧栏，画布占满窗口，符合「沉浸式回忆」的产品目标；
- 仓库已有先例：AI 阅读（`view=ai-read`）就是与目录浏览平级的独立阅读视图，思维导图与其同构；
- 该偏离已在《目录与知识空间》专题记录，避免后续实现与产品权威文档冲突。

### 2. 无壳实现方式：AppShell 条件隐藏侧栏
`AppShell` 读取 `view=mindmap` 时不渲染 `<aside>`，网格由 `grid-cols-[216px_minmax(0,1fr)]` 改为单栏；其他视图不受影响。

备选方案与取舍：
- 浮层遮挡：保留侧栏 DOM 再覆盖，会留下残影与状态不一致，拒绝；
- 全局可折叠侧栏：扩大为通用壳能力，超出本 change 范围，拒绝。

极简阅读栏（返回知识空间、项目名、侧栏开关）由思维导图组件自身渲染，可复用 `AppShell` 主栏顶部 52px 占位。

### 3. 画布渲染：纯 DOM + SVG 手写分层树布局，零新依赖
采用父节点垂直居中对齐其子节点集合的左→右分层布局；连线用 SVG 绘制；节点为 button，便于键盘与可访问性。

备选方案与取舍：
- d3-hierarchy / elkjs：引入布局算法与依赖，风格与 Tailwind/shadcn 存在适配成本，MVP 目录规模（几十至一两百节点、深 3–4 层）收益不明显，拒绝；
- 现成脑图库：交互与视觉过于强绑定、体积大、难以贴合产品语义，拒绝。

密度控制：默认展开上限建议为可见节点 ≤60 或深度 ≤3，超出提示「还有 N 个节点未显示，聚焦子树后查看」；上限数值待真实数据验证后调整。

### 4. 计数口径：subtree = 本节点 + 严格后代
节点徽标「直接数 / 子树数」中，子树数 = `entry_count` + 全部严格后代 `entry_count` 之和，前端由嵌套树递归计算（与目录视图 `descendantEntryCount` 同源，天然一致）。

阅读侧栏「包含子树」使用同一口径，因此后端 `list_entries_by_node` 的 `scope` 新增 `subtree`（`[node_id] + 严格后代`），与现有 `direct`、`descendants` 并列。不做前端合并两次请求，保证口径在服务端单一可信。

### 5. 搜索只匹配节点名称
画布搜索对节点名称做大小写不敏感子串匹配，`%`/`_` 按字面转义；命中自动展开祖先路径并高亮，未命中显示提示。不匹配节点说明，避免与项目内 Entry 搜索边界混淆。高亮复用 `HighlightText` 的实现模式。

### 6. 状态与数据流
- 复用 `fetchProjectTree` / `fetchNodeEntries` / `fetchEntry`，`queryKeys.nodeEntries` 的 scope 类型扩展为 `direct | descendants | subtree`；
- 查询不设置长 `staleTime`，保持全局默认即时刷新；
- 阅读侧栏条目为轻量行组件（标题 + 路径），详情复用 `EntryPreviewDialog`；
- 思维导图独立维护选中节点，支持 `?node=<id>` 深链；知识空间目录浏览支持读取 `node` 参数定位节点（「在知识空间中打开」的落地端）。

### 7. 入口与视觉验收
入口仅两处：项目首页目录入口区域与知识空间页头，AppShell 侧栏不新增导航项，避免入口膨胀。视觉以原型假稿为参考，按 grove-ui-conventions 完整视觉流程在 1280 / 1440 / 1600 验收；与原型的有意偏离（独立视图、无壳）已在专题与本文档记录。

### 8. 走查修订（2026-08-21）
- **画布内边距**：布局增加 `CANVAS_PAD` 四周内边距，修复首行叶子节点被滚动容器上沿裁剪的问题。
- **项目总根**：思维导图以项目为总根（虚拟节点，id 为 `VIRTUAL_ROOT_ID`），显示「0 / 项目全部 Entry 数」，默认选中并在侧栏展示项目全部知识；配套新增后端 `GET /api/projects/{id}/entries` 与 `fetchProjectEntries`。总根不提供「包含子树」勾选与「在知识空间中打开」（无对应目录节点）。
- **画布背景**：最终采用原型式 28px 线格网格（`muted-foreground` 26% 透明度 1px 线）；线格附着在滚动容器上（默认 `background-attachment: scroll`），背景固定不随内容滚动，实现成本极低。此前尝试的点阵背景可见度不足，已弃用。

### 9. 交互升级：知识进入画布（2026-08-21）
- 采用「目录骨架 + 知识按需展开」：每个目录节点提供「+N 直接知识」入口，展开后该节点直接 Entry 以缩略小卡（标题 + 类型图标，不含全文）作为终端分支展示在画布中。解决「知识只存在于侧栏、体感等同目录浏览」的问题，同时避免全量展开导致画布爆炸；中间节点与叶子节点均可就地展示知识。
- 详情阅读位置：点击知识小卡或侧栏条目后，阅读侧栏展示全文、适用条件、补充说明与来源证据，并提供「返回列表」；弹窗不再作为主路径（首版不做弹窗）。
- 知识小卡布局：作为目录子分支参与树形布局，视觉用圆角小卡 + 类型图标与目录节点区分；目录「展开/收起」管结构，知识「展开/收起」管内容，两个维度独立。

### 10. 交互定稿：点击展开 + 悬浮详情（2026-08-21）
- **触发方式**：去掉「+N」按钮，点击目录节点 = 选中 + 切换该节点直接知识展开（再次点击收起）。
- **展开位置**：叶子节点（无目录子节点）在节点右侧列以紧凑行距堆叠，堆叠以节点为中心上下对称展开（向上不越过上一个兄弟，超出则整体下移）；非叶子节点在同列节点下方堆叠。
- **行位预留**：布局函数按堆叠实际高度计算预留行位（`state.nextSlot += ceil((堆叠底部 - 2) / ROW_GAP) - state.nextSlot`），把后续兄弟节点整体下推，天然避免重叠；画布高度随行数增长、可滚动，无需加载时预占。
- **详情交互**：hover 列表条目或画布知识小卡 → 悬浮小窗预览（跟随条目位置、优先显示在左侧避免遮挡）；点击 → 固定悬浮小窗（可滚动、可关闭）。侧栏不再承载详情模式，回归「节点知识列表 + 包含子树」。

## Risks / Trade-offs

- [手写布局在深树/长节点名下出现重叠或溢出] → 展开上限 + 聚焦子树 + 名称截断；用真实装修目录（深 3–4 层）在 1280/1440/1600 验证。
- [「包含子树」与目录浏览「仅后代」口径易混淆] → 文案明确区分（包含子树 = 本节点 + 后代），后端独立 `subtree` 口径，规格场景覆盖两种范围。
- [AppShell 无壳改动影响其他视图] → 仅 `view=mindmap` 条件分支，回归项目首页、知识空间、确认台、AI 阅读等既有视图。
- [大目录渲染性能] → MVP 规模由展开上限兜底；如真实数据超出预期，再评估虚拟化或后端返回子树计数，属后续演进。
- [侧栏折叠状态无持久化] → 首版组件内状态（默认展开）足够；如需要可后续用 URL 参数承载，不作为首版承诺。

## Migration Plan

- 无数据库迁移；`scope=subtree` 为既有接口的参数扩展，向后兼容；
- 前后端可独立合入：先加后端 `subtree` 口径（不影响现有调用），再实现前端视图与入口；
- 回滚：移除思维导图入口即可退回现状，不影响目录浏览、Entry 读取与搜索。

## Open Questions

- 展开上限的具体数值（≤60 可见节点 / 深度 ≤3）需在实现后用真实数据集校准；
- 侧栏「包含子树」默认勾选已按原型确认，实际使用占比待上线后验证；
- 大目录是否需要在后续 change 提供画布缩放/平移，以真实节点规模决定。

## 遗留项（归档后处理）

- 视觉打磨：节点/知识卡样式、间距观感按用户反馈后续独立迭代，不阻塞本次归档；
- Code Review P3：`hiddenCount` 文案把知识卡计入「个节点」；叶子堆叠上界 `y - 32` 对上一兄弟为非叶子且子树下探的场景是启发式假设；`revealedNodes` 在目录变更后可能残留失效 id 触发冗余 404 请求。
