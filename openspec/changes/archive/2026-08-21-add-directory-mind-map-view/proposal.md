## Why

P1 的差异化目标之一是「知识回忆」：整理完成后，用户需要能回到知识库按结构重新找到知识。现有知识空间的目录树 + 卡片/列表是管理工作台，承载大量操作件，不适合沉浸式阅读；思维导图作为 P1 最后一个 change，提供独立的目录阅读视图，让用户通过结构回忆、浏览和定位知识。

## What Changes

- 新增项目级独立思维导图视图（`view=mindmap`），与知识空间目录浏览（`view=directory`）、AI 阅读（`view=ai-read`）平级；入口位于项目首页与知识空间页头。
- 沉浸式无壳阅读：进入思维导图后隐藏应用壳左侧栏，画布占满窗口宽度；顶部仅保留极简阅读栏（返回知识空间、项目名、阅读侧栏开关），侧栏可折叠为纯画布。
- 画布为左→右树形目录布局，节点显示「直接 Entry 数 / 子树 Entry 数」；采用纯 DOM + SVG 手写布局，不引入图或脑图第三方依赖。
- 画布交互：展开/收起（全局）、聚焦子树（以选中节点为临时根并支持面包屑返回）、搜索并高亮（匹配节点名称、命中自动展开祖先）。
- 阅读侧栏：点击节点后显示知识列表；「包含子树」默认勾选（本节点 + 严格后代）；条目支持打开 Entry 详情弹窗（复用 AI 阅读的 EntryPreviewDialog）。
- 阅读与管理的衔接：「在知识空间中打开」从思维导图跳转目录浏览并定位该节点；思维导图本身不提供任何管理入口。
- 后端：按节点读取 Entry 的 `scope` 参数新增 `subtree` 口径（本节点 + 严格后代），与既有 `direct`、`descendants` 并列。
- 移除 node-tree 主规格中「思维导图浏览尚无实现时不显示可操作入口」的占位约束，替换为正式视图能力（通过 delta spec 同步）。
- 原型对齐与偏离：视觉结构参考 `docs/prototypes/grove-product-prototype.html` 的思维导图假稿；「知识空间内 Tab 切换」有意偏离为「独立沉浸式项目视图」，偏离理由与决策记录在 design.md 和产品专题《目录与知识空间》。

## Capabilities

### New Capabilities
- `directory-mind-map`: 思维导图目录阅读视图，覆盖沉浸式壳、画布布局、节点计数、展开/收起/聚焦/搜索高亮与阅读侧栏。

### Modified Capabilities
- `node-tree`: 知识空间工作台规格更新——思维导图由「未实现时不显示入口」变为正式项目级视图，并定义入口与沉浸式壳行为。
- `entry`: 「Entry 按目录浏览」范围口径扩展，新增 `subtree`（本节点 + 严格后代），与 `direct`、`descendants` 并列。

## Impact

- 前端：`ProjectPage` 增加思维导图分支与入口；`AppShell` 在 `view=mindmap` 时隐藏左侧栏；新增思维导图画布与阅读侧栏组件；`queryKeys.nodeEntries` 的 scope 类型扩展。
- 后端：`GET /api/projects/{project_id}/nodes/{node_id}/entries` 的 `scope` 参数增加 `subtree`；`list_entries_by_node` 支持新口径。无数据库变更、无新增依赖。
- 文档：本 change 同步更新《目录与知识空间》思维导图小节。

## Non-Goals

- 思维导图不是编辑器：不提供节点创建、改名、移动、排序、删除与拖拽。
- 不在画布或侧栏创建、编辑、归档 Entry；不处理 Candidate，不改动证据关系。
- 不接入 AI 拓展与目录草稿/调整流程（属于独立 change）。
- 不做通用脑图编辑、自由节点、画布缩放/平移/虚拟化；大目录通过展开上限与聚焦子树控制密度。
- 不改动目录树侧栏现有徽标形态（仍只显示直接数）。
- 画布搜索只匹配目录节点，不替代项目内 Entry 搜索；思维导图内不显示项目内 Entry 搜索框。
- 不实现手机 Web 业务界面；桌面 ≥1024px。
