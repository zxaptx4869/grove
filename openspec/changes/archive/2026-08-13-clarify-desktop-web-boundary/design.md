## Context

当前产品蓝图、`AGENTS.md`、前端主规格和 Grove UI skill 都要求 390px 完成核心流程。随着确认台、知识空间和目录共创原型成形，这一要求迫使高密度桌面工作流维护另一套逐层进入的手机交互，而前期用户主要在电脑上整理知识，移动场景计划由后续原生 App 承担。

本 change 只校正产品和工程基线。当前代码尚未提供统一的小屏阻断页，因此主规格只取消手机业务流程承诺并约束权威文档；阻断页由后续前端实现 change 落地，避免把未实现行为写成当前能力。

## Goals / Non-Goals

**Goals:**

- 统一桌面 Web、手机 Web 和未来原生 App 的职责边界。
- 取消 390px 完整业务流程的设计、实现和验收负担。
- 让确认台、知识空间等页面按桌面工作效率设计。
- 记录后续小屏阻断页的明确行为，避免未来重新讨论。

**Non-Goals:**

- 不在本 change 中修改 React 业务代码或实现媒体查询。
- 不兼容手机 Web 的部分业务能力，也不提供“仍然访问”。
- 不确定原生 App 技术栈、发布时间和完整功能范围。
- 不重写已归档的历史工件。

## Decisions

### Web 只承担桌面完整工作流

Web 工作台从 1024px 视口宽度开始支持，重点验收 1280px、1440px 和 1600px。浏览器缩放、桌面窄窗口、文字溢出和可访问性仍需检查，但不把复杂页面重排为手机业务流程。

替代方案是保留采集、阅读或轻量确认等手机 Web 子集。前期使用人数少，这会形成额外的信息架构、权限状态和测试矩阵，且用户会自然期待剩余功能补齐，因此不采用。

### 小屏使用统一阻断而不是简化版工作台

后续实现以视口宽度作为稳定判定：低于 1024px 时不加载业务工作台，显示“请在电脑上使用 Grove”；若用户已经在电脑上，则提示扩大窗口。App 上线前不提供继续访问或部分功能入口。

原生 App 上线后，同一承接页改为“打开 App / 下载 App”，具体链接、深链和商店策略由 App change 决定。

### 本 change 不提前声明未实现的运行时能力

本次修改主规格中的 390px 验收承诺，并新增端侧边界文档要求；不把“小屏已阻断”写成当前系统行为。后续实现阻断页时单独建立可测试的前端 change。

### 历史归档保持不可变

历史 proposal、design、tasks 和 delta spec 中的 390px 记录保留，用于说明当时实施依据。当前产品定义只由蓝图、主规格、守则和 UI skill 表达。

## Risks / Trade-offs

- [手机用户前期无法使用 Grove] → 明确提示在电脑上访问；前期不投入低价值兼容工作。
- [1024px 阈值可能误拦窄窗口桌面用户] → 阻断页同时提示扩大窗口，后续通过真实设备数据调整阈值。
- [App 上线前缺少移动采集入口] → 接受该阶段限制，先验证桌面整理闭环，再规划原生采集体验。
- [文档先于阻断页实现] → 在蓝图和任务顺序中明确实现项，主规格不宣称阻断页已经存在。

## Migration Plan

1. 更新蓝图、守则、OpenSpec 上下文和 README 的端侧描述。
2. 更新 `frontend-foundation` 主规格，取消 390px 业务支持要求。
3. 更新并校验 Grove UI skill，使后续前端任务按桌面工作台验收。
4. 后续通过独立前端 change 实现统一小屏阻断页。

## Open Questions

- 原生 App 的技术栈和首批能力在进入 App 阶段前另行评估。
- 1024px 阈值可在阻断页实现 change 中通过原型和真实设备测试微调。
