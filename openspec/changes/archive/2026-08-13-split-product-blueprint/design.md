## Context

当前 `docs/产品蓝图与功能优先级.md` 共 954 行，混合了产品定位、领域对象、整理流程、目录体验、Agent 架构、技术基线和排期。README、AGENTS、OpenSpec config 与 Grove UI skill 都直接指向整份文档，导致代理为了单个 change 也会加载全部产品背景。

这次调整是文档信息架构迁移。关键约束是所有现有决策必须保留，且同一决策只能有一个权威位置；索引只负责稳定摘要与路由，不能再成为一份缩小版完整蓝图。

## Goals / Non-Goals

**Goals:**

- 把默认产品上下文控制在短索引和当前任务相关的 1 至 2 份专题内。
- 保持 README 为唯一仓库文档入口，`docs/产品蓝图.md` 为唯一产品路由入口。
- 让每个产品决策有且只有一个专题归属。
- 让代理、OpenSpec 和 Grove UI skill 明确执行渐进式读取。

**Non-Goals:**

- 不改变产品范围、优先级、术语、数据关系或 Agent 边界。
- 不把专题内容复制进 Skill、AGENTS 或 OpenSpec config。
- 不修改历史归档中的旧链接与决策快照。
- 不建立自动文档生成系统或新依赖。

## Decisions

### 使用一个短索引和七个专题

`docs/产品蓝图.md` 保留状态、一句话定义、第一阶段承诺、四条产品铁律、当前阶段、路由表与阅读规则，目标控制在约 120 行内。其余内容进入：

1. `产品定位与阶段.md`
2. `核心对象与关系.md`
3. `采集整理与确认.md`
4. `目录与知识空间.md`
5. `Agent架构与AI边界.md`
6. `技术与端侧边界.md`
7. `功能优先级与Change顺序.md`

七份专题覆盖原蓝图全部章节。专题之间允许链接，不复制完整规则。

### 按领域责任而不是原章节编号拆分

原第 5 至 8 节共同描述 Source 到 Entry 的整理闭环，统一进入“采集整理与确认”；目录共创和知识使用共同进入“目录与知识空间”；Project Context 放入 Agent 专题。这样单个业务 change 通常只需读取一至两份文档。

### 删除重复决策清单，保留决策索引

原第 19 节重复前文 24 条结论。新索引不复述全部细节，而用“决策主题 → 权威专题”定位，防止未来更新一处遗漏另一处。稳定的四条铁律仍可在索引和 AGENTS 同时存在，因为它们是必须常驻的仓库约束。

### 历史归档不迁移

`openspec/changes/archive/` 中的旧路径属于历史工件，保持原样。只更新当前生效的 README、AGENTS、OpenSpec config、主规格和 Skill。

### 用脚本化章节切片保证内容覆盖

先按原始顶级章节边界提取内容，再通过补丁添加专题标题、导语和链接。迁移完成后比较原始章节标题与新专题标题映射，并全文搜索旧路径，减少手工复制丢段风险。

## Risks / Trade-offs

- [拆分时遗漏原文] → 按顶级章节切片迁移，并核对标题、关键术语和总字数。
- [专题之间产生重复] → 索引只路由，跨主题细节使用链接，不复制规则。
- [代理仍全文加载所有专题] → AGENTS、OpenSpec config 和 UI Skill 都明确禁止无差别加载。
- [旧链接失效] → 更新全部当前生效引用；历史归档保留旧链接作为当时快照。
- [专题边界偶尔需要两份文档] → 路由表允许 1 至 2 份专题，优先保证决策语义内聚。

## Migration Plan

1. 保存原长蓝图快照并按章节生成七份专题。
2. 用短索引替换原长蓝图路径。
3. 更新当前生效的引用、主规格与 Skill。
4. 校验文件链接、旧路径残留、章节覆盖、Skill 与 OpenSpec。
5. 归档 change 并提交新分支。

## Open Questions

无。后续只有当单份专题再次明显膨胀时，才根据真实读取模式继续细分。
