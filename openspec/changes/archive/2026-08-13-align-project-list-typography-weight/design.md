## Context

`align-project-list-visual-fidelity` 已将项目列表的壳宽度、内容起点、行高、控件尺寸、颜色和间距对齐到 `docs/prototypes/grove-product-prototype.html`。本轮截图复核发现剩余差异集中在字体渲染：原型的常规字重变量为 430，正式前端 body 仍为 400，并通过 Tailwind `antialiased` 强制灰阶抗锯齿；项目筛选和项目名称则分别被局部提升到 600 与 650，层级与原型不一致。

本轮继续以蓝图和 OpenSpec 决定产品行为，只采用原型“项目列表”页面的字体、视觉层级与密度作为参考。

## Goals / Non-Goals

**Goals:**

- 让中文正文在 macOS 和常见桌面环境中呈现更接近原型的深度与稳定字面。
- 明确正文、筛选、项目名称、当前导航和页面标题之间的字重层级。
- 通过浏览器计算样式和同视口截图验证结果。

**Non-Goals:**

- 不改变项目列表几何、颜色、字号、文案、交互或业务状态。
- 不增加原型中的收集箱计数、搜索、账户入口、知识统计或更新时间等未实现能力。
- 不修改后端接口、Workspace 隔离、数据模型或迁移。
- 不调整登录、注册、项目工作台和目录页面的局部层级；全局正文基线自然生效的部分除外。

## Decisions

### 1. 保留系统字体栈，调整常规字重为 430

继续复用 `frontend/src/index.css` 现有系统字体栈、14px 字号和 1.5 行高，只在 body 设置 `font-weight: 430`。不引入 Web Font，避免新增下载、中文字形覆盖、性能和授权成本。

### 2. 移除全局 `antialiased`

从 body 移除 Tailwind `antialiased`，让浏览器和操作系统选择默认字体平滑策略。该属性在 macOS 上会让中文笔画显得更细，且原型没有对整个工作台强制该策略。按钮组件自身的既有渲染规则不在本轮调整。

### 3. 局部强调按原型重新分层

保留页面标题 650、品牌 650、当前导航 600 和状态徽标 600。状态筛选移除 600，继承正文 430；筛选计数移除 400，继承 430；项目名称从 650 调整为 500。替代方案是整体增加所有字重，但会让筛选与项目名继续偏离原型，并削弱层级差异，因此不采用。

### 4. 现有代码保留、重写和删除判断

- 保留：应用壳与项目列表组件结构、设计令牌、系统字体栈、所有交互和数据查询。
- 重写：不重写任何组件，只修改最小范围的字体类名与 body 基线。
- 删除：仅删除 body 的 `antialiased` 类以及与原型冲突的局部强制字重；不删除业务代码。

### 5. 原型结构与有意差异

沿用原型的 52px 顶栏、216/184px 侧栏、24px 内容内边距、标题区、状态筛选和通栏项目行。仍有意不展示未由真实 API 返回的知识数、候选数、更新时间，也不增加尚未进入规格的全局功能入口。

### 6. 接口与迁移

前后端接口保持不变，不修改请求、响应或认证行为。数据库无 schema 或数据迁移；回滚只需恢复相关 CSS 与 className。

## Risks / Trade-offs

- [风险] 430 属于可变字重数值，部分系统字体可能映射到相邻静态字重 → 使用系统字体栈并在目标 macOS 浏览器截图验收，同时保证 400 回退仍可读。
- [风险] 全局正文基线会自然影响其他页面 → 保留所有显式标题和组件字重，并运行前端测试、lint 和 build；本轮只对项目列表做视觉验收。
- [风险] 取消强制抗锯齿会在不同操作系统产生细微差异 → 接受系统原生渲染差异，以目标桌面环境和原型层级为准，不用文本阴影模拟笔画。

## Migration Plan

1. 更新字体基线和项目列表局部字重。
2. 运行自动化检查并在三种桌面视口复核计算样式与截图。
3. 若视觉回归，恢复 `antialiased` 和原字重类即可，无数据回滚。
