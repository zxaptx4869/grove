## Context

最终原型位于会话生成目录，包含项目首页、收集箱、确认台、知识空间、目录共创、AI 阅读以及全局页面的可交互演示。它符合当前桌面 Web 与小屏阻断边界，但不属于正式 React 应用，也包含静态数据和模拟反馈。若只复制文件而不建立使用规则，后续实现代理容易把原型当成产品规格或一次性照搬其 HTML。

## Goals / Non-Goals

**Goals:**

- 将最终原型作为可版本化、可直接访问的单文件 HTML 保存。
- 明确产品蓝图、OpenSpec、原型和正式代码之间的权威顺序。
- 让每个前端 change 只读取并引用自身涉及的原型页面。
- 提供一致的桌面截图对照验收方式。

**Non-Goals:**

- 不把原型转换为 React，不提取组件或设计令牌。
- 不承诺原型中的所有页面和交互已经进入当前开发阶段。
- 不修改原型源文件中的演示数据和依赖加载方式。

## Decisions

### 将可访问预览版作为唯一入库 HTML

使用 `docs/prototypes/grove-product-prototype.html` 保存带完整文档外壳的预览版。它可以通过静态服务器直接访问，避免同时维护源片段和预览包装两份内容。原始会话生成目录不作为仓库依赖。

### 原型是视觉与交互参考，不是行为事实来源

权威顺序为：产品蓝图决定产品方向，OpenSpec 决定 change 的可验收行为，原型提供布局和交互参考，正式前端代码描述当前实现。冲突时不得用原型覆盖蓝图或 OpenSpec；确需改变产品行为时先更新对应产品专题与 change。

### 后续 change 按页面引用原型

每个涉及前端的 change 在 `design.md` 中记录对应原型页面、采用的布局和有意偏离项。实现使用现有 React、Tailwind 4、shadcn/ui 和 Lucide，不复制原型的嵌套 HTML、内联样式或演示脚本。

### 使用固定桌面视口进行视觉验收

关键页面在 1280px、1440px 和 1600px 对照原型检查；低于 1024px 只验证电脑访问阻断状态。原型覆盖不等于当前 change 必须实现所有状态，验收范围仍由 change 决定。

## Risks / Trade-offs

- [原型文件较大且包含生成包装] → 作为冻结参考资产保存，不在正式构建中导入，也不对其做零碎格式化。
- [原型与正式实现逐步漂移] → 每个相关 change 记录采用与偏离项；产品方向变化时先更新蓝图，再决定是否另存新版本原型。
- [外部图标脚本不可用时图标缺失] → 原型仅用于开发参考，仓库不将其外部依赖带入正式应用；视觉验收时使用可访问依赖的本地开发环境。
- [演示页面超出当前阶段] → README 显示覆盖范围不等于已实现范围，功能状态只以 OpenSpec 主规格和代码为准。
