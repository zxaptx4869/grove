## Context

当前 `/projects/:projectId?view=directory` 已提供真实目录树读取和完整的节点创建、编辑、移动、排序、删除操作，项目侧栏与项目首页将它称为“目录管理”。产品蓝图把项目层正式页面定义为“知识空间”，目录树是理解和浏览正式知识的主要骨架；原型也使用“知识空间 → 目录浏览 → 目录树 + 知识内容”的层级。

仓库尚无 Entry、Source、Candidate、来源证据或知识查询接口，因此本 Change 只能调整前端信息架构、目录工作台结构和真实空态。原型中的知识卡片、列表、直接/子树计数、来源数、思维导图和目录助手草稿不能作为本 Change 的数据或行为依据。

## Goals / Non-Goals

**Goals:**

- 把项目导航、项目首页入口和目录页面统一重定位为“知识空间”。
- 复用现有真实目录 API 和全部目录 CRUD，让目录编辑成为知识空间内的次级能力。
- 让非空目录默认进入一个明确的节点范围，并在没有 Entry 能力时展示准确、克制的知识空态。
- 按原型收敛知识空间的标题区、250px 树栏、内容区、工具栏和桌面密度。
- 保持 loading、error、empty、disabled、成功反馈和删除确认完整。

**Non-Goals:**

- 不新增或模拟 Entry、Source、Candidate、Processing Task、Extraction 和来源证据。
- 不实现知识卡片/列表、视图偏好、知识计数、目录搜索、关键词搜索、思维导图、AI 阅读或知识详情。
- 不实现 Directory Agent、目录草稿或自动修改目录。
- 不修改后端、数据库、API、Query Key、Workspace 隔离和端侧阻断规则。

## Decisions

### 1. UI 使用“知识空间”，兼容保留现有查询参数

侧栏、项目首页入口和页面标题统一显示“知识空间”，但本 Change 继续使用 `/projects/:projectId?view=directory`。该 URL 已有测试和浏览器历史行为，当前变化不需要后端或路由迁移；未来增加知识浏览 API 时可以独立决定是否迁移为 `view=knowledge` 或子路由。

备选方案是立即把参数改为 `view=knowledge`。这会增加旧链接兼容、重定向和测试范围，却不会带来用户可见价值，因此本轮不采用。

### 2. 保留 `ProjectPage` 的数据与操作所有权

`ProjectPage` 继续持有项目/目录查询、mutation 和全部对话框状态，`NodeTree` 继续只呈现树行并回调操作。当前只有一个知识空间消费者，没有必要为未来 Entry 提前抽取通用知识空间框架。

### 3. 非空目录默认选择第一个根节点

目录数据成功加载且当前没有有效选择时，页面以真实返回顺序选择第一个根节点；用户选择其他节点后更新当前范围。删除当前节点后重新选择刷新后树中的第一个根节点，树变空时进入空目录状态。

这与原型进入知识空间即有当前节点的行为一致，也避免右侧大面积画布只显示“请选择”。不新增“全部知识”虚拟节点，因为当前既无 Entry 查询也无真实全项目知识范围。

### 4. 内容区区分节点信息与知识空态

内容区顶部保留当前节点路径、名称、可选说明和节点菜单/编辑动作；其下展示“这里还没有正式知识”的稳定空态。空态不显示未来功能说明、静态 Entry、来源、计数或不可用的采集按钮。

空目录仍提供“手动创建”和“与 AI 共创目录”两个平等入口，这是现有主规格已确认的产品行为。AI 入口继续打开未实现说明，不生成任何候选目录。

### 5. 不呈现单一模式的假切换控件

原型标题下包含“目录浏览 / 思维导图”，内容工具栏包含“卡片 / 列表”。本 Change 只有目录浏览和知识空态可用，因此省略两组切换控件；使用与原型一致的页面层级和工作台几何，但不呈现不可用或无数据支撑的控件。

### 6. 原型基线

- 对应页面：`docs/prototypes/grove-product-prototype.html` 的“知识空间”。
- 主验收视口：1440×900；扩展视口为 1280×900、1600×900。
- 全局令牌与字体：沿用 `frontend/src/index.css` 的背景、表面、边框、主次文字、品牌色、系统字体、14px 正文、22px/650 页面标题和零字距。
- 应用壳与页面边界：沿用 216px 全局侧栏、52px 品牌栏与主顶栏、24px 页面水平边界；不修改应用壳。
- 关键组件：知识空间工作区为 `250px minmax(0,1fr)`、最小高度 604px；树栏 `14px 10px`，内容区 `14px 24px 28px`，节点工具栏最小高度 50px；树行继续使用现有 36px 稳定高度。
- 动态状态：项目/目录 loading 和 error 保持稳定工作区尺寸；覆盖空目录、默认节点、节点切换、节点无正式知识、操作 disabled、删除确认和 AI 未实现说明。

### 7. 有意偏离

- 不显示原型的目录搜索、直接/子树知识数：当前 API 没有 Entry 和计数，目录搜索也不在本 Change 规格内。
- 不显示“目录浏览 / 思维导图”和“卡片 / 列表”：后者均无可切换的真实第二模式。
- 不显示原型知识卡片、来源和更新时间：当前没有 Entry/Source 数据模型，静态展示会违反产品铁律。
- 不把“目录助手”按钮改造成草稿抽屉：Directory Agent 属于 P1；保留现有未实现说明。
- 内容区空态替代原型的知识列表：这是当前真实数据能力要求，不是视觉偏好。

## Risks / Trade-offs

- [页面叫“知识空间”但暂时只能管理目录] → 通过节点范围和正式知识空态表达正确方向，不呈现任何虚假知识能力；后续 `add-knowledge-browse-and-search` 在同一内容区接入真实数据。
- [保留 `view=directory` 与 UI 名称不一致] → 将它视为内部兼容参数，不暴露给用户；未来路由迁移独立处理。
- [默认选择在树刷新后跳变] → 当前选择仍存在时保留，仅在无效或为空时回退到第一个根节点。
- [空态画布视觉重量不足] → 保持原型内容区和工具栏几何，用紧凑空态承接，不添加装饰卡或未来功能文案填充空间。

## Migration Plan

1. 更新项目导航和项目首页入口文案、激活态测试。
2. 重组项目页目录分支为知识空间结构，加入稳定的默认节点选择和真实知识空态。
3. 保留并回归全部目录 mutation、对话框和删除确认。
4. 完成自动化、截图、计算样式和多视口验收，保存证据。

无数据迁移和后端发布步骤。回滚时恢复前端文案与页面结构即可，现有目录数据和 API 不受影响。

## Open Questions

无。Entry 接入后的“全部知识”、直接/子树范围和卡片/列表行为由后续 `add-knowledge-browse-and-search` 决定，本 Change 不提前锁定。

## Validation Results

- 1440×900 实测工作区为 `1176×604px`，起点为 `(240, 154)`；目录树宽度 `250px`，树栏内边距 `14px 10px`，内容区内边距 `14px 24px 28px`，与本设计基线一致。
- 1280×900 与 1600×900 实测页面 `scrollWidth` 分别等于 `1280px` 与 `1600px`，无横向滚动、遮挡、文字溢出或布局漂移；工作区宽度分别为 `1016px` 与 `1336px`。
- 浏览器交互覆盖空目录双入口、首个根节点自动选中、节点更多菜单、删除二次确认和 AI 未实现说明；页面控制台无 error。
- 页面只显示真实目录数据和“这里还没有正式知识”空态，未出现静态 Entry、Source、知识计数、思维导图或 Directory Agent 行为。

- 自动化结果：前端 8 个测试文件共 18 个测试通过，lint 与生产构建通过；`openspec validate --all --strict` 10 项全部通过；`git diff --check` 通过。
