## MODIFIED Requirements

### Requirement: 按 Source 审阅

系统 MUST 提供按 Source 审阅的工作台；工作台 MUST 展示当前项目内待审 Source、其原始材料与候选；工作台 MUST NOT 展示未归属项目或其他项目的 Source。原始材料中的证据引用 MUST 以归一化方式匹配并高亮（忽略空白差异、统一全角/半角标点与英文大小写），候选切换时 MUST 自动滚动定位到高亮区域；无匹配时 MUST 不高亮且不滚动。来源审阅弹窗 MUST 展示来源原文并在选中候选时高亮对应证据、自动定位。

候选落库前，系统 MUST 将证据引用在对应附件原文中做归一化与模糊匹配，能命中时 MUST 以原文精确子串替代引用落库；省略号摘要引用 MUST 按段拆分，能匹配的段各自作为独立证据；全部段无法匹配时 MUST 保留原引用。前端高亮 MUST 以精确匹配为主，失败时 MAY 使用相似度模糊匹配兜底，相似度低于阈值 MUST NOT 高亮。

#### Scenario: 原始材料与候选同屏

- **WHEN** 用户选择一条待审 Source
- **THEN** 展示该 Source 的原始材料与全部候选

#### Scenario: 项目内待审 Source

- **WHEN** 用户进入某项目的确认台
- **THEN** 只显示该项目内且仍有待采纳候选的 Source

#### Scenario: 证据归一化高亮

- **WHEN** 候选的证据引用与原文存在换行、多余空格、全角/半角标点或大小写差异
- **THEN** 原文中对应片段仍被高亮显示

#### Scenario: 生成端规范化为原文子串

- **WHEN** 组织 Agent 输出的引用与原文存在符号或改写差异但语义对应
- **THEN** 落库前引用被替换为原文精确子串，前端可直接命中

#### Scenario: 省略号引用拆分

- **WHEN** 引用以省略号跳过原文中间内容
- **THEN** 能匹配的各段作为独立证据落库并分别高亮

#### Scenario: 模糊匹配兜底

- **WHEN** 历史数据或轻微改写导致精确匹配失败但相似度足够
- **THEN** 前端以滑动窗口相似度定位高亮，低于阈值则不高亮

#### Scenario: 切换候选自动定位

- **WHEN** 用户在确认台切换到另一条候选
- **THEN** 证据区平滑滚动到该候选第一个高亮片段

#### Scenario: 无匹配不高亮

- **WHEN** 候选的证据引用在原文中找不到对应片段
- **THEN** 不高亮且切换时不做滚动

#### Scenario: 来源弹窗原文高亮

- **WHEN** 用户在来源审阅弹窗选中一条候选
- **THEN** 弹窗展示来源原文，高亮该候选证据并自动定位
