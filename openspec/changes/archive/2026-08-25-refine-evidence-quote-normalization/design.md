## Context

前端已用「归一化 + 分段匹配」覆盖空白/标点/省略号/装饰符号差异，但仍依赖模型引用与原文的字符级近似，逐类适配不可持续。方案：生成端（落库前）把引用规范化为原文精确子串，前端保留精确匹配为主、模糊匹配兜底。

## Goals / Non-Goals

**Goals:**

- 新数据引用是原文精确子串，前端简单匹配即可命中；
- 历史数据由前端模糊匹配兜底；
- 低相似度不高亮，避免误标。

**Non-Goals:**

- 不回填历史数据；
- 不改 organizing 提示词；
- 不新增偏移字段。

## Decisions

### D1：后端规范化服务

新增 `normalize_evidence_quote(text, quote) -> str | None`：

- 归一化：仅保留字母/数字/CJK（与前端一致）；
- 滑动窗口 + `difflib.SequenceMatcher.ratio()` 找最佳区间，阈值 ≥ 0.75；
- 命中时通过「归一化字符 → 原文索引」映射返回原文精确子串；否则返回 `None`。

### D2：省略号拆分

引用按 `…` / `...` 拆段，每段独立匹配；能匹配的段各自生成一条证据（同一 attachment_id、quote 为该段精确子串）；全部失败保留原引用。

### D3：落库接入

在 `save_success_extraction` 落库前，读取该来源附件原文（`text_content` / `ocr_text`），对每个候选的 `evidence` 逐条规范化并重建列表；找不到原文的附件跳过。

### D4：前端模糊匹配兜底

`findEvidenceRanges` 精确匹配失败时，用滑动窗口相似度（字符匹配比例 ≥ 0.75）在归一化原文中找最佳区间并映射回原文；仍失败返回空（不高亮）。现有归一化、分段、多证据逻辑保留。

## Risks / Trade-offs

- [模糊匹配误标] → 阈值 0.75 控制，宁缺毋滥；
- [拆分后证据条数增加] → 前端已支持多证据全部高亮，无兼容问题；
- [OCR 质量差导致匹配失败] → 属于 OCR 问题，超出本 change。

## Migration Plan

无数据回填；历史 `evidence_refs` 保持不变。
