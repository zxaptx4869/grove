## Context

项目列表已通过 `align-project-list-visual-fidelity` 和 `align-project-list-typography-weight` 建立 Grove 当前视觉基线：216/184px 侧栏、52px 品牌栏和主顶栏、`22px 24px 30px` 页面内边距、22px/650 标题、系统字体 430 正文字重和通栏内容。剩余基础页面仍来自较早实现：认证页使用 64px 品牌栏和 12vh 不稳定顶部间距；项目工作台使用 1120px 居中限宽，标题紧贴主顶栏；项目概况、目录树、生命周期与项目编辑混在同一画布；侧栏“项目首页/目录管理”只是页内锚点且激活态固定。

产品原型覆盖项目首页和知识空间的页面层级，但不覆盖登录/注册，也包含 Candidate、Entry、Source、AI 项目理解和 Directory Agent 等尚未进入当前基础体验的静态内容。本 Change 只采用原型的壳层、页面边界、标题区、两栏关系、目录树工作台和控件密度，产品行为继续由当前 OpenSpec 和真实 API 决定。

## Goals / Non-Goals

**Goals:**

- 让登录、注册、项目首页和目录管理与项目列表共享同一视觉基线。
- 将项目首页和目录管理拆为同一路由下可导航、可回退的两个真实视图。
- 让项目首页按原型的主内容 + 右侧信息栏结构展示真实目录概况、项目状态、目标与背景和目录入口。
- 让目录管理按原型知识空间的 250px 树栏 + 剩余内容区结构承载现有目录 CRUD。
- 保持全部 loading、empty、error、disabled、确认状态和 Workspace 隔离。

**Non-Goals:**

- 不实现收集箱、Source、Processing Task、Candidate、Entry、知识空间、项目 AI 理解、Directory Agent、AI 阅读、搜索或思维导图。
- 不创建未来功能占位页面，不显示原型静态知识数、候选数、更新时间或 AI 理解。
- 不修改后端接口、缓存契约、Workspace 校验、数据库模型或迁移。
- 不为登录/注册虚构原型；认证页只采用已确认的 Grove 视觉令牌与密度。

## Decisions

### 1. 现有代码保留、重写和删除判断

- **保留**：所有认证 hooks 与表单校验；项目和目录 TanStack Query；项目编辑、生命周期、目录创建/编辑/移动/排序/删除 mutation；删除确认；AI 共创入口的未实现说明；真实 `description`、`node_count` 和目录树数据。
- **重写**：`AuthLayout` 几何；登录/注册局部密度；`ProjectNavigation` 项目上下文；`ProjectPage` 的可见页面结构和视图切换；目录树外围工作台布局。
- **删除**：认证页 64px 顶栏与 `12vh` 动态顶部间距；项目页 1120px 居中限宽；标题紧贴 `y=52`；同一画布内同时展示项目首页和目录管理；固定“项目首页”激活态；项目侧栏用目标与背景代替生命周期状态。
- **不删除**：现有 API、mutation、对话框和 `NodeTree` 的操作能力；这些行为已符合规格，偏差集中在表现层和导航结构。

### 2. 视觉基线

**认证页（无直接原型）：**

- 使用 52px 白色品牌栏、216px 水平品牌起点概念对应工作台，但表单保持单栏居中，不渲染应用侧栏。
- 表单宽度 360px，桌面顶部使用稳定 88px 间距，不随视口高度按百分比漂移。
- 标题 22px/650、说明 14px/430、输入和按钮 36px、表单字段间距 16px；页面背景、表面、边框和焦点继续使用 Grove 令牌。

**项目首页（原型 1440px 基线）：**

- 继续使用现有 216px 全局侧栏和 52px 主顶栏。
- 页面内容通栏使用 `22px 24px 30px`，不设置最大宽度。
- 标题 22px/650，标题区下方 20px；主体使用 `minmax(0,1.4fr) minmax(280px,.8fr)` 两栏和 28px gap，右栏用 1px 左边框与 22px 左内边距分隔。
- 原型的任务、知识和 AI 理解改为当前真实能力：目录概况/空目录下一步、项目状态、目标与背景、目录共创入口。

**目录管理：**

- 页面标题区与项目首页一致；主体使用 250px 树栏 + `minmax(0,1fr)` 内容区，最小高度 604px。
- 树栏使用右边框、14px/10px 内边距和 34px 工具栏；内容区使用 14px 24px 28px。
- 空目录仍保留两个平等入口：手动创建第一个节点、与 AI 共创目录；非空目录支持选择节点、查看说明并通过现有菜单执行操作。

### 3. 项目视图使用查询参数

`/projects/:projectId` 表示项目首页，`/projects/:projectId?view=directory` 表示目录管理。侧栏使用真实 `Link`，根据 `location.search` 计算激活态；浏览器前进、后退和复制 URL 均保持当前视图。

选择查询参数而不增加 `/projects/:id/directory` 路由，是因为两个视图共享同一项目查询、对话框和操作状态，当前只是基础工作台内部视图；也不使用页内锚点，因为锚点不能表达独立视图和正确激活状态。

### 4. 项目首页只展示真实能力

左侧主区显示目录概况：节点数、空目录说明、进入目录管理和必要的手动创建入口。右侧显示生命周期、目标与背景和目录共创入口。项目更多菜单继续提供编辑和删除。

不复制原型“下一步待确认”“最近知识”“AI 项目理解”，因为当前 API 和 OpenSpec 没有 Candidate、Entry 或 Project Context Snapshot。保留相同标题、两栏和分隔层级，不用静态假内容填充空间。

### 5. 目录操作所有权不变

`ProjectPage` 继续持有 mutation 与对话框状态，`NodeTree` 继续只负责树行和回调。只重组两者外围结构，不提前抽取新的跨页面工作台框架；当前只有一个目录管理消费者，额外抽象没有真实复用价值。

### 6. 认证页采用 Grove 基线而非原型复制

产品原型没有登录/注册页面，因此认证页不生成“原型对照”结论。它们使用项目列表已经确认的字体、颜色、边框、圆角和品牌标记，登录与注册保持相同宽度和节奏。继续使用真实接口、邻近错误、disabled 提交和注册即登录，不增加营销文案、插画或第三方登录。

### 7. 前后端接口与迁移

前端继续调用现有登录、注册、当前用户、项目列表、项目更新、生命周期、删除和目录树 CRUD/排序接口。请求、响应、Query Key 和 Cookie 行为不变。

无数据库字段、索引或数据变化，不创建 Alembic 迁移。回滚只需恢复前端组件结构和 className。

### 8. 验收方式

- 主视口：1440×900 先对齐认证页、项目首页、空目录和非空目录管理。
- 扩展视口：1280×900、1600×900；端侧边界复用并复核 1023/1024。
- 截图：检查壳层、内容起点、标题区、两栏视觉重量、目录树宽度、空态密度和认证表单位置。
- 计算样式：检查 52px 顶栏、216/184px 侧栏、24px 页面内边距、22px/650 标题、28px 首页 gap、250px 目录树和溢出。
- 状态：登录错误、注册校验、项目 loading/error、不存在、空/非空目录、节点选择、AI 未实现说明、删除确认和 disabled。

## Risks / Trade-offs

- [原型项目首页大量内容尚未实现，真实页面会更空] → 保留准确页面边界和两栏层级，用真实目录概况和项目元数据承载当前价值，不用静态功能填充。
- [查询参数视图可能在 mutation 后丢失] → 所有 mutation 只使查询失效，不导航；显式删除项目才返回项目列表。
- [项目侧栏同时依赖项目数据与 URL] → 继续使用现有全状态项目查询，并在数据加载前使用稳定占位文案和禁用风险控制。
- [目录树在 1024px 可用空间变窄] → 侧栏按现有规则收窄至 184px，目录树保持 250px，内容区使用 `minmax(0,1fr)` 和截断，浏览器实测无横向溢出。
- [认证页没有原型可比] → 明确记录为 Grove 基线一致性验收，不宣称原型像素一致。

## Migration Plan

1. 调整认证布局与认证页面密度。
2. 改造项目侧栏为真实视图导航。
3. 重组项目首页和目录管理，保留现有 mutation 与对话框。
4. 更新测试并完成自动化、计算样式和多视口截图验收。
5. 同步规格、归档并本地提交。

无数据迁移。若出现回归，可逐文件恢复前端结构，不影响持久化数据。
