## Context

问题证据、用户目标及涉及能力见 proposal 和多轮基线。当前上下文理解与事实工作集绑定，B1 统计不更新事实工作集，导致连续对话被提前截断。本次解决该衔接，同时补充真实查询所需的项目子集与分组，不重建查询执行器。

## Goals / Non-Goals

目标是同一对话自然完成总数、分组、条件调整、对象查阅与通用讨论；非目标见 proposal。正式 Entry、Source、Candidate 与目录仍不由本次只读链路修改。

## Decisions

1. **复用持久化 Run 形成有界对话上下文。** 在本轮用户消息之前，按消息顺序读取同 Conversation、同 owner/Workspace、同范围的有效消息和终态 Run，遇到 scope_change 或新主题边界截断；保留最近澄清内容、上一任务的独立问题/集合摘要和最近展示列表。它们只帮助理解意图，不创建事实工作集，也不将助手文本送入事实引用路径。已归一化决策及选定消息/对象句柄保存到 context_meta，恢复不重新选择历史。相比新增与消息重复的可变对话表，这样可兼容已有会话并减少双重状态源。
2. **上下文决策负责通用语义合并。** 提供当前可信范围和产品词义，指导在完整问题、可消解追问时直接执行；用户指定新条件覆盖旧条件。澄清只用于真实缺失信息，不为输出措辞和已知范围追问。缺乏工作集不再意味着缺乏对话。对象指代由模型选择近期列表位置，服务端验证位置、范围与 Entry 现状，不允许任意对象 id。
3. **项目名称是筛选条件，不是授权。** EntrySet 增加可选有界 project_name；服务端先在可信 Workspace/项目范围精确解析唯一名称，并在查询与聚合中强制追加同一项目谓词。找不到/重名/越界时不删除条件、不回退全空间。已有 schema 保留版本并增加可选字段，所有模型输入仍拒绝 id 和未知字段。执行快照记录实际筛选项目；恢复及共享图指纹包含该条件。
4. **项目分组返回有标识的桶。** project 分组以项目 id 为键、名称为可选 label，使用限定范围的项目集合左连接匹配 Entry，返回零条项目。保留桶数、结果字节、完整性和排序边界，SQLite/MySQL 使用一致语义。客户端显示服务端 label，旧维度照常展示。
5. **依据限制与回退一致。** 修正规则对通用知识的过宽匹配；明确禁止 Grove 的请求不进入检索兼容分支，纯模型回答保留正常依据与可观测性。用户仅用个人知识库的限制继续有效；不以消除 fallback 为目的忽略非法计划。
6. **评测继续核对真实任务。** 不改写场景来掩盖产品缺陷，统计核对值、完整性及实际范围；新增字段只增加评测识别能力。对新对象指代和开放解释用真实响应人工复核，自动通过不替代原生用户走查。

## Risks / Trade-offs

- 历史边界错误可能误带筛选条件：范围变化、新话题、消息顺序、恢复和跨用户测试必须覆盖。
- demo 只有一个非空项目，数字可能碰巧相等：测试构造两个有数据项目与同名项目；真实评测检查实际集合范围。
- 模型语义不稳定：用原始、多轮和独立变体验证；修复通用输入/状态/工具规则，不增加针对场景的题型路由。
- 原生分组新增 label：增加适配器与 schema 测试，用户执行项目分组和连续追问手动验收后再归档。

## Migration Plan

先完成全库 OpenSpec 严格校验；实施后按相关后端测试、原生测试/typecheck/lint、真实 demo 评测验证。复用现有 Run JSON 字段，不需要数据库迁移。旧快照无可选字段时使用旧语义；不回填用户历史。保存本地阶段提交，等待适用的原生验收与归档批准，不推送或合并。
