## Why

真实多轮基线显示，当前范围未进入上下文理解，统计与澄清后的主题承接中断，依据限制规则还会把通用知识请求反向解释。结果是 48 次实际提问只有 3 次通过确定性检查；项目统计另有范围缺失与工具维度不足。详见 `docs/验收记录/knowledge-agent-multiturn-baseline-2026-09-05.md`。

2026-09-06 首轮实现后的自动评测已完成，但用户手动测试 Conversation 172（Run 366–370）仍暴露任务衔接缺陷：单项目查询后分项目统计沿用了错误条件；真实项目“新疆旅行”被规划为语义搜索词，数字碰巧一致掩盖了口径错误。现有“近期历史 + 上轮集合 + 独立问题改写”不足以表达任务切换和条件来源。本轮仅修订设计与验收计划，业务实现尚未开始，原生验收未通过。

## What Changes

- 将当前可信范围、有限对话主题、待澄清任务及最近展示对象提供给上下文决策；对话意图承接不以事实工作集为前提，仍隔离范围切换、新话题与失败数据。
- 统计追问继承必要集合条件、支持用户替换条件；列表序号引用只解析服务端实际展示对象，并在本轮重新校验和读取。
- 明确全部知识默认包含全部正式 Entry 类型；修复通用知识与个人知识库限制混淆，失败回退保留用户依据限制。
- 为受限集合增加项目名称筛选，由服务端在 Run 授权范围内精确解析；增加按项目分组、零条项目和项目名称展示，不允许模型指定授权 id 或改变 Run 范围。
- 复用并增强现有真实多轮评测，补充范围、恢复、未写入及调用方兼容验证。
- 在现有 Pydantic AI 与 Run 持久化上增加有界、版本化的对话任务状态：区分任务目标、关注对象、查询条件、依据限制与最近结果；支持条件修改、深入后返回、插话后恢复与纠正。任务状态只用于意图及执行控制，不成为事实依据。
- 上下文决策选择本轮任务，查询规划结合原始消息、选定任务与真实项目候选一次解释条件变化；服务端归并、校验和固化计划。独立改写句保留兼容用途，不再成为结构化查询唯一输入。
- 以状态变化和执行参数为主要评测对象，加入组合、对照与保留集；不将每个自然问法转换成专门路由，也不把“分项目”固定等同于撤销项目筛选。

不引入 LangGraph/Rasa，不实现通用 B2 Agent 循环、跨会话长期记忆、外部搜索、知识写入或 Operation Plan；本轮最小实现范围是只读查询任务，开放讨论和复合回答只接入必要上下文边界与兼容约束，不重建其执行图。

## Capabilities

### New Capabilities

- 无。

### Modified Capabilities

- `knowledge-agent-follow-up`：可信范围、独立于事实工作集的对话承接、澄清恢复与结果对象指代，以及任务版本、条件来源、恢复边界和规划输入契约。
- `knowledge-agent-structured-query-tools`：项目名称子集、项目分组和全部知识类型口径，以及项目实体核实、条件增量归并与结果口径一致性。
- `knowledge-agent-answer-basis`：通用知识限制的正确识别与跨回退路径保持，以及任务切换后的用户陈述隔离。

## Impact

后端上下文决策、依据策略、结构化/复合查询与执行、Run 诊断和结果 schema；原生端分组展示与 API 类型兼容；多轮评测及必要自动化测试。优先复用已持久化 Run、消息和快照表达对话状态，不新增正式知识对象。新能力通过可选字段保持旧 Run 可读；项目 id、Workspace 和对象读取权限继续由服务端控制。

修订涉及 `dialogue_context.py`、`follow_up.py`、上下文/查询规划 Agent、`runner.py`、`structured_entry_search.py` 与依据装配。外部结果形态和统计工具 schema 继续复用；内部任务协议版本化并保存在 Run JSON 中。具体兼容、恢复与分支接入边界见 design。已有修复及其验证记录保留，新增设计不代表旧评测已覆盖新增行为。
