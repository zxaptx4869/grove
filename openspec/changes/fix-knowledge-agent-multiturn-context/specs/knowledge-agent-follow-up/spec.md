## MODIFIED Requirements

### Requirement: 有限历史只用于意图理解

系统 MUST 只向承担意图理解的上下文决策和查询规划阶段提供配置上限内的同一 Conversation 与当前范围链内的近期消息、可信范围名称、有界任务及其来源、待澄清任务、最近展示对象和工作集标题；回答阶段只能接收服务端从同一 Conversation、同一范围快照、本轮选定任务链中选出的有界用户消息，以及本 Run 重新读取的正式 Entry/Evidence。供模型选择任务的历史范围 MUST NOT 自动成为回答依据范围。历史助手回答 MUST NOT 直接进入回答事实上下文、被标记为用户陈述或作为正式知识引用；系统 MUST 分开保存意图理解实际使用的消息 ID 与允许作为本轮用户陈述的任务消息 ID，并记录最终采用的依据消息 ID。

#### Scenario: 解析省略指代
- **WHEN** 用户追问“它为什么更适合”且近期消息与活动主题能确定“它”的含义
- **THEN** 上下文决策可据此生成包含明确对象的独立查询或开放回答问题

#### Scenario: 继续话题使用用户陈述
- **WHEN** 当前决策为 `continue`，近期用户消息包含回答所需的个人前提且该消息仍在服务端允许集合内
- **THEN** 依据规划器可以选择该消息，回答将其标记为“用户提供的信息”并保存消息 ID

#### Scenario: 历史回答包含无引用说法
- **WHEN** 近期助手消息含有未被当前 Run Evidence 支持的说法
- **THEN** 回答阶段不把该说法当作用户陈述或独立事实，只能使用本轮允许的用户消息、模型通用知识和重新读取的正式 Entry/Evidence

#### Scenario: 新话题切断旧用户陈述
- **WHEN** 当前决策为 `new_topic`
- **THEN** 回答阶段只允许当前用户消息，不把旧上下文链中的用户陈述作为本轮形成依据

#### Scenario: 历史超过上限
- **WHEN** Conversation 历史超过配置的消息数量或单条长度
- **THEN** 系统只使用稳定选取并截断后的有限历史，同时分别保存上下文决策和实际用户陈述所用消息 ID

#### Scenario: 当前范围已经明确
- **WHEN** 用户在已选择项目的对话中询问当前项目总数
- **THEN** 上下文决策接收该项目的可信名称，不要求用户重复提供项目

#### Scenario: 范围与新话题边界
- **WHEN** 用户切换范围或显式开始新话题
- **THEN** 系统建立硬边界，旧范围或旧主题中的任务、统计集合和对象序号不进入新任务，恢复时复用已固化的决策输入

#### Scenario: 自动切换任务后恢复
- **WHEN** 自动判断用户暂时讨论另一个任务，随后用户明确恢复边界内仍可用的先前查询任务
- **THEN** 系统可以选择该任务版本并重新查询，不自动混入中间任务的筛选、用户陈述或工作集；自动 new_topic 本轮仍不继承旧任务事实

### Requirement: 用户显式模式覆盖自动判断

系统 MUST 将 `continue` 与 `new_topic` 视为用户确定性指令；分类模型 MUST NOT 改变显式模式的语义，且重复提交同一 `client_message_id` MUST 返回首次保存的模式与决策。任务状态协议下，显式继续只允许延续或调整可确定的关联任务，不得暗中开始无关任务；显式新话题 MUST 清除旧任务继承资格。

#### Scenario: 强制继续当前主题
- **WHEN** 对话有活动工作集且用户以 continue 提交问题
- **THEN** 系统继续关联任务，工作集仅作为该任务的合法检索种子，本轮仍重新校验对象与依据

#### Scenario: 强制开始新话题
- **WHEN** 用户以 new_topic 提交问题
- **THEN** 系统在提交事务关闭旧活动工作集并以当前消息开始独立检索，旧任务也不能通过 resume 绕过此边界

#### Scenario: 重试时改变模式
- **WHEN** 客户端以相同 client_message_id 重试但提交不同 context_mode
- **THEN** 系统返回首次创建的消息与 Run，不改写已保存模式或重新执行

### Requirement: 追问改写为可独立检索查询

系统 MUST 为 continue 决策生成非空的 standalone_query，使其脱离聊天记录仍表达本轮检索目标；原始用户消息 MUST 保持不变。任务状态协议下，结构化查询规划 MUST 同时读取原始请求、选定任务及必要的有界历史，改写句仅为兼容检索表达，不得成为新增或撤销筛选的唯一依据。结果路由只判断展示契约，不修改查询条件。

#### Scenario: 成功改写追问
- **WHEN** 用户在“闭水试验时长”主题下追问“为什么不能提前放水”
- **THEN** 系统保存包含闭水试验对象的独立查询，并保留原始追问消息供展示与后续理解

#### Scenario: 改写模型不可用
- **WHEN** 用户强制 continue 但上下文模型未配置或调用失败
- **THEN** 旧协议使用主题标签与当前消息形成确定性独立查询并标记降级；新协议只有可保持已固化任务条件及操作时才执行兼容路径，否则返回具体澄清或可见失败，不依据拼接句猜测新筛选

#### Scenario: 改写与原始条件冲突
- **WHEN** 改写句增加原始请求和选定任务均不支持的项目或语义条件
- **THEN** 本轮查询不将该改写句视为已确认条件，规划以原始请求和任务来源为准，记录最终条件变化

### Requirement: 歧义通过澄清回复处理

系统 MUST 在无法安全确定追问对象或用户强制继续但既无对话主题也无可用历史线索时返回澄清回复；澄清 Run MUST NOT 执行知识检索、生成事实引用或更新工作集。

#### Scenario: 自动判断需要澄清
- **WHEN** `auto` 消息含有无法从有限上下文解析的指代
- **THEN** 系统返回 `answer.status=clarification` 的具体澄清问题并正常结束 Run

#### Scenario: 无工作集强制继续
- **WHEN** 对话既无活动工作集、也无同范围对话主题或有效历史且用户提交 `context_mode=continue`
- **THEN** 系统请求用户补充主题，不猜测或读取无关历史对象

#### Scenario: 澄清不推进上下文
- **WHEN** Run 以澄清回复结束
- **THEN** 输入工作集保持不变且 Run 不产生输出工作集版本

#### Scenario: 统计回答后继续
- **WHEN** 上轮返回统计而未创建事实工作集，用户要求分组或修改筛选条件
- **THEN** 系统使用上轮任务和有限历史理解继续请求，重新执行统计，不因没有事实工作集而澄清

#### Scenario: 补充澄清后执行
- **WHEN** 用户补充了上一轮询问的必要信息
- **THEN** 系统合并原任务与补充信息继续执行，不重复索取已经明确的范围或输出口径

#### Scenario: 分组存在实质性范围歧义
- **WHEN** 同一追问可合理解释为恢复先前汇总或细分当前子集，且有限上下文不足以区分
- **THEN** 系统只询问两种实际统计范围的差异并保存未决任务，不固定清空条件、不静默选择更宽集合，也不要求用户重新描述完整任务

### Requirement: 上下文决策可观测且安全降级

系统 MUST 记录上下文决策/改写阶段的 provider、model、prompt 版本、fallback、错误和耗时。旧协议 auto 模型不可用时 MUST 显式降级为 new_topic，不得静默沿用旧工作集；新任务协议 MUST 同时记录输入任务版本、任务选择、条件变化及归并结果，失败不得产生有效任务版本或静默放宽条件。降级决策 MUST NOT 被解释为用户显式重置。

#### Scenario: 真实模型完成判断
- **WHEN** 自动上下文决策由配置的模型成功完成
- **THEN** 阶段记录实际 provider/model 与 is_fallback=false；新协议可以关联所选任务及条件来源

#### Scenario: 自动判断模型失败
- **WHEN** 自动上下文模型未配置、超时或结构校验失败
- **THEN** 系统记录失败原因和降级；旧协议按 new_topic 兼容处理，新协议在无法保证当前任务语义时停止执行并显示失败，不用失败的候选替代有效任务

## ADDED Requirements

### Requirement: 对象指代只绑定真实展示结果
系统 MUST 将列表序号解释为同范围、同话题最近成功展示的有序对象快照；模型只能选择快照内的位置或句柄，服务端 MUST 重新校验对象归属和当前可用性，本轮重新读取内容与来源，不能把历史列表或助手文字作为事实证据。

#### Scenario: 第二条详细说明
- **WHEN** 上轮展示多条 Entry，本轮要求解释第二条
- **THEN** 系统锚定实际展示的第二个 Entry，读取其当前内容和 Evidence，最终回答保持该对象

#### Scenario: 对象失效或序号不存在
- **WHEN** 对象已经删除、移出范围或用户指定不存在的序号
- **THEN** 系统说明目标不可用或请求选择，不静默换成另一条对象

### Requirement: 对话任务以有界版本管理

系统 MUST 将任务目标、关注对象、查询状态、条件来源、依据限制、未决信息与结果引用分开保存，模型只可选择服务端提供的同 owner、Workspace、Conversation、范围及硬边界内任务句柄。任务状态 MUST 有版本、条数、深度和体积上限，查询和讨论任务都不能把历史答案保存为可直接复用的事实。未明确恢复的暂停任务 MUST NOT 自动贡献查询条件或用户陈述。

#### Scenario: 关注对象不是默认筛选
- **WHEN** 对话提到一个项目但本轮请求未将其用作查询限制，选定任务也无此限制
- **THEN** 系统可记录该项目为关注对象，但不因此添加 project_name 或 semantic_query

#### Scenario: 深入后返回
- **WHEN** 用户从汇总查询深入单个项目后明确返回之前汇总
- **THEN** 系统选择可用的汇总任务版本、应用本轮修改并重新执行，不继承子任务项目条件或直接复用旧总数

#### Scenario: 插话后恢复
- **WHEN** 查询中间插入通用讨论后用户明确恢复先前仍在边界内的查询
- **THEN** 系统恢复该查询任务；中间讨论的内容和依据限制不自动写入原查询任务

#### Scenario: 任务超出预算
- **WHEN** 用户指代的任务已经被裁剪或位于硬边界之外
- **THEN** 系统具体说明缺少的任务信息，不无界扫描历史、不伪造任务状态或读取范围外内容

### Requirement: 任务候选与有效结果分开提交并可恢复

系统 MUST 在执行前固化输入任务版本、任务选择和候选计划；只有终态可用结果才提交相应有效查询/结果版本。澄清只保存未决任务，失败或取消只保存尝试，不得覆盖先前有效状态。相同 Run 的重试和恢复 MUST 使用已保存的协议及计划，旧历史不回填；未知或损坏的新协议 MUST 显式失败，不能静默按旧语义重猜。

#### Scenario: 澄清后的简短补充
- **WHEN** 上轮保存了待确认的任务范围，本轮只回答其中一个项目名
- **THEN** 系统将补充应用到该未决任务并继续规划，不把项目名作为无关新问题

#### Scenario: 失败后更正
- **WHEN** 一次查询失败后用户更正其项目名称
- **THEN** 系统可读取失败请求理解更正，但不能把失败候选条件或缺失结果作为已验证任务继承

#### Scenario: 空结果与部分输出
- **WHEN** 查询得到合法空集合、正常截断列表或部分可用输出
- **THEN** 系统可提交与实际可用输出一致的状态，保留完整性和未完成标记，不把失败输出保存为成功的零条结果

#### Scenario: 新旧协议与崩溃恢复
- **WHEN** Worker 恢复已保存协议及计划的 Run，或新 Run 首次读取旧历史
- **THEN** 已开始的 Run 按原协议恢复且不重选基线；旧历史仅从可核验消息和计划派生 legacy 基线，不将缺失来源补写成用户显式条件
