## ADDED Requirements

### Requirement: 实验入口与正式运行隔离
系统 MUST 提供仅命令行使用的对话循环实验入口，默认执行无模型预检，真实模型运行 MUST 显式启用。实验 MUST 使用经应用认证的 demo 身份和开发数据库一致快照的隔离副本，MUST NOT 更改正式 App/API/Worker 路由或向原库写入实验 Run。临时数据库和本地报告 MUST 限制访问并按设计清理敏感副本。

#### Scenario: 原库路径被用作执行目标
- **WHEN** 实验配置解析后的执行数据库路径等于原库，或后台 Worker 未隔离
- **THEN** 预检失败且不执行 Run 或模型调用

#### Scenario: 正常对照运行
- **WHEN** 用户显式启动已获批的固定对照
- **THEN** 两臂使用相同快照的独立副本及同一已验证身份，原库不新增实验对话且正式业务表保持不变

#### Scenario: 付费前全链路彩排
- **WHEN** 用户启动无模型全链路彩排
- **THEN** 系统以显式本地代表值走完两臂固定顺序、24 个逐轮检查点与最终报告，且模型请求为零、不将彩排结果冒充语义验收

### Requirement: 统一 Agent 按工具结果选择下一步
实验 MUST 让同一 Agent 接续用户原话、必要历史和配对工具消息，选择回答、针对性澄清或一个及多个白名单工具调用；MUST NOT 要求先通过独立任务分类、结果形态路由或完整执行图规划。补查结果 MUST 返回 Agent，不能被直接当作最终回答。

#### Scenario: 同一问题包含解释和查询
- **WHEN** 用户同时询问概念、知识库内容和统计
- **THEN** Agent 可以组合通用解释和实际工具结果，不被强制归入单一文字或列表通道

#### Scenario: 首次搜索不足
- **WHEN** 工具返回部分材料且预算仍允许继续
- **THEN** Agent 可针对缺口继续调用工具或诚实说明不足，调用结果重新进入同一对话上下文

### Requirement: 第二版确定性管理历史上下文
第二版实验 MUST 保留每轮用户原话与已展示回答，并将历史工具结果确定性压缩为包含实际条件、状态、完整性、必要统计、列表句柄、标题和准确顺序的结构化摘要。大段正文与来源原文 MUST 保存在程序侧并按需重新读取，MUST NOT 新增摘要或任务分类模型。模型请求、工具调用和工具返回 MUST 保持协议配对，MUST NOT 直接截断序列化消息字符串。

#### Scenario: 历史列表经过缩减后被引用
- **WHEN** 较早轮次展示了有序列表，后续经过话题切换再次引用其中一项
- **THEN** 历史摘要保留同一结果集句柄、标题和准确顺序，程序据此定位对象并在当前轮重新核验范围与来源

#### Scenario: 本轮新增工具材料接近输入预算
- **WHEN** 工具返回后估算的下一次完整模型输入达到资料软阈值
- **THEN** 系统停止继续取资料，保留一次计入总额的收尾请求并在预算内回答；若收尾也无法容纳则不调用模型并明确说明限制

#### Scenario: 估算与真实 usage 并存
- **WHEN** Provider 返回实际 token usage
- **THEN** 报告分别记录派发前长度估算与实际 usage，不声称估算值是精确 token 上限

### Requirement: 范围与查询条件独立管理
实验 MUST 从认证和固定上下文取得授权范围，工具 MUST 复验每次访问。查询项目条件 MUST 明确表达合法项目或授权范围全部，MUST NOT 因参数省略自动继承全局当前项目。已执行条件与用户消息来源 MUST 可审计，模型 MUST NOT 以话题背景扩大授权或让程序隐式增加筛选。

#### Scenario: 单项目后回到全部项目
- **WHEN** 用户先查询某项目，随后明确要求全部项目
- **THEN** 下一查询清除单项目筛选，但仍受原有 Workspace 和界面范围约束

#### Scenario: 越权项目或对象
- **WHEN** 模型请求当前授权范围之外的项目或 Entry
- **THEN** 程序返回 denied，不提供该对象内容，记录真实拒绝原因

### Requirement: 历史对象引用与当前证据复验
实验 MUST 保存实际展示结果集及其有序对象映射，以结果集引用和位置解析追问，并在每轮重新校验对象范围。正文读取 MUST 遵守既有已发现集合规则；Grove Citation MUST 仅使用当前 Run 实际读取并核验的来源句柄，历史回答或旧 Evidence MUST NOT 直接成为本轮事实。

#### Scenario: 插入讨论后恢复第三项
- **WHEN** 用户列出五条记录、插入普通讨论，再要求该列表第三项的来源
- **THEN** 程序解析原列表第三个真实对象，复验其范围并读取当前来源，而非由模型重写标题后猜测对象

#### Scenario: 对象失效或引用属于旧轮
- **WHEN** 对象已移出范围或回答直接引用历史 Evidence
- **THEN** 不展示为当前有效依据，返回不可用或要求本轮重新读取

### Requirement: 工具状态不得伪造零结果
实验 MUST 保留领域工具原始状态，并向 Agent 区分已完成、无匹配、部分、未执行、错误与拒绝。预算不足或失败形成的空集合 MUST NOT 输出为精确零条；语义检索截断 MUST NOT 表达为完整总数。共享领域缺陷阻断复用时 MUST 报告，不静默修改旧基线或伪造结果。

#### Scenario: 额度耗尽时请求统计
- **WHEN** 所需集合查询未执行或只得到部分语义候选
- **THEN** 返回未完成及相应完整性，不将空数组计为完整集合的零条

#### Scenario: 确定性完整查询无记录
- **WHEN** 授权范围内完整确定性集合的聚合成功且数量为零
- **THEN** 返回可信零值及查询口径，区别于未执行和语义未匹配

### Requirement: 第二版提供明确统计接口和记录类型默认值
第二版实验 MUST 在适配层分别提供精确总数工具与分组统计工具，两者 MUST 复用既有底层统计实现，MUST NOT 要求模型组合 `operation` 和 `group_by`。记录类型筛选 MUST 可选，未指定时覆盖全部正式记录；只有用户明确限定内部类型时才筛选。工具结果 MUST 记录实际类型、项目和权限条件，错误 MUST 指出具体字段与原因。

#### Scenario: 用户询问知识库记录总数
- **WHEN** 用户以泛称“知识库记录”或“知识”询问总数且未明确内部类型
- **THEN** 总数工具查询授权范围内全部正式记录，并将可信总数明确展示，不能以分组数相加代替回答

#### Scenario: 用户明确限制记录类型
- **WHEN** 用户明确只查询 method、parameter、reminder 或内部 knowledge 类型
- **THEN** 工具只应用所指定类型筛选，并在结果条件中记录该筛选

#### Scenario: 用户要求按项目汇总
- **WHEN** 用户要求按项目分组统计
- **THEN** Agent 调用分组统计工具，结果包含项目与数量的准确对应关系及适用的零条桶，不填写互相冲突的统计操作字段

### Requirement: 模型和工具执行有共享硬边界
实验 MUST 执行 design 第 6 节冻结的批次、请求、材料和时间上限，所有路由、重排、向量、重试和收尾调用均计入。预算 MUST 在派发前预留；独立工具并发 MUST 不共享 AsyncSession 或不受控可变上下文。耗尽时 MUST 禁止进一步工具调用，并在可用预留额度内收尾；模型无法收尾时 MUST 返回显式失败。

#### Scenario: 同批提出多个搜索
- **WHEN** Agent 同时提出独立搜索
- **THEN** 程序按并发和共享额度分配执行，各调用分别返回状态，不能让第二条的零额度伪装成无匹配

#### Scenario: 内部调用无法纳入计数
- **WHEN** 预检发现领域工具的模型调用或框架重试无法受共享上限控制
- **THEN** 阻止真实评测启动并报告，不通过遗漏计数来宣称预算合规

#### Scenario: 达到批次上限或重复异常
- **WHEN** 达到冻结上限或相同基础设施异常第二次发生
- **THEN** 停止整批，保存已完成与未执行项，不自动增加额度或重复付费运行

### Requirement: 混合回答引用真实结果
实验 MUST 支持有序文字、统计引用、列表引用和来源引用的本地输出。程序 MUST 用合法工具结果解析数字和对象，拒绝未知句柄及伪造原文；最多一次输出纠正后仍失败 MUST 明确失败。语义正确性 MUST 与引用合法性分别评价。

#### Scenario: 文字与统计列表混排
- **WHEN** Agent 在回答中引用合法统计、列表和 Evidence
- **THEN** 本地报告按模型选择的顺序展示文字和真实数据，保留形成依据

#### Scenario: 合法句柄但问题遗漏
- **WHEN** 回答只绑定了某需求的结果，却未真正回答该需求
- **THEN** 人工语义审阅记录遗漏，不能因句柄合法自动判定整段通过

### Requirement: 对照报告可复查且不夸大结论
实验 MUST 按 design 第 7 节三组固定四轮输入对照相同模型和数据，预期答案 MUST 不传入 Agent。首批 MUST 最多 24 条消息且不自动重复。报告 MUST 记录代码和配置摘要、实际文本、工具与模型状态、原始错误、token 可得性、耗时、停止原因和逐段评价；密钥、密码、隐藏推理 MUST NOT 写入报告。模型自评 MUST NOT 作为唯一验收依据。

#### Scenario: 旧流程因工作集冲突失败
- **WHEN** 旧路径出现已有数据库或生命周期故障而实验路径绕开该机制
- **THEN** 报告记录集成差异，不仅凭该失败宣称新循环语义质量更优或旧问题已修复

#### Scenario: usage 或可比数据不足
- **WHEN** 调用 usage 不可得、前置对象缺失或多数可比轮次未完成
- **THEN** 对应费用标记未知、依赖追问标记 blocked，并按证据不足报告，不计作成功

#### Scenario: 实验达到继续条件
- **WHEN** 三组确定性边界与人工语义审阅通过，可比轮次有具体改善且无新增退化
- **THEN** 仅建议进入正式接入规划，MUST NOT 自动切换 App、合并分支或宣称生产验收完成

#### Scenario: 第二版无模型验证完成
- **WHEN** 第二版相关测试和全链路彩排通过
- **THEN** 报告只证明基础设施与确定性边界，并输出原三组及表达变体的模型、快照、消息数和请求预算清单，不将其视为语义理解通过或自动启动真实评测
