## Why

用户浏览信息以手机为主（移动端采集随原生 App 单独规划，本轮不做），但电脑端承担「集中整理」角色，需要把采集降到两步以内。当前电脑采集需手动保存/复制再上传，多步且长内容分段截图无法保持上下文。浏览器扩展「框选截图 → 批次发送 → 一键进收集箱」复用现有 Source 多附件与 OCR 链路，让整理时段效率最大化。

## What Changes

- 新增 Chrome（Chromium 系）浏览器扩展（Manifest V3，本地开发者模式加载，不上商店）：代码放在仓库子目录 `browser-extension/`。
- 框选截图：快捷键（`Cmd+S`，冲突时退 `Cmd+Shift+S`）或点击扩展图标进入框选模式，页面遮罩拖框；框满视口即整页截图，拖局部即局部截图。
- 批次管理：截图追加到当前批次，底部预览条显示张数，可取消单张；用户显式「发送批次」。
- 发送：一个 Source 多个图片附件直进收集箱（不选项目，归属交给 AI 推荐）；发送后轻提示成功并可选查看收集箱。
- 登录态：复用浏览器 Grove 会话；未登录时提示并打开登录页。
- 首次引导：点击扩展图标展示快捷键与使用说明；扩展内可配置 Grove 服务器地址（默认本地 dev）。

## Capabilities

### New Capabilities

- `browser-capture`: 浏览器扩展框选截图、批次管理与一键发送到 Grove 收集箱。

### Modified Capabilities

（无；后端复用现有 `create_source` 多图上传，预期零改动）

## Impact

- 新增 `browser-extension/` 扩展工程（Manifest V3 + 构建工具 + content script + popup）。
- 后端：预期无改动；联调时验证登录会话与上传链路。
- 测试：扩展构建与静态检查；端到端手动验证（真实页面框选 → 收集箱出现 Source → 走确认流程）。

## Non-Goals

- 不做商店上架、Firefox / Safari 适配、无痕模式适配。
- 不做长截图（滚动拼接）；不做桌面截图工具；不做移动端采集。
- 发送时不提供项目选择与备注输入（归属由 AI 推荐）。
- 不支持浏览器内置页（`chrome://`、扩展商店）与 Chrome 内置 PDF 查看器框选。
