## Why

实验统一循环在长对话中仍会把已渲染的 Entry 正文和 Evidence 原文随完整回答重复写回历史，并在本轮第一次正常请求达到 9000 软阈值时直接转入收尾。真实记录 `session-20260909-222648 / e49b01d3-db3e-47dd-bfa4-8cfc84160e7a` 进一步证明：原 Agent 在收尾阶段仍能执行资料工具，导致来源已经取得却因单次收尾请求上限无法组织最终回答，而且“继续”没有可恢复材料可用。人工验收记录 `session-20260910-175455 / d1a0cb53-fb13-41a8-8295-0e392a87befb` 又暴露出同一边界的后续缺口：用户明确要求“抛开知识库”后，普通阶段虽已禁用资料工具，但输出校验失败转入 finalizer 时丢失了该约束；finalizer 引用了历史 Evidence，失败后没有无资料回答可恢复的 continuation，“下一轮继续”又被当作普通新请求并重复读取 Evidence。后续记录 `session-20260911-092517 / b955e4ae-269b-4276-bd95-2b8512537ee8` 还表明，用户说“帮我把第一条的知识补充一下，发给我”时，现有连续短语匹配没有识别出候选稿交付，误把只需返回文本的请求报告为正式 Entry 写入能力不支持。切换 `deepseek-v4-flash` 后的记录 `session-20260911-104336 / fe11f237-c328-439e-8969-86be8ce2d517` 又出现三次收尾输出失败：模型默认 high 思考模式累计产生大量隐藏推理，分别输出错误句柄类型、错误顶层结构和 text 块多余 `note`；其中一次公开状态为 `can_continue=true` 却没有 continuation，随后“继续”被当作普通请求并重复读取了 Evidence。修复后的人工记录 `session-20260911-115702 / 7fae950d-fc2a-4e8c-8cb2-3d4190ad9a91` 证明非思考设置、无资料回答和句柄顺序已生效，但 finalizer 仍把完整合法内容包在旧式 `answer_summary + completion` 外壳中，导致本可一次完成的回答被严格结构校验转为部分完成。继续验收的 `session-20260911-123115 / f614baa1-3ac3-422f-9e2e-3b254b3769b3` 第五轮表明普通 Agent 也会一次生成内容完整的旧式候选稿；仅在 finalizer 事后兼容会先触发格式纠正，随后被软阈值切入收尾并丢失该候选稿。

## What Changes

- 从结构化回答块、工具摘要和程序状态生成有界历史，保留用户原话、结论、后续建议、授权列表顺序、对象与来源状态，同时不把已展开正文或 Evidence 原文重复放回模型历史。
- 保持 9000 软阈值与 12000 硬上限数值不变：本轮第一次正常请求只受硬上限约束，后续正常请求达到软阈值时停止资料循环并转入收尾。
- 使用独立、程序级不注册资料工具的 finalizer 完成唯一一次收尾请求；资料工具形态的输出不得执行，并记录 `finalize_tool_attempted` 后确定性兜底。
- 在资料已取得但最终回答因输出非法、超时或系统故障未完成时，保存可校验、可恢复的 finalize-only continuation；用户明确继续且主题未切换时只重试最终回答，不重复搜索或 Evidence 读取。
- 将本轮“使用知识库/不使用知识库”的回答依据作为执行约束贯穿普通阶段、finalizer 与 continuation；无资料回答的 finalizer 不接收历史资料句柄或工具结果，不得输出 Entry、Evidence 或正式记录列表。
- 以“修改动作 + 交付或审核信号”的组合规则识别中间带对象描述的候选补充稿请求；仅返回明确尚未写入的候选文本，直接保存、覆盖或写入正式 Entry 的请求仍不支持。
- `deepseek-v4-flash` 在统一对话求解与收尾阶段显式使用非思考模式，以延续旧 `deepseek-chat` 的非思考行为；不改变模型名、上下文或任何冻结预算。
- 只有实际保存 continuation 时才公开 `can_continue=true`；没有可恢复步骤的孤立“继续”不得调用模型或资料工具，也不得重读历史成功材料。
- 普通求解与收尾共用的模型响应边界确定性忽略 text 块的无害备注字段，并仅对已观察到的旧式 `answer_summary + completion` 最终回答外壳做受限转换；保留 Provider 原始响应和兼容事件，叙述转为 text、引用转为标准块后仍经过当前轮授权与来源校验，模型自报完成状态不被采信，错误句柄、错误引用类型或越权材料仍不修正。候选稿的“只输出补充后的内容”表达只返回带必要边界的文本，不展开 Evidence 原文。
- 无资料最终回答失败时保存最小 answer-only continuation；“继续”或“下一轮继续”只重试最终回答，不恢复资料工具能力，也不重新读取历史 Evidence。
- 候选修改稿的 finalizer 只接收已保存稿件并输出文本；模型附带的 Evidence、列表或统计块在校验前丢弃，不执行、不引用且不得使完整候选稿失败；续执行保存完整文本和校验缺口，资料关系仅供程序侧复验。
- 在实验工作台公开状态中保存和展示真实的续执行能力、材料失效与收尾失败原因，并补充针对长对话、权限与第三批结果集合边界的离线回归测试。

本 change 不包含分页、全部查询效率优化、输入估算算法重做、预算扩容、额外规划/摘要/分类模型或正式知识写入能力。

## Capabilities

### New Capabilities

- `knowledge-agent-long-dialogue-finalization-experiment`：实验统一循环的确定性历史压缩、软阈值触发时机、无资料工具收尾隔离及最终回答续执行。

### Modified Capabilities

无。本 change 延续第三批授权结果集合与实验工作台合同，不修改其他 active change 的范围，也不改变正式 App/API/Worker 的公开协议。

## Impact

- 主要影响 `backend/evals/dialogue_loop/`、`backend/evals/dialogue_workbench/`、`frontend/src/experiments/dialogue-workbench/` 及对应离线测试。
- 复用既有结果句柄、授权集合、来源边界、部分完成状态、预算和工作台本地保存生命周期；不新增数据库迁移、依赖、模型类型或写权限。
- 保持正式 Entry 只读、Source 可追溯、Workspace/项目/目录归属校验，以及前三批的 SQLite 稳定性、目录统计、正文展示、相关性过滤和查询去重行为。
- 自动化验证只证明上下文、工具执行、续执行与状态合同；自然语言指代和最终答案质量仍需用户在实验工作台人工验收。实施完成前不归档、推送或合并。
