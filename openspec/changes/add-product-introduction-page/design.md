## Context

范围与行为见 proposal 和增量规格。用户授权直接实施正式页面，无独立原型。现有 AuthLayout 是 52px 品牌栏与 360px 表单，全局 DesktopBoundary 阻断小屏所有路由。

## Goals / Non-Goals

以两个场景、三个 AI 能力与三个端解释产品，桌面首屏保留登录。只展示产品能力，不增加业务能力、模拟登录或商店链接。

## Decisions

- 在正式 LoginPage 中组合公开 ProductIntroduction 与原有登录表单；登录表单独立为 LoginForm，保持接口、错误与跳转语义。
- 登录页使用独立公共布局，注册页继续使用 AuthLayout，避免介绍干扰注册流程。
- DesktopBoundary 仅对 `/login` 放行；小屏 `/` 引导介绍，其余路由维持阻断。公开页没有业务查询；通过统一视口 hook 保证小屏不挂载 LoginForm。
- 说明性流程采用原生 HTML 和 Lucide，明确标注示例，无静态业务 API 或伪造操作。以目录树、候选与对话的可读结构直接展示产品价值。
- 不更改全局主题，新增页面局部样式；公共展示标题有意大于工作台字号，因用户明确要求产品介绍，原工作台的非营销式布局不约束公共介绍。

## Risks / Trade-offs

- 示例可能被误认成已加载用户数据 → 每个示意区域标明示例，使用虚构说明材料。
- 小屏公开入口可能放开业务 → 路径精确匹配、路由测试验证没有业务查询及认证表单。

## 页面审阅后的精简（2026-10-13）

用户要求删除截图中的底部引导块并简化细碎提示。沿用已授权的能力与路由范围：移除底部引导和技术栈横条；首屏合并说明；删除重复流程条、区块眉题、场景提问与总结、目录标签和长示例免责声明；三端各保留标题、职责和适用的真实体验状态。AI 区域保留单一「示例」标识、候选与草稿的待确认状态及引用来源，设计原则继续解释共用后端与数据隔离。区块间距从 88px 收敛为 72px，示意区域最小高度从 434px 调整为 360px。无新的业务或规划范围变更。

## 固定导航与 AI 标签页（2026-10-13）

用户明确要求加强选中态和切换感、固定顶部栏并移除右侧登录入口，授权覆盖本次关联工件与实现调整。

- 导航保持原有 72px 桌面 / 64px 手机高度，使用 sticky/top:0 与白色背景、20 层级，布局仍占据文档流；公共跳过链接使用固定定位并置于导航之上。内容区与主题不变。
- 区块定位偏移按导航高度与原区块内边距计算，标题留在导航下方 16px；登录区域偏移导航高度 +16px。回到顶部目标移到普通文档流的页面根部，避免 sticky 目标已可见时浏览器不滚动；保留可聚焦返回及跳过正文入口。
- 使用已安装 radix-ui 的 Tabs，无新增依赖。标签组沿用三列，但收拢到共同浅底容器（6px 内边距、6px 间距、12px 圆角）；标签约 52px 高，选中为品牌绿底白字，未选为次文字并有白底悬停反馈，去掉跳转箭头。手机保持横向三列，图标与换行标签纵向排列。
- Tabs 维护 aria-selected、tabpanel 与关联标识、单个标签的 Tab 停留和方向键/Home/End 操作；示例内容与真实登录流程不变。
- 回归 1440px 主视口与 1280/1600/1023/1024/390px；检查滚动固定、锚点遮挡、回到顶部、选中/悬停/键盘焦点、手机文字换行与非预期溢出。
