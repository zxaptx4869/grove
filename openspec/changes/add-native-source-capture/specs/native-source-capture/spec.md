## ADDED Requirements

### Requirement: 原生采集入口

收集栏目 MUST 提供「相机 / 相册 / 文本」三个入口并替换此前的未接入占位。相机入口 MUST 调用系统相机拍摄 1 张并提交为一条单图 Source，MUST NOT 做连拍或连续扫描。相册入口 MUST 先让用户选择「每张一条」或「多张合并一条」，再打开系统相册选择器，两种形态都 MUST 支持多选 1–5 张，选择器 MUST 以 5 作为数量上限而不做静默截断。文本入口 MUST 支持输入或从系统剪贴板填入文字并提交为一条文字 Source。

#### Scenario: 相机拍一张
- **WHEN** 用户在收集栏目点击相机并完成拍摄
- **THEN** 系统得到 1 张图片并进入采集表单，提交后生成一条单图来源

#### Scenario: 相册每张一条
- **WHEN** 用户选择「每张一条」并选中 N（1–5）张图片
- **THEN** 系统按张分别提交，最终生成 N 条独立来源，表单提示「这 N 张将分别作为 N 条材料提交」

#### Scenario: 相册多张合并一条
- **WHEN** 用户选择「多张合并一条」并选中 N（2–5）张图片
- **THEN** 系统一次请求提交 N 张图片，最终生成 1 条多图来源，表单提示「这 N 张将作为一条材料一起整理」

#### Scenario: 文本采集
- **WHEN** 用户在文本入口输入或从剪贴板填入文字并提交
- **THEN** 系统生成一条只包含该文字的来源

### Requirement: 采集表单字段

采集表单 MUST 只包含「补充说明」（可选，提交为 `note`）与「所属项目」（可选，默认未归属）两个字段，项目选项 MUST 来自 `GET /api/projects`。图片采集 MUST NOT 附带正文文字。

#### Scenario: 默认未归属
- **WHEN** 用户采集时未选择项目
- **THEN** 提交请求不携带 `project_id`，来源保持未归属

#### Scenario: 选择项目与补充说明
- **WHEN** 用户选择项目并填写补充说明后提交
- **THEN** 请求携带对应的 `project_id` 与 `note`，来源保存这两项

#### Scenario: 图片不携带正文
- **WHEN** 用户采集图片
- **THEN** 表单不提供正文输入，请求不携带 `text`

### Requirement: 图片客户端预处理

上传前系统 MUST 把图片统一转成 jpg：长边不超过 2048、quality 0.8；MUST NOT 放大尺寸小于上限的图片。预处理 MUST 同时解决 iOS 默认 HEIC 输出与单张 10MB 上限，使上传文件类型为 `image/jpeg`。

#### Scenario: 大图压缩
- **WHEN** 用户选择长边超过 2048 的图片
- **THEN** 上传文件的长边被缩到 2048 并以 quality 0.8 的 jpg 保存

#### Scenario: 小图不放大
- **WHEN** 用户选择长边不超过 2048 的图片
- **THEN** 系统只做 jpg 转码，不放大尺寸

#### Scenario: HEIC 转 jpg
- **WHEN** 用户选择 HEIC（或其它非 png/jpg/webp）照片
- **THEN** 上传文件为 jpg，不会因类型被后端 400 拒绝

### Requirement: 采集权限处理

相册或相机权限被拒时，系统 MUST 说明权限用途、告知系统不会再重复弹出授权，并提供「去设置」入口跳转系统设置；MUST NOT 反复弹窗或静默失败。

#### Scenario: 相机权限被拒
- **WHEN** 用户点击相机但相机权限已被拒绝
- **THEN** 系统显示用途说明与「去设置」入口，不打开相机

#### Scenario: 相册权限被拒
- **WHEN** 用户进入相册入口但相册权限已被拒绝
- **THEN** 系统显示用途说明与「去设置」入口，不打开选择器

### Requirement: 上传通道与超时

系统 MUST 使用独立的 multipart 上传通道提交采集，MUST NOT 复用固定 JSON 头与 12 秒超时的通用请求函数。上传请求 MUST 通过 FormData 传 `files`（`{ uri, name, type }` 形式）、`capture_key`，并在有值时传 `text`、`title`、`project_id`、`note`；MUST NOT 手动设置 `Content-Type`。单次上传超时 MUST 明显长于通用请求超时（取 90 秒）且失败时给出可重试的提示，MUST NOT 静默重试。

#### Scenario: 请求形态
- **WHEN** 用户提交一次图片采集
- **THEN** 请求为 `POST /api/sources` 的 multipart，包含图片文件与 `capture_key` 字段，且未手动设置 `Content-Type`

#### Scenario: 上传超时
- **WHEN** 单次上传超过 90 秒仍未返回
- **THEN** 该条目失败并提示网络问题，用户可以沿用同一键重试，系统不自行重发

### Requirement: 批次键与幂等重试

一次采集动作 MUST 生成一个批次标识，第 i 个提交单元 MUST 使用 `capture_key = "{batchId}:{i}"`（序号从 1 开始，长度不超过 128）。同一提交单元重试 MUST 复用同一个键；用户重新发起一次采集（即使内容相同）MUST 使用新批次标识。图片采集 MUST 显式传 `title`，文本采集 MUST 不传 `title`（沿用正文首行的默认标题）。

#### Scenario: 同一张重试复用键
- **WHEN** 某一张上传失败后用户点击重试
- **THEN** 该次重试使用与首次相同的 `capture_key`，服务端命中时返回 200 而已存在来源，不产生重复来源

#### Scenario: 新一轮采集换键
- **WHEN** 用户在一次采集成功后重新发起采集
- **THEN** 新采集使用新的批次标识，即使内容相同也生成新的来源

#### Scenario: 图片显式标题
- **WHEN** 用户提交图片采集
- **THEN** 请求携带 `title`（形如「图片 2026-09-23 15:20」，每张一条且多于 1 张时附 `· M/N`），不依赖原始文件名

### Requirement: 逐张提交与触发处理

「每张一条」MUST 按张串行提交单文件请求，MUST 显示「正在上传 N 张中的第 M 张」形式的进度，MUST NOT 使用百分比。每个提交单元成功后 MUST 立即对其来源调用 `POST /api/sources/{id}/process`；该端点返回 409（来源正在处理或已完成）MUST 视为正常，MUST NOT 提示失败；其它处理启动失败 MUST 单独提示「来源已保存，但处理启动失败」，MUST NOT 让用户重新采集该条。

#### Scenario: 串行进度
- **WHEN** 用户以「每张一条」提交 3 张图片
- **THEN** 系统依次提交 3 次单文件请求，并在界面显示当前进度为第几张

#### Scenario: 逐条触发处理
- **WHEN** 某个提交单元成功创建来源
- **THEN** 系统立即对该来源触发处理；触发失败时只提示处理未启动，来源保持已保存

#### Scenario: 重试命中已在处理的来源
- **WHEN** 重试的提交单元命中已存在来源（返回 200），且该来源正在处理或已处理完成
- **THEN** 触发处理返回 409 被当作正常结果，界面只显示该条已提交，不提示处理启动失败

### Requirement: 部分失败与重试

多个提交单元中部分失败时，系统 MUST 继续提交其余单元，MUST NOT 中途整批中断或回滚已成功条目，并 MUST 在结束后汇总「已提交 M 条，N−M 条未成功」；失败项 MUST 可逐条重试并沿用各自的键。

#### Scenario: 部分成功汇总
- **WHEN** 3 张图片中 2 张成功、1 张失败
- **THEN** 系统提示「已提交 2 条，1 条未成功」，并只为失败的那张提供重试

#### Scenario: 失败项重试
- **WHEN** 用户点击失败项的重试
- **THEN** 系统只重试该条并沿用其 `capture_key`，已成功的条目不受影响

### Requirement: 后端错误原文透传

上传或提交失败时，系统 MUST 原样展示服务端返回的错误文案，MUST NOT 自造替代文案；网络中断等无服务端文案的情况 MUST 说明材料未保存并保留表单内容。

#### Scenario: 400 原文透传
- **WHEN** 后端返回 400（最多 5 张、单张 10MB、仅支持 png/jpg/webp）
- **THEN** 界面显示该原文，并说明材料未保存、可调整后重新提交

#### Scenario: 网络中断
- **WHEN** 上传过程中网络中断且没有服务端文案
- **THEN** 界面说明材料没有保存到 Grove，已填写内容保留在表单中，可重试

### Requirement: 采集结果自包含

本 change MUST NOT 提供来源列表或来源详情，因此提交结果 MUST 在采集栏目内自包含地给出进行中、全部成功、部分失败与全部失败四种状态，并说明可在桌面工作台或后端接口核对是否入库。

#### Scenario: 全部成功
- **WHEN** 一次采集的全部提交单元成功
- **THEN** 系统显示成功汇总，并说明可到桌面工作台查看处理进展

#### Scenario: 全部失败
- **WHEN** 一次采集的全部提交单元失败
- **THEN** 系统显示失败数量与逐条重试入口，不展示任何业务记录
