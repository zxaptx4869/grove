## Context

现有实验循环把 `search_knowledge`/语义 `query_entries` 的重排候选直接保存为普通 `list` 结果句柄，候选一旦被共享工具加入 `discovered_entry_ids`，模型即可读取并把整个原始列表渲染到工作台。循环已有结果句柄、历史压缩、一次输出纠正、确定性兜底和 `StopState`，目录工具也已有去重与 continuation，但语义搜索没有“候选”和“授权展示集合”的边界，通用续聊也没有成功搜索复用状态。

本 change 只改实验统一循环和工作台。现有共享领域工具继续负责召回、重排、Workspace/项目/目录验证和审计；正式 App/API/Worker 不接入新工具，不改变数据库模型。

## Goals / Non-Goals

**Goals:**

- 在同一 Agent 工具循环内完成候选相关性分层，建立唯一可展示、可读取、可引用的直接相关集合。
- 让等价语义查询最多执行一个底层入口，并在后续失败与继续时复用成功结果。
- 用窄兼容层接收常见旧参数形态，同时保持所有权限和归属边界。
- 让后端终态、确定性回答和工作台文字准确区分未执行、读取失败、预算、能力与系统错误。

**Non-Goals:**

- 不新增意图、规划、相关性评分或覆盖检查模型，不增加现有文本、向量、工具、材料、上下文或时间预算。
- 不为甲醛、乳胶漆等主题增加关键词特判，不建设默认“延伸参考”界面。
- 不改变正式 Entry/Source、写入权限、正式 Agent 路由或数据库结构，不重做第一批和第二批。
- 不用固定 FunctionModel 结果替代真实模型人工验收。

## Decisions

### 1. 原始召回是内部候选句柄，分层工具产生唯一授权句柄

语义 `query_entries` 与 `search_knowledge` 仍调用现有共享召回/重排，但 `_dispatch` 将其 `ResultRecord` 标记为不可展示的 `candidate`。同一个对话 Agent 随后调用 `select_relevant_entries`，为候选中的每个 Entry 提交 `direct`、`indirect` 或 `unrelated` 以及有界理由。程序校验候选句柄属于当前会话、Entry ID 完整且不重复；授权列表按原候选顺序只保留 `direct`，并把分类计数和原始候选映射保存在程序侧。

选择工具不调用新模型、不读取数据库、不消耗领域搜索预算。原始候选可作为当前 Agent 决策材料，但输出校验、正文/来源工具和确定性兜底均拒绝其作为主结果。授权列表沿用 `list` 块、`ResultRecord`、历史有序映射和工作台卡片，不新增第二套展示协议。

备选是按相似度阈值或关键词由程序自动分类，但现有候选没有跨 Provider 可比较的稳定分数，关键词规则也会退化为主题特判，因此不采用。另一备选是新增独立相关性模型，违反本批模型与预算边界。

### 2. 可读取集合从共享发现集合中进一步收紧

共享工具仍把召回候选加入 `discovered_entry_ids`，以保持底层 `read_entries` 的既有门禁不变；实验层新增 `authorized_entry_ids`，只在非语义结构化列表或 `select_relevant_entries` 成功后写入。表面 `read_entries`、`read_evidence` 和列表输出先校验授权集合，再进入共享工具。`open_list_item` 继续只能从实际可展示列表的位置解析，并在数据库读取前重新验证对象范围。

这是一层额外收紧，不替代 Workspace、项目、目录或共享发现集合校验。间接与不相关分类只保存在内部诊断中；本批不提供默认延伸结果，也不把它们加入历史有序列表。

### 3. 规范化查询键串行保护单一语义搜索

循环按规范化查询文本、项目范围/名称、类型与可信目录范围构造查询键。`search_knowledge` 和语义 `query_entries` 进入同一个 `asyncio.Lock` 保护的执行入口：第一个调用执行底层搜索并保存候选；同轮并发或后续 continuation 的等价调用复用既有候选/授权句柄，记录 `not_executed` 与 `duplicate_semantic_query`，不再次派发数据库搜索或向量/重排。

键只用于等价请求去重，不把历史主题猜成新参数。对于“好的，你帮我查一下”类承接表达，动态 instruction 明确要求模型从已保留的用户原话、回答、查询条件和项目上下文恢复主题，并只选一个入口；程序仍校验模型最终提交的显式范围。

若搜索已成功而选择或读取失败，continuation 保存失败工具、授权 Entry ID 与查询键。下一轮明确继续时提示只执行待办；即使模型再次搜索，查询键也会复用成功结果。非语义列表、统计和目录查询不受此去重键影响。

### 4. 参数兼容在表面工具规范化，授权校验保持在下游

`query_entries` 继续把扁平 `sort_field`/`sort_direction` 作为首选参数，同时接受可选的旧式 `sort` 对象。只有一方提供时规范化；两者冲突、字段缺失或枚举非法时抛出 `ModelRetry`，沿用 Agent 的最多一次纠正。可空字符串在进入 `_entry_set`、目录句柄或项目解析前统一把大小写不敏感的 `"null"` 转为 `None`。

兼容层不接受 Workspace ID，不将未知项目改为全局范围，不根据名称猜目录 ID。规范化后仍由 `_entry_directory_scope`、`RunToolContext` 和共享 dispatcher 完成原有范围验证。相比修改共享 Pydantic schema，这种表面兼容只覆盖实验模型常见输出，不扩大正式工具合同。

### 5. 用结果是否可展示决定部分完成，用原因码表达精确状态

新增 `not_executed` 轮次终态，用于没有任何可展示确认材料且查询因参数或前置依赖未执行的情况。已有 `partial_completed` 只在存在授权列表、统计、正文或 Evidence 等可展示材料时使用。搜索候选成功但尚未形成授权列表属于已执行步骤但无可展示结果，确定性回答只说明分层/读取缺口，不展示候选。

当授权集合已形成而 `read_entries` 失败时，`StopState.reason_code=search_succeeded_read_failed`，兜底展示授权列表并指出正文缺口；预算原因保持具体 `*_budget`，能力缺失保持 `unsupported`，未知异常保持 `failed/system_error`。工作台根据 completion reason code 展示“未执行”“搜索成功但读取失败”“预算耗尽”等文字，不用绿色完成态掩盖缺口。

参数验证发生在工具函数入参解析或表面规范化阶段。若唯一纠正仍失败且没有可展示材料，异常归类为 `not_executed/invalid_tool_params`；若此前已有授权材料，则保留这些材料并明确后续步骤未执行，而不是把空 payload 当成有效部分结果。

### 6. 定义型回答由提示合同约束，事实块仍由程序授权

系统提示加入通用规则：定义型问题先用 text 块说明概念和核心结论，再用授权 `list`/正文/Evidence 块展示少量直接相关正式记录；无直接结果时使用 `insufficient` 明确说明。文本必须区分“模型通用知识”“知识库正式记录”“来源原文”。该规则不做关键词识别、不触发额外模型，也不改变自由文本仍需人工语义验收的事实。

## Risks / Trade-offs

- [同一 Agent 对候选相关性仍可能误判] → 程序保证候选来源、三类边界和集合一致性；真实语义效果由工作台人工验收，不用阈值或新模型伪造确定性。
- [新增选择步骤占用一次现有工具动作] → 选择为本地无数据库工具但仍计入既有 Agent 工具动作总额；不提高预算，直接相关不足时诚实停止。
- [查询键规范化可能把表面不同但语义相同的查询漏判] → 只对确定性相同的规范化参数去重，宁可让真实不同查询执行，不做模糊主题合并。
- [历史授权集合扩大可读取对象集合] → 只保存本会话实际授权 Entry，并在每次读取时继续执行 Workspace/项目/对象复验；跨会话状态不恢复。
- [旧式参数兼容增加公开 schema 形态] → 文档和 docstring 明确首选与兼容字段，冲突直接拒绝且只允许一次模型纠正。

## Migration Plan

无数据库迁移。先提交 OpenSpec 工件并通过全库严格校验，再分段实现后端集合/编排/状态、前端状态展示和测试。回滚可撤销本 change 的提交；旧工作台记录保持只读，新会话使用新合同。自动化完成后停留在本地分支等待用户手动验收，不归档、推送或合并。

## Open Questions

无阻断问题。真实模型对定义型问题和承接表达的理解是否稳定，按用户给定的工作台清单人工验证；本批自动化不作语义通过结论。
