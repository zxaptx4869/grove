## ADDED Requirements

### Requirement: 语义候选必须分层后形成单一授权结果集合
实验统一循环 MUST 在既有召回和重排之后，由同一个对话 Agent 将每个候选分类为直接相关、间接相关或不相关；程序 MUST 校验分类只引用真实候选，并按原候选顺序只将直接相关项固化为默认可展示、可读取和可引用的授权结果集合。间接相关和不相关项 MUST NOT 进入默认主答案、正式记录列表、`read_entries` 结果或前端列表卡；分类 MUST NOT 扩大 Workspace、项目或目录范围。

#### Scenario: 候选同时包含三种相关性
- **WHEN** 一次语义召回包含直接相关、间接相关和不相关的正式记录
- **THEN** 授权结果句柄只包含直接相关记录，保留其原始重排顺序，并在内部记录三类数量

#### Scenario: 模型尝试展示原始候选句柄
- **WHEN** 模型将未经过分层的候选句柄用于列表块、正文读取或来源读取
- **THEN** 程序拒绝该引用并要求使用授权结果集合，不把候选列表渲染到主答案

#### Scenario: 没有直接相关记录
- **WHEN** 候选全部被分类为间接相关或不相关
- **THEN** 授权结果集合为空，回答明确没有找到足够直接相关的正式记录，且不以弱相关条目补足列表

### Requirement: 搜索、读取、渲染与位置指代共享授权集合
语义搜索完成后，模型选择、`read_entries`、列表渲染和后续按序号指代 MUST 共享同一授权结果句柄及其有序 Entry 映射。程序 MUST NOT 允许 `read_entries` 读取仅存在于原始候选而未进入授权集合的 Entry；前端 MUST 只渲染回答块携带的授权集合，不从原始召回补充卡片。

#### Scenario: 模型只选中部分直接相关记录
- **WHEN** 原始召回有多条候选而授权集合仅包含其中少量直接相关记录
- **THEN** 搜索公开结果、模型可引用项、`read_entries` 成功项和前端列表卡的 Entry ID 与顺序完全一致

#### Scenario: 后续追问第二条
- **WHEN** 用户追问授权列表中的第二条
- **THEN** 程序从该授权结果句柄的第二个真实对象解析 Entry，并重新执行当前 Workspace 与范围校验

### Requirement: 定义型问题先回答概念再展示直接相关记录
对于询问某概念是什么的定义型问题，Agent MUST 先区分并回答通用概念与核心结论，再通过授权集合展示少量直接相关正式记录；知识库正式记录、Source 内容和模型通用分析 MUST 明确区分，MUST NOT 伪造来源或用间接结果支持定义。

#### Scenario: 定义问题存在直接相关记录
- **WHEN** 用户询问一个概念的定义且授权集合包含直接相关正式记录
- **THEN** 回答先给出概念说明，再展示该授权集合中的少量记录，并标明其为知识库正式记录

#### Scenario: 定义问题没有直接相关记录
- **WHEN** 用户询问一个概念的定义但授权集合为空
- **THEN** 回答仍可给出明确标识为模型通用知识的概念分析，同时说明知识库中没有找到直接相关正式记录

### Requirement: 同类语义查询只执行一个搜索入口
同一轮及可恢复续聊中的等价语义查询 MUST 只执行 `search_knowledge` 或 `query_entries` 中的一个入口。程序 MUST 以规范化主题、项目范围、类型与目录范围建立可追踪查询键，串行决定首次执行或复用；成功查询在选择或读取步骤失败后 MUST 保留，用户继续时 MUST 只重试失败步骤。

#### Scenario: 同一响应提出两个等价搜索入口
- **WHEN** 模型在同一响应中同时调用 `search_knowledge` 与带相同语义条件的 `query_entries`
- **THEN** 程序只派发一次底层搜索，另一调用返回未执行和复用原因，且不额外消耗底层搜索结果

#### Scenario: 承接上一轮建议查询
- **WHEN** 用户用“好的，你帮我查一下”等表达承接上一轮主题、项目范围和已确认上下文
- **THEN** Agent 复用该上下文选择一个搜索入口，不把承接语句本身作为新主题或丢失项目范围

#### Scenario: 搜索成功后读取失败并继续
- **WHEN** 搜索和授权集合已成功形成，但正文读取失败，随后用户要求继续
- **THEN** 程序保留成功查询及授权集合并只重试读取步骤，不重新派发同一搜索

### Requirement: 常见参数形态只做确定性兼容
公开查询工具 MUST 以扁平 `sort_field`、`sort_direction` 和真实可空字段作为首选合同，同时 MUST 接受旧式 `sort: {field, direction}`；字符串 `"null"` MUST 按未提供值规范化。兼容后仍 MUST 执行既有 Workspace、权限、项目、目录和范围校验；互相冲突、枚举外或越权参数 MUST 被拒绝，且合法重试最多一次。

#### Scenario: 旧式排序对象
- **WHEN** 模型仅提交合法的旧式 `sort: {field, direction}`
- **THEN** 程序规范化为当前排序字段后执行一次查询，并在审计中记录实际条件

#### Scenario: 字符串 null
- **WHEN** 模型在可空的项目名、语义条件或目录句柄字段提交字符串 `"null"`
- **THEN** 程序将其视为未提供值，不把 `"null"` 当作项目名、主题或对象句柄

#### Scenario: 兼容参数仍然越权
- **WHEN** 规范化后的项目、目录或对象不属于当前 Workspace 或授权范围
- **THEN** 程序沿用既有拒绝状态，不通过兼容处理改写或放宽范围

### Requirement: 轮次状态准确表达执行与部分完成边界
程序 MUST 区分未执行、部分完成、搜索成功但读取失败、预算耗尽、能力不支持和系统故障。只有存在可展示的已确认内容时才能以部分完成保留该内容；纯参数错误或搜索尚未执行 MUST NOT 表达为已取得有效部分结果。确定性兜底 MUST 展示已确认内容、具体缺口和可恢复步骤。

#### Scenario: 首个工具参数非法
- **WHEN** 查询尚未成功且模型在唯一合法重试后仍提交非法参数
- **THEN** 轮次状态为未执行并说明参数错误，不展示空列表或部分完成结果

#### Scenario: 搜索成功但读取失败
- **WHEN** 授权搜索集合已经形成而 `read_entries` 发生系统错误或对象暂不可用
- **THEN** 轮次状态为部分完成，原因明确为搜索成功但读取失败，并展示授权列表与未读取正文的缺口

#### Scenario: 预算在执行前耗尽
- **WHEN** 预算阻止计划中的搜索或读取派发
- **THEN** 状态明确为预算耗尽，未派发动作标为未执行，且不伪造零条或完整结果

#### Scenario: 能力与系统故障
- **WHEN** 白名单不支持目标或基础设施发生未知异常
- **THEN** 分别返回能力不支持或系统故障，不与参数错误、权限拒绝或预算停止混淆

### Requirement: 只读与既有领域边界不得回退
第三批 MUST 保持 AI 输出仅为候选、正式 Entry 不被自动修改、Source 可追溯、Workspace 隔离、项目与目录归属校验，以及既有 SQLite 稳定性、预算、真实目录、叶子定位、统计口径和正文展示行为。候选修改稿 MUST 继续明确尚未写入；直接保存、覆盖或写入正式 Entry MUST 继续不受支持。

#### Scenario: 候选修改稿与直接写入
- **WHEN** 用户要求生成供自己审核的修改稿或要求系统直接保存正式记录
- **THEN** 前者只输出明确未写入的候选文本，后者报告不支持，且数据库正式 Entry 不发生变化

#### Scenario: 既有目录与统计回归
- **WHEN** 用户按真实目录名称、路径、叶子节点或目录范围查询统计和正文
- **THEN** 系统继续使用真实 Node、权威统计与正文块，并重复执行 Workspace、项目及目录归属校验

#### Scenario: 离线自动化通过
- **WHEN** FunctionModel、后端和前端自动化测试通过
- **THEN** 报告只证明工具合同、集合、状态和渲染边界，不宣称真实模型已理解所有自然语言表达
