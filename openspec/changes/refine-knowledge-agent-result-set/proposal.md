## Why

当前统一对话循环会把语义召回候选直接作为可展示、可读取的结果，导致弱相关条目可能进入前端列表，而模型实际只使用其中少数记录；多轮承接查询还可能重复选择两个语义搜索入口，工具参数错误与后续读取失败也没有稳定区分。第三批需要在不增加独立模型或预算的前提下，把相关性选择、可引用集合、工具依赖和轮次状态收敛为同一条可追踪链路。

## What Changes

- 在现有召回与重排之后，由同一个对话 Agent 将候选标记为直接相关、间接相关或不相关；程序只把直接相关项固化为默认授权展示集合，间接和不相关项不进入主答案、正文读取或前端列表。
- 搜索、模型选择、`read_entries`、列表渲染和后续位置指代统一使用同一个授权结果句柄；定义型问题优先回答概念，再按该句柄展示少量直接相关正式记录，直接结果不足时明确材料缺口。
- 对同轮及续聊中的同类语义查询做确定性去重，阻止 `search_knowledge` 与 `query_entries` 重复执行；读取只能发生在授权集合形成后，成功搜索在后续读取失败或继续时不重复执行。
- 保持公开工具合同明确，并兼容旧式 `sort: {field, direction}` 与表示未提供值的字符串 `"null"`；真正非法的项目、目录、范围与 Workspace 参数继续拒绝，兼容层不参与授权判断。
- 将轮次结果明确区分为未执行、部分完成、搜索成功但读取失败、预算耗尽、能力不支持和系统故障；参数错误在没有已确认材料时不得伪装成有效的部分完成。
- 更新实验工作台的状态文案与结构化列表展示，并补充离线 FunctionModel、后端领域回归和前端渲染测试；不启动真实模型评测。

## Capabilities

### New Capabilities

- `knowledge-agent-dialogue-result-selection-experiment`：统一对话循环中的相关性分层、授权展示集合、单一语义搜索编排、参数兼容与精确结果状态。

### Modified Capabilities

无。第三批继续限定在实验统一循环和实验工作台，不改变正式 App/API/Worker 的公开协议或写入能力。

## Impact

- 主要影响 `backend/evals/dialogue_loop/`、`backend/evals/dialogue_workbench/`、`frontend/src/experiments/dialogue-workbench/` 及对应测试。
- 复用现有 `KNOWLEDGE_AGENT_READ_TOOL_REGISTRY`、召回/重排、`RunToolContext`、结果句柄、部分完成和确定性兜底；不新增数据库迁移、模型类型、依赖或预算。
- 保持正式 Entry 只读、Source 可追溯、Workspace 隔离、项目/目录归属校验，以及第一批稳定性与第二批目录/统计/正文展示行为。
- 自动化验证只证明工具合同、集合与状态边界；自然语言相关性和多轮理解仍由用户在实验工作台人工验收。实施完成前不归档、推送或合并。
