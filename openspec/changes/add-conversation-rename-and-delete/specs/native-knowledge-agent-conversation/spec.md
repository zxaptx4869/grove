## ADDED Requirements

### Requirement: 原生对话重命名与删除
原生 App MUST 在对话历史列表为每条对话提供可读屏识别的重命名与删除入口，并复用服务端重命名与删除接口。重命名 MUST 在提交前校验去空白后非空且不超过 255 字符，非法输入 MUST 就地提示且不发请求，成功后就地更新该行标题而不重载整份历史。删除 MUST 二次确认并说明「对话将从列表移除、内容保留」，确认期间 MUST 显示进行中状态且不可重复提交。

#### Scenario: 历史列表行操作
- **WHEN** 用户打开对话历史列表
- **THEN** 每行提供可读屏识别的重命名与删除入口，且原有的切换对话操作保持可用

#### Scenario: 重命名成功
- **WHEN** 用户在某行提交合法新标题
- **THEN** 客户端调用重命名接口、就地更新该行标题，并保留当前列表滚动位置与选中状态

#### Scenario: 重命名非法输入
- **WHEN** 用户提交空白或超过 255 字符的标题
- **THEN** 客户端就地提示并阻止提交，不发起请求

#### Scenario: 删除确认
- **WHEN** 用户对某行选择删除
- **THEN** 客户端二次确认并说明删除后从列表移除、内容保留，用户取消时不发起请求

#### Scenario: 删除当前对话后回到空白新对话
- **WHEN** 用户删除当前正在查看的对话并确认
- **THEN** 客户端回到空白新对话状态、清空消息与运行状态，且不预先创建服务端 Conversation，直到用户首次发送

#### Scenario: 删除非当前对话
- **WHEN** 用户删除的不是当前正在查看的对话
- **THEN** 客户端只从列表移除该行，当前对话与阅读位置保持不变

#### Scenario: 活动 Run 期间删除被拒绝
- **WHEN** 删除请求因对话存在进行中的问答而返回冲突
- **THEN** 客户端保留该行并就地提示需等待完成或取消，不重复提交删除

#### Scenario: 无待恢复工作时按不存在处理
- **WHEN** 客户端读取的对话已被其他端删除并返回 404，且本地没有未发送输入、pending 提交或待恢复 Run
- **THEN** 客户端按不存在处理，回到空白新对话并刷新历史列表，不反复重试同一对话

#### Scenario: 有本地待恢复工作时保留恢复错误
- **WHEN** 客户端读取的对话已被其他端删除并返回 404，但本地仍有未发送输入、pending 提交或待恢复 Run
- **THEN** 客户端保留明确恢复错误与重试/退出入口，不清空本地输入、pending 状态与对话，由用户显式退出到空白新对话
