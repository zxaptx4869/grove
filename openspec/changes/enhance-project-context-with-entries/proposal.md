## Why

当前 Project Context Snapshot 只基于项目说明与目录生成，无法反映“项目里已经确认了什么知识”，导致目录路由、关系判断和后续 Agent 拿到的项目理解缺少正式知识维度。本 change 把已确认 Entry、知识覆盖和近期主题纳入快照，并记录版本与更新原因，让 Agent 拥有一份稳定、可追溯、不过时的项目上下文。

## What Changes

- 生成器输入扩展为实时数据：项目说明、顶级节点（名称 + 截断说明 + 覆盖计数，超过 50 个截断并标注剩余）、已确认 Entry 确定性摘要（总数、类型分布、按顶级节点覆盖、最近 20 条标题）、用户纠正。
- 快照输出新增：`entries_summary`（确定性聚合，不经 AI）、`recent_themes`（AI 提炼 3–5 个近期主题）、`version`（每次成功生成 +1）、`last_update_reason`。
- `directory_topics` 保持确定性派生（顶级节点名），定位为 Agent 稳定摘要；前端目录主题徽章改为从实时目录树派生，避免展示过期快照。
- 刷新触发策略：只认重要变化（新建/编辑/移动 Entry、应用修订、目录与项目说明变化、用户纠正、手动刷新）；补充来源证据不触发；防抖窗口 + 最小生成间隔可配置，手动刷新始终立即执行。
- 公共上下文接口与前端项目上下文面板展示新增字段。
- 新增真实 LLM 项目上下文生成器（`llm`），使用 Workspace 文本模型生成概要、关注方向与近期主题；无可用密钥时回退为确定性输出；`CONTEXT_GENERATOR` 可在 `llm` / `demo` 间切换。

## Non-Goals

- 不做完整快照版本历史表，只保留版本号与最近一次更新原因。
- 不做语义/向量检索、embedding 或新增依赖。
- 不做 Knowledge Gap / 知识缺口分析。
- 不把 Entry 全量内容写入快照，只存确定性摘要与近期标题。
- 不重写目录路由、关系判断 Agent 的调用链（快照通过公共接口就绪，消费留待后续）。
- 真实 LLM 生成器只负责语义提炼，不改变正式数据；无密钥时确定性回退，不影响功能闭环。
- 不改变 Entry 数据模型，不做跨项目或跨 Workspace 上下文。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `project-context`: 生成输入纳入已确认 Entry 摘要与顶级节点信息；快照输出增加知识覆盖、近期主题、版本与更新原因；刷新触发策略从“所有变化防抖”改为“重要变化白名单 + 防抖 + 最小间隔”。

## Impact

- 后端：`ProjectContext` 模型新增列与 Alembic 迁移；生成器接口与 demo 实现扩展；`services/project_context.py` 增加确定性聚合与触发策略；Entry 服务与项目/目录接口补触发点；API schema 扩展。
- 前端：项目上下文面板展示近期主题、知识覆盖、版本与更新原因；目录主题徽章改为从目录树派生。
- 数据：`project_contexts` 新增可空列，无回填；版本从现有快照开始计数。
- 依赖：无新增第三方依赖。
