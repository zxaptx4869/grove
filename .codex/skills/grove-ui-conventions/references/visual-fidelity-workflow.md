# Grove 视觉对齐流程

只在完整页面实现、页面重建、原型还原、设计稿精确对齐、应用壳或全局令牌调整时完整读取并执行。局部视觉调整按影响范围选择相关部分；非视觉任务不要加载本文件。

本文件只定义 Web 与浏览器原型的视觉检查；任务分流、批准、证据记录与无 change 情况遵循 [主 Skill](../SKILL.md)。正式原生端不套用浏览器矩阵。

## 工作顺序

```text
规格与原型范围
      ↓
视觉基线 + 有意偏离
      ↓
1440px 主视口实现与收敛
      ↓
截图 + 计算样式双重验收
      ↓
1280px / 1600px 扩展验证
      ↓
关键状态与必要断点
      ↓
保存必要证据并核对完成条件
```

用户提供其他尺寸的权威截图时，用该尺寸替代 1440px 作为主视口，按主 Skill 的记录规则说明。

## Definition of Ready

修改完整页面样式前由代理核对以下适用条件；不逐项要求用户确认：

- 已按任务范围读取相关规格或原型说明、必要产品专题、`frontend/src/index.css` 与页面代码；复用已读且未变化的材料。
- 已明确本次产品行为、明确不做和真实 API 字段。
- 已填写视觉基线表，不使用 Tailwind、shadcn/ui 或浏览器默认值代替测量。
- 已列出有意偏离，并为每项提供规格、真实数据、可访问性或演示包装理由。
- 已明确主验收视口和需要覆盖的状态。
- 先从原型源码、计算样式、令牌和同类组件解决细节；仍会显著改变结果的实质性歧义已记录并得到用户确认。

受阻条件未解决时，不实现依赖该条件的样式；其他已明确的工作可继续。

## 视觉基线表

按实际页面选择字段，不存在的元素标记“不适用”，不要编造数值。

| 层级 | 提取内容 |
|---|---|
| 全局令牌 | 页面色、表面色、柔和表面、边框色、主次文字色、品牌色、状态色 |
| 字体 | 字体栈、正文基线、标题/正文/说明字号、行高、字重、字距、字体平滑 |
| 应用壳 | 侧栏宽度、顶栏高度、分隔线、背景层级、内容起点、窄桌面规则 |
| 页面边界 | 最大宽度、水平与垂直内边距、标题区高度、主操作位置、区块间距 |
| 固定组件 | 筛选、列表行、图标容器、徽标、按钮、输入框、圆角、边框、阴影 |
| 动态内容 | 长文本截断、数量变化、加载占位、空态、错误、disabled、菜单和确认态 |
| 端侧边界 | 1280/1440/1600 布局；受影响时检查 1023/1024 |

按主 Skill 的记录规则保存确定值，无 change 时不强造 design.md。实际主题值仍以 `frontend/src/index.css` 为准，不在本 reference 保存页面像素值。

## 有意偏离判断

以下理由可以构成偏离：

- 当前 OpenSpec 未包含原型中的功能或动作；
- 真实 API 没有原型静态展示的字段；
- 原型内容属于文档切换器、演示窗口或静态包装；
- 可访问性、真实交互状态或用户数据需要不同呈现；
- 产品蓝图或主规格明确覆盖原型行为。

以下理由不能构成偏离：

- Tailwind 或 shadcn/ui 默认就是这样；
- 现有旧页面这样实现；
- 实现者觉得另一种样式更好；
- 大致看起来相似；
- 为了少改几行代码。

## 实施顺序

1. 先校准全局令牌和字体基线，但只修改本任务确认需要的共享范围。
2. 再实现应用壳几何、页面边界与背景层级。
3. 再实现标题、筛选、列表或工作区的主要几何。
4. 最后调整字重、图标、边框、圆角、阴影和交互细节。
5. 正式实现保持真实数据和适用状态，不得为了截图改用静态假数据；独立探索原型可使用明确的确定性模拟。

每完成一层就在主视口检查，不要同时在三个桌面宽度反复调参。主视口稳定后再扩展验证。

## 双重验收

### 截图检查

检查：

- 壳层和内容起点；
- 信息密度与留白；
- 主次层级与视觉重量；
- 颜色关系和表面层级；
- 固定控件形态；
- 长文本和真实数据对布局的影响；
- 页面整体是否保持安静、紧凑、适合重复操作。

### 计算样式与边界检查

至少核对关键元素的：

- `width`、`height`、`padding`、`margin`、`gap` 和边界位置；
- `background-color`、`color`、`border`、`border-radius`、`box-shadow`；
- `font-family`、`font-size`、`line-height`、`font-weight`、`letter-spacing`；
- 横向溢出、文字截断和固定控件是否因动态内容发生位移。

截图和计算样式不能互相替代。计算值一致但整体观感不一致时继续检查表面层级、字体渲染和密度；截图相似但计算值明显漂移时修正实现，避免在其他数据或视口下失效。

## 验收矩阵

| 任务类型 | 编码前 | 主视口 | 扩展视口 | 证据 |
|---|---|---|---|---|
| 完整页面、重建、原型还原 | 完整视觉基线与偏离清单 | 截图 + 计算样式 | 1280/1600；必要时 1023/1024 | 截图、计算值、偏离说明 |
| 局部视觉精修 | 受影响基线 | 相邻布局 + 计算样式；需要时截图 | 仅跨断点或共享范围受影响时 | 受影响项结论 |
| 全局令牌或应用壳 | 完整共享基线与影响页面 | 截图 + 计算样式 | 1280/1440/1600 和必要断点 | 多页面抽查与影响说明 |
| 纯文案、数据逻辑、API、不可见重构 | 不适用 | 功能与可访问性验证 | 按行为需要 | 自动化测试结果 |

## Definition of Done

完整视觉流程完成前确认：

- 主视口已完成原型与正式页面同尺寸截图对照。
- 关键几何、颜色和字体已经读取浏览器计算样式核对。
- 主视口（默认 1440px，权威截图可覆盖）及 1280px / 1600px 无非预期溢出、遮挡、文字截断或布局漂移。
- loading、empty、error、partial、retry、disabled 和破坏性确认按当前任务的适用范围稳定。
- 端侧边界受影响时，1023px 不加载工作台，1024px 完整可用。
- 所有剩余差异都有记录且属于有意偏离，不存在“以后再看”的未知视觉偏差。
- 截图、计算样式结论和偏离说明按主 Skill 的记录规则保存；已有验收记录直接引用，不重复存放同一证据。
- 相关测试、lint、build 通过；正式 change 另须满足 AGENTS.md 的严格校验与收尾条件，无 change 的修复不新增 OpenSpec 流程。
