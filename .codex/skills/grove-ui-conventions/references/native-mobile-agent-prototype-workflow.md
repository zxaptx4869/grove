# Grove 原生移动端与对话 Agent 原型流程

只在原生 App、移动端产品形态或对话式 Agent 的探索性原型、实现与评审任务中读取。手机 Web 仍遵循桌面工作台的小屏阻断边界，不得用本流程把 Web 业务界面重排到手机。

本文的浏览器尺寸、DOM 和控制台检查只适用于 HTML 移动原型。正式原生端由 AI 运行相关自动化检查并提供走查清单，设备操作及人工验收遵循 AGENTS.md；不得以浏览器模拟键盘或截图替代原生系统验收。局部修改只检查受影响项，不重复执行完整矩阵。

## 权威边界

- 产品专题、已确认讨论和用户当前决定定义产品行为；原型只验证形态与关键交互，不反向宣布正式范围。
- 有 active change 时按其规格实施并记录必要设计，现有验收记录直接引用；探索原型在对应说明记录基线和偏离，`docs/prototypes/README.md` 只保留入口。无 change 的局部修复在交付说明记录结论，必要证据沿用 `artifacts/`，不强造工件。
- 原生 App 原型可以复用 Grove 品牌、语义令牌和对象语义，但不决定正式 App 技术栈，也不改变手机 Web 阻断策略。
- 正式实现不得直接复制探索原型的内联样式、演示脚本或静态业务状态。

## 工作顺序

```text
用户核心场景与端侧职责
        ↓
信息架构、范围与对象上下文
        ↓
关键对话轨迹和页面状态
        ↓
移动视觉与交互基线
        ↓
可点击确定性原型
        ↓
多视口、键盘与状态走查
        ↓
截图、控制台与偏离记录
```

先验证一个完整纵向场景，再补栏目骨架和次要状态；不要为了显得功能丰富而堆叠不可走通的页面。

## Definition of Ready

开始完整移动端原型前由代理核对；可从既有材料确定的细节不要求逐项用户确认，仍有重大歧义时再澄清：

- 已说明这是原生 App、探索性原型还是正式实现，不与手机 Web 混淆。
- 已明确用户核心目标、首条纵向场景、当前不做和需要模拟的失败路径。
- 已确认对话、页面、卡片、Sheet、全屏审阅和系统能力各自承担什么职责。
- 已区分知识范围、页面上下文、用户引用对象和 Agent 当前工作集，不存在用户不可感知的隐式收窄。
- 已明确主设备尺寸、扩展尺寸、安全区、键盘态、底栏和长内容滚动策略。
- 已查找并优先复用仓库中的现有移动原型、品牌资产、语义令牌和原创图标方向。

## 对话式 Agent 界面语义

### 范围、上下文与工作集

- 当前知识范围必须持续可见；范围改变使用明确事件或提示，不得只改变隐藏查询参数。
- 当前页面或用户主动引用的 Entry、Source、目录等对象使用可见、可移除的上下文表达，不自动替代知识范围。
- 会话允许切换范围时，旧回答保留生成时的范围来源；切换后不得把旧工作集伪装成新范围结果。
- 跨项目或跨范围结果显示对象归属，避免用户把引用误认为来自当前项目。

### 回答、引用与正式对象

- AI 即时回答、AI 草稿、Candidate、正式 Entry 和 Source 原文使用不同文案与视觉语义。
- 综合正式 Entry 得出的回答写“基于正式知识”或等价措辞，不把回答自身标记为“正式知识”。
- 关键结论提供到 Entry 与 Source 的可达引用；原文片段和 Agent 总结必须可辨识。
- 冲突、适用条件和知识不足作为回答内容的一部分呈现，不用模型常识或伪精确信心掩盖缺口。

### 过程、澄清与操作

- 只展示用户可验证的阶段，如搜索知识、读取条目、核验证据、等待确认、执行和降级；不展示隐藏推理或装饰性的“思考过程”。
- 过程状态在完成后切换为完成态文案，不能同时出现“正在处理”和“已完成”。
- 指代或目标不明确时使用澄清卡或短追问；普通讨论不得被强制路由成内容修改。
- 操作建议显示目标对象、范围、差异和风险；执行结果与建议状态分离，可逆操作提供撤销，长任务提供恢复与失败重试。

## 移动信息与交互基线

- 对话可以是主要入口，但证据、差异、确认、任务进度和对象详情优先使用结构化卡片、Bottom Sheet 或全屏审阅，不把所有内容塞进聊天气泡。
- 首屏服务核心任务，不使用营销式 Hero、大面积装饰留白或通用客服聊天气质。
- 主要触控目标采用适合移动端的稳定尺寸；纯图标控件提供辅助名称，不只依靠颜色表达选中或风险状态。
- 固定顶栏、输入区、底栏和软件键盘不得互相遮挡；键盘展开后的发送、收起、滚动和焦点恢复必须实际可走通。
- Bottom Sheet 与全屏层处理安全区、返回、焦点归还和长内容滚动；覆盖主导航时关闭后恢复原状态。
- 动态回答、引用数量、长标题、状态徽标和错误信息不得导致固定控件跳动或产生横向溢出。
- Grove Web 正式前端默认使用 Lucide；移动原型可采用已确认的原创或平台中性图标体系，但同一原型内保持尺寸、线条和选中态一致。

## 原型实现边界

- 独立 HTML/CSS/JavaScript 原型可以使用静态数据和确定性模拟，但关键路径必须可点击走通，不能只用静态效果图替代状态转换。
- 模拟动作的前后状态保持一致：范围、会话历史、任务状态、建议、执行和撤销不能互相矛盾。
- loading、empty、error、partial、retry、disabled、知识不足、澄清和完成态只实现当前场景真正需要的部分，并提供可恢复路径。
- 外部脚本、网络资源或系统权限不是原型核心时避免依赖；相机、麦克风和系统分享可以用明确的模拟说明代替真实调用。

## 视觉与交互验收

以下为完整 HTML 移动原型的浏览器检查矩阵，不是正式原生端设备验收结论。用户提供权威设备截图或尺寸时以其为主视口；没有指定时默认：

- 主视口：390 × 844；
- 扩展视口：360 × 800、412 × 915；
- 另行记录平台特定安全区或系统栏差异，不假装单一 HTML 外壳等同所有设备。

完整 HTML 原型至少验证以下适用项；正式原生端将相关交互、安全区、系统键盘和读屏项目列入用户走查清单：

1. 文档和应用无非预期横向溢出，长回答、列表、Sheet 与全屏审阅可滚动。
2. 固定顶栏、输入区、键盘、底栏和安全区在三个视口下不遮挡。
3. 范围选择、会话继续、引用详情、核心纵向场景、知识不足、失败重试及当前范围内的操作状态可走通。
4. 触控目标、焦点、关闭、返回、Escape 替代和辅助名称符合原型载体可支持的可访问性边界。
5. 选中、风险、正式、候选、失败和禁用状态不只依靠颜色表达。
6. HTML 原型的浏览器控制台无未解释的 error 或 warning；截图与 DOM/计算样式检查互相印证。正式原生端不要求 DOM 或浏览器计算样式。
7. 原型状态、说明文档、截图和验收记录一致，不出现截图已更新但说明仍描述旧行为的情况。
