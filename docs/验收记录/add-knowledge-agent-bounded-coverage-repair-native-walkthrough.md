# 知识 Agent 一次有界覆盖补查原生端兼容走查清单

来源 change：`add-knowledge-agent-bounded-coverage-repair`（任务 6.4）

状态：等待用户走查

## 职责边界

AI 已完成原生端自动化测试、类型检查和 lint。本 change 不新增 UI 或公开协议；按仓库约定，
模拟器/真机的交互、视觉、安全区、系统键盘和读屏兼容由用户执行并反馈，AI 不代替填写
手动验收结论。

## 前置条件

- 开启复合回答、共享执行图和一次覆盖补查灰度开关；
- 使用已配置且可调用的文本模型；
- 准备能覆盖甲醛来源、但故意缺少某一细分材料或环保等级的测试知识；
- 回答方式选择“快速”，回答依据选择“自动”。

## 走查清单

1. 提问“甲醛是什么？结合我的知识说明来源，并统计相关知识数量”，确认模型解释、真实
   Citation 和结构化统计仍按既有卡片/文本形态展示，无新增内部补查 UI。
2. 使用首次检索即可完整覆盖的问题，确认回答正常完成，没有重复段落、重复 Citation 或
   可感知的第二次执行痕迹。
3. 构造首次只覆盖部分材料来源、补查能够找到新 Evidence 的问题，确认最终缺口减少，新增
   内容引用可打开到正确 Entry 与 Source Evidence。
4. 构造补查后仍缺环保等级依据的问题，确认已完成内容保留，整体仍显示 partial 或
   insufficient，剩余 gaps 清晰可见，不伪装为 completed。
5. 使用语义条件统计，确认 limited/unknown 仍按有限集合表达；补查不会把 top-k 结果改写
   为当前范围精确全集。
6. 临时切换到未配置或失败的文本模型，确认 fallback 可识别，首次合法回答不会被空白、
   错误候选或“完整回答”覆盖。
7. 在补查执行中取消 Run，确认回到取消状态，不出现正常终态回答、迟到 Citation 或事实
   工作集推进。
8. 在补查执行中退出页面或重启 App，再进入原会话，确认历史恢复一致；首次内容、Citation
   和统计不重复，Run 不重新规划或无限转圈。
9. 分别在 Workspace 与项目范围提问，确认 Citation 和统计只来自当前范围，切换范围后旧
   Run 的历史展示保持原快照。
10. 检查较窄设备、安全区、动态字体、VoiceOver/读屏和系统键盘下既有回答、缺口、Citation
    与 fallback 展示无回归。
