保留 Pydantic AI 和现有只读工具，Run 创建时固定 `dialogue_task_v1` 协议。

服务端完成归并、范围核实与执行；规范化查询计划标记 `task-v1`。

任务池最多五项、深入最多二层、另设字节预算并记录裁剪。自动插话保留可恢复任务，
显式重置和范围变化清空继承边界。成功结果与有效任务状态一起提交，澄清、取消和失败
不覆盖成功条件。恢复讨论只提供选定任务的合法用户陈述；工作集、项目实体和结果
序号在使用前重新核验。空列表会取代旧列表，不能继续引用旧列表中同序号的对象。
任务句柄和条件原文引用接入 Pydantic AI 输出校验，非法输出最多在模型内修正一次；
持续非法仍明确降级，修正不会替代服务端范围核实，实际请求次数保留在 usage 中。

项目候选同时来自模型提出的原文片段和服务端对当前原文的范围内名称精确匹配。
服务端最多取六个不同名称以检测五项上限，不向模型发送项目全集、Entry 内容或计数；
名称出现本身不添加过滤条件。保留未知、重名、已删除后同名替代的拒绝边界。

真实调用前固定；保留场景首次测试暴露的问题也如实记录，后续重复属于修复回归，
不能再称为完全未见过的盲测。旧的开放讨论/指代/澄清场景另行复跑。

旧协议通过临时服务在提交 Run 时关闭任务状态；Worker 按 Run 持久化协议执行，
不会因同一时刻开关不同而改猜语义。抽查旧批 Run 无任务协议，新批 Run 均使用新协议。
自动比较验证数据、模型配置、场景摘要一致；完整运行时配置未由接口全部公开，
不能据此声称所有环境变量均由评测器证明一致。
