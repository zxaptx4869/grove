## 八项核对

| 反馈 | 核对与修复 | 验收边界 |
| --- | --- | --- |
| 1. auto 复合问题进入 investigate | 路由提示识别 quick 的多义务、结构化统计与一次补查能力；使用原始消息决策，解释加来源加统计优先 quick | 提示合同与显式模式覆盖有自动化回归，真实模型路由待复验 |
| 2. 有部分有效回答却 insufficient | 增加内部逐点直接答题标记；仅合法且明确回答核心问题的点可纠正矛盾全局标记为 partial；Run 同步非完整状态 | 边缘证据和非法引用仍 insufficient；不把任意有内容当作回答 |
| 3. 模型依据与文案矛盾 | 依据使用从最终保留的无引用内容派生，不再以权限代替使用；删除无依据的“没有用模型常识”默认说明，状态徽标不被混合依据覆盖 | 旧持久化 answer_basis 不重写；自然语言依据边界仍需真实输出复验 |
| 4. 调查没有结构化统计 | 自动复合统计问题优先 quick，以已有结构化工具执行 | 显式 investigate 仍不支持结构化统计，本次未迁移旧流程，不能宣称此能力已完成 |
| 5. 范围从装修变全部知识 | 只读快照核对：Run 144 属于项目会话 70，Run 145 属于 Workspace 新会话 71；范围在提交前已不同 | 未发现执行器扩大范围；补查失败恢复与界面范围回归通过；新会话仍默认全部知识 |
| 6. 主要来源重复、旁支偏题 | 标题按冻结义务统一，相同义务相同正文去重，复用 Evidence 仅输入一次；明确直接答题要求并拒绝标记为旁支的复合点 | 自动去重不等于完整语义相关性验证；仍需原问题真实模型复验 |
| 7. 受限 0 与 6 不一致 | 实际补查扩大了类型过滤；新增服务端校验禁止改变类型、性质和时间口径，planner 接收首次参数与事实摘要 | 有限语义匹配仍非全量统计；两批合法结果显示首次/补查与不可直接合并边界，不把 6 覆盖为总数 |
| 8. 再综合失败突出旧 0 | 复合输出收窄为 points/conflicts；失败保留首次正文并附加合法确定性统计，持久化 final_result 支持恢复不重放；界面前置专用失败提示和未解决缺口 | 结构化模型仍可能失败；快照容纳不下新增材料时保留完整基线并提示预算边界 |

实际快照中再综合模型错误只有 `Exceeded maximum output retries (1)`，没有保存具体字段校验原因；不据此猜测某个字段是唯一根因。收窄输出合同降低重复状态负担，失败保底则独立于模型能否修正。

## 用户复验

1. 在同一“房子装修”项目会话、自动模式下重问“解释甲醛是什么，结合当前项目说明主要来源，并统计治理方案有多少条”。核对实际 quick、统计工具调用和完整原始问题。
2. 核对部分来源仍显示部分结果；模型通用解释与正式引用分别表达，不出现自相矛盾的依据声明；主要来源不重复且不被环保等级旁支取代。
3. 核对统计仍标明有限结果，不把近义检索命中当作全量治理方案；补查不得放宽类型过滤。
4. 若补查再综合失败，确认正文前的明确警告、保留的首次引用和附加工具事实；离开后返回历史不重复执行补查。
5. 新建会话先核对范围选择；新会话默认全部知识不继承上一项目，不能把跨会话结果当作同范围复验。

显式调查接入结构化统计属于后续能力，已向用户说明并询问是否登记优化清单；未获同意前不自动登记。真实模型与真机走查完成前，本 change 保持本地待验收状态。
