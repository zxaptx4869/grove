# 知林 Grove 项目初始化提示词

你是知林 Grove 项目的主程。Grove 是一个「个人知识管家」Web 产品：把用户散落的收藏/截图/文档，通过 AI 提取整理为结构化知识库，人在确认后归档（产品提案见 PROPOSAL.md）。本次任务是**初始化工程与流程骨架**，不实现业务功能。

## 目标

1. 建立 OpenSpec 工作流骨架（AGENTS.md、openspec/config.yaml、docs/项目上下文与文档路由.md）
2. 创建一个 OpenSpec change `setup-project-foundation`，含 proposal、design、specs、tasks
3. 初始化后端工程 backend/（FastAPI + Pydantic v2 + async SQLAlchemy 2 + Alembic）
4. 初始化前端工程 frontend/（React 19 + TypeScript + Vite + Tailwind 4 + shadcn/ui + TanStack Query）
5. 打通最小可运行链路：前后端启动、健康检查、测试/lint/build、git 提交推送

## 开始前

- 先完整阅读 PROPOSAL.md 与 README.md
- 使用 OpenSpec CLI 确认当前无活动 change；CLI 不可用则先安装或明确提示
- 全程用中文沟通与代码注释

## 范围

### 包含

- 仓库骨架：backend/ frontend/ docs/ openspec/ 目录结构、.gitignore 完善、.env.example（不提交 .env）
- 后端：FastAPI 应用工厂、pydantic-settings 配置、CORS、健康检查 /healthz、async SQLAlchemy 引擎与会话、Alembic 初始迁移（开发默认 SQLite，生产 MySQL 8 通过环境变量切换）、pytest 最小用例、ruff 配置
- 前端：Vite + React + TS 壳、Tailwind 4 配置、shadcn/ui 基础、React Router、TanStack Query、健康检查页/占位首页、vitest 最小用例、eslint/prettier 配置
- AI 层骨架：AIProvider 抽象接口 + DemoProvider（确定性实现）+ get_ai_provider 工厂（可切换 deepseek/doubao/demo，仅定义，不接真实 API）
- OpenSpec 骨架与 setup-project-foundation change
- Git：在 codex/init-scaffold 分支上开发，完成后提交并推送远端

### 不包含（写进 Non-Goals）

- 登录/认证（第一个功能切片另开 change）
- 采集、抽取、确认、搜索等业务功能
- 真实 AI / OCR 接入
- CopilotKit、pydantic-ai 代码接入（只保留文档决策）
- 移动端、部署、OSS 接入

## 工程规范

- 后端 Python ≥3.12，依赖用 requirements.txt 或 pyproject.toml 管理
- 环境变量：DATABASE_URL（开发默认 sqlite+aiosqlite:///./grove.db）、认证/AI 相关键位留占位，.env.example 提供模板
- 数据库：开发 SQLite，生产 MySQL 8；Alembic 迁移必须能在两库跑通并标注差异
- 前端需保证 390px 移动宽度可用
- 测试命令：backend `pytest -q` + `ruff check .`；frontend `npm test -- --run` + `npm run lint` + `npm run build`
- OpenSpec：`openspec validate --all --strict` 通过

## 验收标准

1. 前后端均可启动，/healthz 返回 200
2. 全部测试 / lint / build 通过
3. setup-project-foundation 的 proposal/design/specs/tasks 保持一致，validate 通过
4. 同步 specs 到主规格、归档 change、提交并推送到远端

## 约束

- 严格遵循 OpenSpec 工作流：先提案/设计/规格/任务，再实施；实施完成后 validate → sync specs → archive → commit
- 将产品守则写入 AGENTS.md：AI 输出永远是候选、正式记录必须可溯源、数据按 Workspace 隔离
- 不要复制 KnowStruct 的业务代码；可参考其工程模式（.env.example、Alembic 结构、OpenSpec 骨架）
- 遇到方案分歧先记录决策到文档，不要静默猜测
