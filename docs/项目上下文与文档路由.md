# 项目上下文与文档路由

> 状态：工程初始化（2026-08-12）
> 本文档是 Grove 仓库的「文档入口」，所有新文档先在此登记路由，避免信息散落。

## 1. 项目速览

知林 Grove 是「个人知识管家」Web 产品：把用户散落的收藏/截图/文档，通过 AI 提取整理为结构化知识库，人在确认后归档。产品提案见 [PROPOSAL.md](../PROPOSAL.md)。

产品铁律：

1. AI 输出永远是候选，人拥有最终决定权。
2. 正式记录必须可溯源到原始材料。
3. 数据按 Workspace 隔离。

## 2. 文档路由

| 主题 | 文档 | 说明 |

## 3. 目录结构

```text
grove/
├── AGENTS.md                 # 代理工作守则
├── PROPOSAL.md               # 产品提案
├── README.md                 # 仓库入口
├── docs/                     # 项目文档（含本文档）
├── openspec/                 # OpenSpec 工作流（changes/ 与 specs/）
├── backend/                  # FastAPI 后端
│   ├── app/                  # 应用代码（工厂、配置、路由、db、ai）
│   ├── alembic/              # 数据库迁移
│   └── tests/                # pytest 用例
└── frontend/                 # React 前端
    ├── src/                  # 源码（组件、页面、路由、API 客户端）
    └── ...                   # Vite/Tailwind/shadcn 配置
```

## 4. 决策记录约定

- 技术决策先记录在 change 的 `design.md` 中；跨 change 的长期决策沉淀到本文档或独立决策文档。
- 分歧处理：把候选方案、取舍理由写进决策记录，标记「开放」或「已锁定」，不静默选择。
- 已锁定决策见 PROPOSAL.md 第 13 节；新锁定决策追加时同步更新本文档速览。

## 5. 常用命令

```bash
# OpenSpec
openspec validate --all --strict
openspec list
openspec archive <change-name>

# 后端
cd backend && pytest -q && ruff check .
uvicorn app.main:app --reload

# 前端
cd frontend && npm test -- --run && npm run lint && npm run build
npm run dev
```
