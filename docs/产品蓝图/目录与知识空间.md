# 目录与知识空间

[返回产品蓝图索引](../产品蓝图.md)

> 权威范围：目录共创、知识浏览、卡片与列表、思维导图、搜索、AI 阅读与页面信息架构。

## 目录共创

### 产品定位

新项目默认允许空目录，提供两个平等入口：

```text
手动创建第一个节点
与 AI 共创目录
```

目录共创应由独立的 Directory Agent 承担，而不是一次无状态的“生成目录”调用。

### 三类任务

1. 从零起草：根据项目说明和必要澄清生成候选目录。
2. 节点拓展：读取目标节点、现有子树、项目上下文与相关 Entry，提出更细结构。
3. 调整现有目录：根据自然语言提出新增、改名、移动、更新说明和建议删除。

节点拓展入口位于知识空间目录树的节点菜单与选中节点的内容区；AI 输出目标节点下的完整目标子树（含应保留的现有子节点），系统按名称递归计算“新增 / 保留 / 建议移除”差异供用户逐项确认。目标节点自身与保留节点不被 AI 修改；真正的改名、移动与改说明属于“调整现有目录”能力。

### 统一工作流

```text
用户目标或对话
      ↓
Directory Agent
      ↓
可视化目录草稿
      ↓
结构差异：新增 / 改名 / 移动 / 建议删除
      ↓
用户确认
      ↓
正式目录
```

首次从零起草可返回完整候选树；后续调整优先返回结构化操作，避免完整重写导致节点漂移或丢失。

建议操作类型：AddNode、RenameNode、MoveNode、UpdateDescription、SuggestRemoveNode。

节点拓展与后续目录调整中的“建议移除”默认勾选（经旧项目实测确认，默认不选中会让用户误以为 AI 未响应），但子树含正式 Entry 的节点受保护、不可勾选，并显示阻断数量；差异面板同时展示受影响的子节点与 Entry 数量。正式变更由应用层校验并原子执行。

## 知识使用方式

### 目录浏览

项目知识的主要入口。用户通过目录理解结构，并查看当前节点直接挂载的 Entry 或包含子树的 Entry。

### 卡片与列表

同一批 Entry 的两种视图，不是两种数据模型：

- 卡片：适合阅读、回顾和探索，突出核心内容、适用条件、类型和来源。
- 列表：适合扫描、筛选、排序和批量管理，突出标题、目录、类型、来源和更新时间。
- 系统记住项目内视图偏好。

### 知识全景与思维导图浏览

知识全景是项目级沉浸式阅读视图（唯一入口，与知识空间目录浏览、AI 阅读平级），包含「旭日图 | 思维导图」两种模式，默认展示旭日图；顶部切换，支持跨模式联动，不是编辑器。

**旭日图模式（全局认知）**

- 扇区按深度单色着色，扇区宽度 = 知识量；计数沿用「直接 / 后代 / 合计」口径，与目录浏览的「仅后代」区分；
- hover 高亮祖先路径并显示「直接 / 后代 / 合计」；点击扇区图内钻取，面包屑返回；
- 标签按弧长缩写、hover 补名；
- 支持缩放与平移（滚轮以光标为中心、按钮、适应窗口），不依赖第三方库；
- 右侧目录大纲点击联动旭日图；直接知识列表配合悬浮详情（hover 预览、点击固定）。

**思维导图模式（空间回忆）**

- 图中默认只展示目录节点，不铺开全部 Entry；节点徽标为「直接数 / 合计数」；
- 点击节点就地展开直接知识：叶子节点在右侧居中堆叠、非叶子节点在下方堆叠，再点收起；
- 知识小卡与侧栏条目 hover 预览、点击固定悬浮详情；侧栏可勾选「包含子树」（默认勾选）浏览节点范围知识；
- 支持展开、收起、聚焦子树和搜索高亮；画布线格背景固定，不随内容滚动；
- 无壳沉浸，画布占满窗口；目录编辑、移动、删除和 AI 拓展仍在标准目录管理界面完成，通过「在知识空间中打开」跳转定位。

### 搜索

- P0：项目内和全局关键词搜索，覆盖标题、内容、目录和来源摘要。
- 后续：组合筛选、语义搜索、相似知识和搜索结果问答。
- 全局搜索可以跨项目找到 Entry，但不改变 Entry 的项目归属。

### AI 阅读与提问

AI 阅读演进为 Web 与原生 App 共用的 Knowledge Agent。第一条纵向能力仍定位为“带证据的知识阅读器”，不是依靠模型常识自由回答的聊天机器人；交互可以表现为对话，但底层必须是可恢复、可审计的只读 Run。

支持范围：

- 全部知识：当前 Workspace 内的正式知识；
- 项目阅读：当前 Workspace 内的一个具体项目。

范围选择不下钻到目录节点。目录仍作为项目知识的组织结构、Agent 检索定位线索和引用归属信息；用户通常表达主题而不是先定位目录，Agent 应在选定项目内自动找到相关目录与 Entry。

规则：

1. 默认只读取已确认 Entry。
2. 关键结论附 Entry 与 Source 引用；引用原文必须从本轮实际读取的 Attachment 内容中核验，不能直接采用模型生成的 `quote`。
3. 显示冲突、适用条件和知识不足。
4. 知识库不足时明确说明，不用模型自身知识悄悄补齐。
5. 即时回答不是正式知识；保存回答内容时必须转为 Candidate 再确认。
6. 外部知识边界：AI 阅读只读知识库，不用模型自身知识悄悄补齐；知识补充/修订路径（如 Entry AI 修订建议）
   允许结合知识库与 AI 自身知识，但 AI 补充内容必须在回复与草稿中可辨识，并在应用时以虚拟 Source 沉淀溯源；
   联网外部发现（Discovery）仍后置。
7. 对话、消息和 Run 持久化；连续追问通过“继续 / 新话题 / 澄清”的显式决策与版本化工作集实现，用户可覆盖自动判断。历史消息只用于理解省略和指代，事实回答仍重新检索正式 Entry 并生成本 Run Evidence。
8. 知识增删改不混入只读阅读工具；后续写工具只生成 Candidate 或 Draft，并保持用户最终确认。
9. 工作集只保存当前主题涉及的正式 Entry 线索并设置数量上限；范围切换、新话题会切断旧工作集，失败或澄清不更新。无有效引用时不得加入 Entry；知识不足的新话题可以只保留不作为事实的主题标签，便于理解下一句指代。
10. 每条消息支持自动、快速回答和深度调查。快速回答使用单轮检索；自动模式由 Agent 判断并在失败时显式回退快速回答；深度调查默认最多三轮，只在同一 Workspace/项目范围内根据已核验证据补充查询、检查覆盖和冲突。应用层控制查询去重、Entry/Evidence 数量与停止条件，最终显示实际模式、轮数、停止原因和未解决缺口；不联网、不写知识，也不无限后台运行。
11. 调查账本只服务于当前 Run 的恢复、审计和最终综合，不是正式知识或跨对话记忆。历史回答、历史 Evidence 和过程摘要不能支持事实；只有当前 Run 重新核验的 Evidence 可引用，只有最终有效引用的 Entry 可进入输出工作集。
12. 原生 App 是只读 Knowledge Agent 的首个完整客户端：默认恢复最近对话，也允许先选择 Workspace/项目范围再在首次发送时创建对话；历史页优先展示最近消息并向前加载。上下文理解和回答方式默认自动，用户可对下一条消息覆盖为继续/新话题与快速/深度调查。Run 在前台显示可核验阶段并可取消，回到前台或重启后从服务端恢复，不展示隐藏推理。
13. 移动回答以结构化状态区分正常、部分结果、知识不足、失败和澄清。引用先作为正文后的来源条展示，打开后分区显示 Entry、项目/目录、Source 标题和本 Run 核验的原文快照；在后端尚未提供答案片段到 Evidence 的映射前，不伪造段落级内联引用。冲突必须能分别查看双方 Evidence，历史快照与当前知识状态不得混为一谈。

## 信息架构与关键页面

### 全局层

```text
项目
收集箱
搜索
账户
```

- 项目：项目列表、状态筛选和创建入口。
- 收集箱：全局采集、未归属 Source、处理状态和待确认入口。
- 搜索：跨项目查找已确认 Entry。
- 账户：个人设置、AI Provider 与数据管理，后续逐步补齐。

### 项目层

```text
项目首页
知识空间
确认台
采集与来源
AI 阅读
```

- 项目首页：下一步任务、最近知识、处理进度和项目理解，不做装饰性数据看板。
- 知识空间：目录、卡片、列表和知识全景（旭日图 + 思维导图）。
- 确认台：按采集审阅与批量处理。
- 采集与来源：项目内采集、Source 列表、处理状态、失败重试和来源详情。
- AI 阅读：Workspace 或项目范围的带引用知识对话；目录不作为范围选择项。现有项目页入口可在统一对话入口接入前作为过渡保留。

### 端侧职责

页面信息架构按桌面工作效率设计，不维护手机 Web 简化版。支持宽度、小屏阻断页与原生 App 的完整边界统一由[技术与端侧边界](技术与端侧边界.md#端侧产品边界)维护。
