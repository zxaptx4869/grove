# 原生移动端「收集」模块探索原型走查

## 原型基线

- 对应页面：`docs/prototypes/grove-mobile-capture-prototype.html`（自包含单文件，无外部依赖）。
- 功能依据：`docs/discussions/移动端收集模块规划-2026-09-22.md`。
- 主验收视口：390 × 844；扩展视口：360 × 800、412 × 915。
- 视觉语言：沿用 `docs/prototypes/grove-mobile-agent-prototype.html` 的绿色主题、原创林间线稿图标、平台中性安全区与四栏底部导航；图标与样式在新文件内重建，未改动既有原型。
- 应用壳：原型控制条（虚线，标注「正式实现不含此区域」）+ 收集首页 + 采集表单 + 全屏提交状态 + 只读来源详情 + 底部 Sheet + 平台中性键盘示意 + 四栏底栏。
- 入口排布：同一文件内 A/B 两个可切换变体，A 为四个动作平铺，B 为三个动作 + 相册下钻 Sheet。
- 关键状态：上传中、上传失败、处理启动失败、后端 400 文案原样透传（超 5 张 / 单张超 10MB / 格式不支持）、waiting、processing、done（待确认 N 条 / 部分确认 · N 条正式知识 / N 条正式知识）、failed + 重试、改归属成功（含「正在重新路由」中间态）与两种 409、删除二次确认、空状态、列表加载失败、相册与相机权限被拒、来源详情只读、图片放大。

## 采用的页面结构

- 收集首页以「采集入口区 + 筛选 + 最近来源」两段组织，入口区不使用彩色图标底，主操作由动作名称与一行说明承担。
- 列表条目用状态徽标表达处理阶段，副状态用轻量标签表达候选与正式知识数量；未归属显示中性标签，已归属显示项目名。
- 归属与删除放在条目内的次级操作区，风险动作用危险色描边按钮而非实心红底。
- 提交状态使用全屏状态卡，不显示伪造百分比；重试沿用同一次采集的语义写在文案里，不暴露幂等键。
- 来源详情为只读全屏层：元信息 → 原始材料（图片网格 / 文字正文 + 放大）→ OCR 文本 → AI 候选（「AI 候选 / 未应用」标签、目录建议、理由）→ 去路说明。
- 权限被拒页说明用途、列出三条数据边界，并提供「去设置」，同时说明不会反复弹窗。
- 输入框聚焦时显示平台中性键盘示意，底栏下移隐藏，提交区上移贴键盘顶边。

## 有意偏离

- 这是原生 App 产品形态的 HTML 交互原型，不是低于 1024px 的 Grove Web 业务页面，也不决定正式 App 技术栈。
- 顶部控制条、场景分支切换与 toast 提示属于原型专用，正式实现不含。
- 图片使用线稿示意图并标注「示意图」，不依赖网络素材；真实相册与系统相机不可在原型内唤起，入口点击后直接给出模拟结果。
- 候选在原型内固定为只读，不提供确认、拒绝、写入或归档；「确认候选请到桌面工作台」是去路说明，不是本轮要实现的能力。

## 验收结果

- 横向溢出：三个视口的 `documentElement.scrollWidth` 分别等于 360 / 390 / 412，`docOverflow` 均为 false；应用内无越界元素（左右边界检查为空）。
- 键盘态：三个视口下聚焦输入框后均进入 `keyboard-open`，底栏 `translateY(72.6px)` 隐藏，提交区底边与键盘顶边对齐（360 视口为 530 / 530，390 为 574 / 574，412 为 645 / 645），被聚焦字段完整可见。
- 上传中：多图提交显示「正在上传 4 张图片…」与本条材料的事实信息，无百分比文字或进度数值（`%` 匹配为 false）；提交中不提供返回入口，避免误以为可以并行重复提交。
- 上传失败与重试：显示「提交未成功」，说明材料未保存、已填内容保留、重试沿用同一次采集；重试成功后 toast 为「重试成功：沿用同一次采集，没有生成重复来源」，列表只增加一条来源。
- 处理启动失败：显示「来源已保存，但处理启动失败」，提供重试处理、查看来源与返回收集；列表对应条目状态为「处理失败」并带具体失败原因。
- 后端文案透传：400 三种场景分别显示服务端原文「一次最多上传 5 张图片」「单张图片不能超过 10MB」「仅支持 png、jpg、webp 图片」，并明确说明以上为服务端原文、材料未保存。
- 列表状态：waiting、processing、done（三种副状态）、failed 均可通过筛选、下拉刷新与顶栏刷新按钮推进，刷新两次后条目由「提取完成」变为「待确认 2 条」，失败条目重试后变为「提取完成 · 待确认 2 条」。
- 改归属：成功路径先显示「正在重新路由」，随后落到目标项目并提示「已改为未归属」；处理中来源显示「来源正在处理中，不能修改归属」；已被正式知识引用的来源显示「该来源已被正式知识引用，如需移动请先处理关联 Entry」，两处文案与后端一致。
- 删除确认：有待确认候选时提示「有 1 条待确认候选，删除将一并移除这些候选」；确认后条目被移除，空状态显示「还没有来源」并提供「从相册选一张」。
- 列表加载失败：显示「来源列表加载失败」与「重新加载」，重新加载后列表恢复。
- 来源详情只读：详情层内按钮只有「放大」一个，候选统一标注「AI 候选 · 未应用」并显示目录建议与理由，末尾只读说明为「移动端不提供确认、拒绝或写入操作。候选在你确认前不会成为正式知识；需要确认候选时，请到桌面工作台的确认台处理，或回对话里继续讨论。」；对比度与徽标排版正常，未出现被 `.candidate` 样式撑大的异常标签。
- 权限被拒：相册与相机两种情况均显示用途说明、三条边界与「去设置」；原型内点击「去设置」只提示「原型不跳转系统设置」。
- 弹层与 Sheet：相册选择、项目选择、删除确认三类 Sheet 与详情、提交、原图三类全屏层均可正常打开、滚动与关闭，关闭后回到触发位置。
- 功能走查：首页 → 各入口 → 表单 → 提交状态 → 列表各状态 → 详情 → 改归属 / 重试 / 删除全链路在三个视口均可点通，模拟动作前后状态一致。
- 控制台：三个视口全程无 error、无 warning、无未捕获异常。
- 本轮截图：72 张，覆盖 `home-variantA/B`、`album-sheet`、`form-multi/single/text-keyboard/keyboard`、`form-400`、`submit-uploading`、`submit-upload-failed`、`submit-retry-done`、`submit-process-failed`、`home-after-submit`、`detail`、`detail-readonly`、`lightbox`、`move-409-processing`、`move-ok-pending`、`move-ok-done`、`delete-confirm`、`list-empty`、`list-failed`、`permission-album/camera`，每类均为 360 / 390 / 412 三个视口。
- 剩余差异：无未解释的视觉偏差；toast 在列表页会短暂覆盖底部条目、在表单页位于原型演示区之上，属于原型提示位置，已在表单与键盘态调整到不遮挡提交按钮。

## 已知限制

- 原型内的图片、OCR 文本、候选与项目计数均为静态示例数据，不代表真实处理结果。
- 系统相册、系统相机、系统设置跳转只在原型内模拟，未与任何真实系统能力对接。
- 下拉刷新使用触屏拖拽事件模拟，桌面鼠标拖拽不触发，走查时可使用顶栏刷新按钮。
