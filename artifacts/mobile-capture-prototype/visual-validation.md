# 原生移动端「收集」模块探索原型走查

## 原型基线

- 对应页面：`docs/prototypes/grove-mobile-capture-prototype.html`（自包含单文件，无外部依赖）。
- 功能依据：`docs/discussions/移动端/收集模块/移动端收集模块规划-2026-09-22.md`。
- 主验收视口：390 × 844；扩展视口：360 × 800、412 × 915。
- 视觉语言：沿用 `docs/prototypes/grove-mobile-agent-prototype.html` 的绿色主题、原创林间线稿图标、平台中性安全区与四栏底部导航；图标与样式在新文件内重建，未改动既有原型。
- 应用壳：原型控制条（虚线，标注「正式实现不含此区域」）+ 收集首页 + 采集表单 + 全屏提交状态 + 只读来源详情（含底部固定操作条）+ 底部 Sheet + 平台中性键盘示意 + 四栏底栏。
- 入口排布：已按用户选择收敛为方案 B，三个动作横排（相机 / 相册 / 文本），入口区不再有说明行；相册下钻 Sheet 提供「每张一条」与「多张合并一条」。两者都可以一次选择多张图片，区别是每张图片各成一条采集，还是合并成一条一起整理。
- 关键状态：上传中（两种入口的不同标题）、上传失败、处理启动失败、后端 400 文案原样透传（超 5 张 / 单张超 10MB / 格式不支持）、waiting、processing、done（待确认 N 条 / 部分确认 · N 条正式知识 / N 条正式知识）、failed + 列表重试、详情页改归属（含「正在重新路由」中间态）与两种 409、详情页删除二次确认、空状态、列表加载失败、相册与相机权限被拒、来源详情只读、图片放大。

## 采用的页面结构

- 收集首页顺序为：说明文案（一句话）+ 采集入口区（相机 / 相册 / 文本）+「最近收集」标题行（标题 + 条数）+ 筛选 + 来源列表。
- 筛选是「全部 / 未归属」两个轻量文字切换，带计数与选中下划线，放在「最近收集」标题下方，「全部」在前。
- 列表条目为「图标 + 标题 + 附件与时间 + 状态徽标」一行，下面是归属标签与候选副状态标签；失败条目额外显示失败原因与带边框的小按钮「重试」（40px 高，不是纯文字样式）。列表不展示补充说明，条目内也不放改归属与删除；补充说明只在来源详情的元信息里出现。
- 改归属与删除移到来源详情页底部的固定操作条，改回带边框的小按钮（「改归属」默认样式、「删除」危险色描边 + 浅红底），不随内容滚动。
- 表单的多张提示用两行：主句说明这一批怎么成条，副句用用户视角说明之后的处理方式，不提「来源」，也不把用户指去另一个入口重来。
- 相机来源的单张预览右上角是可点的「重拍」，点击后按序轮换模拟画面并更新标签；相册单张的「移除这张」仍是禁用态。
- 提交状态使用全屏状态卡，不显示伪造百分比；重试沿用同一次采集的语义写在文案里，不暴露幂等键。上传中在「每张一条」且张数大于 1 时写明「将分别生成 N 条采集」，正文统一为「这一批材料不会重复生成」。
- 来源详情为只读全屏层：元信息 → 原始材料（图片网格 / 文字正文 + 放大）→ OCR 文本 → AI 候选（「AI 候选 / 未应用」标签、目录建议、理由），底部固定操作条只作用于来源本身。页面不写「这里只读」说明。
- 权限被拒页说明用途、列出三条数据边界，并提供「去设置」，同时说明不会反复弹窗。
- 输入框聚焦时显示平台中性键盘示意，底栏下移隐藏，提交区上移贴键盘顶边。

## 有意偏离

- 这是原生 App 产品形态的 HTML 交互原型，不是低于 1024px 的 Grove Web 业务页面，也不决定正式 App 技术栈。
- 顶部控制条、场景分支切换与 toast 提示属于原型专用，正式实现不含。
- 图片使用线稿示意图并标注「示意图」，不依赖网络素材；真实相册与系统相机不可在原型内唤起，入口点击后直接给出模拟结果。
- 候选在原型内固定为只读，不提供确认、拒绝、写入或归档；详情页不写去路说明（2026-09-22 用户决定）。详情页的改归属与删除只影响来源记录，不触达候选。
- 方案 A（四个动作平铺）与 A/B 切换、列表行内的改归属与删除按钮均已按用户决定移除。
- 改归属与删除的阻断态只用列表里的 `locked` / `processing` 做前置预判，不模拟服务端 409 响应；实现层仍需保留服务端 409 兜底，因为列表数据可能已过期。

## 验收结果

- 横向溢出：三个视口的 `documentElement.scrollWidth` 分别等于 360 / 390 / 412，`docOverflow` 均为 false；应用内无越界元素。
- 首页文案：`#homeScroll .page-heading p` 为「先收进来，慢慢整理成自己的知识。」；入口区不再有 `.entry-note` 元素（数量 0）。
- 列表左留白：来源图标左边界 18px（390 / 412 视口）与 15px（360 视口），条目与入口区、标题行左对齐。
- 列表操作：三行示例条目的操作按钮分别为「无 / 无 / 重试」，页面内可点按钮为三个「查看来源详情：…」与失败条目的「重试」；未归属与处理中条目不再出现改归属或删除。
- 列表信息量：列表内 `.row-note` 元素数为 0，普通条目行高 92px（此前带补充说明时约 110px），三行示例条目的正文为「防水验收现场照片 | 4 张图片 · 今天 10:12 | 处理中 | 未归属」等；补充说明仍在来源详情的元信息里（例如「补充说明 | 补刷完成，等干燥后进入下一道工序」）。
- 筛选位置与尺寸：筛选行高 28px，位于「最近收集」标题与列表之间，顺序为「全部 6 → 未归属 3」，默认选中「未归属」。
- 详情底部操作条：三个视口下操作条底部与设备底部重合（390 视口 781–844、360 视口 737–800、412 视口 852–915，均等于应用高度 844 / 800 / 915），滚动详情内容后位置不变（`stableWhileScrolling` 为 true）。
- 详情只读：详情层内 `.readonly-note` 元素数为 0，正文内按钮只有「放大」，底部操作条按钮为「改归属」「删除」。
- 详情内改归属：点「改归属」→ 选「未归属」，详情保持打开，项目归属更新为「未归属」，toast 为「已改为未归属」；关闭详情后列表对应条目归属同步。
- 两种 409：处理中来源提示「来源正在处理中，不能修改归属」；已被正式知识引用的来源提示「该来源已被正式知识引用，如需移动请先处理关联 Entry」，并附「请先在桌面工作台处理关联的正式知识」的说明。
- 详情内删除：提示「「地漏周边补刷后照片」有 3 条待确认候选，删除将一并移除这些候选。确认删除？」，确认后详情关闭、列表条目移除、toast 为「已删除「地漏周边补刷后照片」」。
- 列表重试：失败条目的「重试」按 2 秒后回到「提取完成 · 待确认 2 条」。
- 每张一条 / 多张合并一条：表单分别显示 3 张与 4 张缩略图，说明为「这 3 张将分别作为 3 条材料提交」与「这 4 张将作为一条材料一起整理」；提交后分别新增 3 条（标题取图片标签）与 1 条来源。
- 上传中（每张一条，3 张）：标题「正在上传 3 张图片，将分别生成 3 条采集…」，正文「请保持 Grove 在前台。上传结束前不要重复提交，这一批材料不会重复生成。」，无百分比文字或进度数值。
- 上传中（多张合并一条，4 张）：标题「正在上传 4 张图片…」，正文与上一条相同。
- 轮询结果 toast：一次刷新推进 3 条同批来源时显示汇总文案「3 条采集处理完成，新增 6 条待确认候选」，不再是三条 note 用「；」拼接；只有一条 note 时仍用单条文案，toast 的位置、时长与触发时机未变。
- 表单多图提示：合并一条为「这 4 张将作为一条材料一起整理 / 这一批会一起整理成知识，不用逐张处理。」；每张一条为「这 3 张将分别作为 3 条材料提交 / 每张单独成为一条采集，之后可以分别处理。」
- 相机重拍：相机来源单张预览的按钮为「重拍」（相册单张仍为禁用的「移除这张」），点击后示意图与标签从「系统相机拍摄的现场照片」变为「重拍：管根加强层」，标签仍为「来自系统相机」，并提示「已重拍，换了一张新的照片」。
- 改归属 409 弹层：阻断时只渲染一段说明与「知道了」，弹层内 `.option-row` 数量为 0、按钮只有「知道了」；锁定场景为「不能修改归属 / 该来源已被正式知识引用，如需移动，请先到桌面工作台处理关联的正式知识。」，处理中场景为「不能修改归属 / 来源正在处理中，等处理结束后再修改归属。」；正常来源的项目列表与勾选未变。
- 上传失败与重试：提交未保存，提供重试且沿用同一次采集（提示「重试成功：沿用同一次采集，没有生成重复采集（共 3 条）」）；处理启动失败提供重试、查看来源与返回收集。
- 后端文案透传：400 场景显示服务端原文「一次最多上传 5 张图片」，并说明以上是服务端原文、材料没有保存。
- 空状态与加载失败：空状态显示「还没有来源」与「从相册采集」；加载失败显示「来源列表加载失败」与「重新加载」。
- 键盘态：三个视口下聚焦输入框后底栏隐藏，提交区底边与键盘顶边对齐（360 视口 530 / 530，390 为 574 / 574，412 为 645 / 645），被聚焦字段完整可见。
- 控制台：三个视口全程无 error、无 warning、无未捕获异常。
- 本轮截图：84 张，覆盖 `home`、`album-sheet`、`form-separate`、`form-merged`、`form-camera`、`form-camera-retake`、`form-text-keyboard`、`form-keyboard`、`form-400`、`submit-uploading`、`submit-uploading-merged`、`submit-upload-failed`、`submit-retry-done`、`submit-process-failed`、`home-after-submit`、`detail`、`detail-bottom`、`lightbox`、`move-from-detail`、`move-from-detail-done`、`move-409-processing`、`move-409-locked`、`delete-confirm`、`list-after-delete`、`list-empty`、`list-failed`、`permission-album`、`permission-camera`，每类均为 360 / 390 / 412 三个视口。
- 剩余差异：无未解释的视觉偏差；toast 会短暂覆盖底部内容（列表页覆盖末条、详情页覆盖操作条上方），属于原型提示位置。

## 已知限制

- 原型内的图片、OCR 文本、候选与项目计数均为静态示例数据，不代表真实处理结果。
- 系统相册、系统相机、系统设置跳转只在原型内模拟，未与任何真实系统能力对接。
- 下拉刷新使用触屏拖拽事件模拟，桌面鼠标拖拽不触发，走查时可使用顶栏刷新按钮。
