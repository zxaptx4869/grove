# 原生移动端「收集」模块探索原型走查

## 原型基线

- 对应页面：`docs/prototypes/grove-mobile-capture-prototype.html`（自包含单文件，无外部依赖）。
- 功能依据：`docs/discussions/移动端收集模块规划-2026-09-22.md`。
- 主验收视口：390 × 844；扩展视口：360 × 800、412 × 915。
- 视觉语言：沿用 `docs/prototypes/grove-mobile-agent-prototype.html` 的绿色主题、原创林间线稿图标、平台中性安全区与四栏底部导航；图标与样式在新文件内重建，未改动既有原型。
- 应用壳：原型控制条（虚线，标注「正式实现不含此区域」）+ 收集首页 + 采集表单 + 全屏提交状态 + 只读来源详情 + 底部 Sheet + 平台中性键盘示意 + 四栏底栏。
- 入口排布：已按用户选择收敛为方案 B，三个动作横排（相机 / 相册 / 文本）；相册下钻 Sheet 提供「每张一条」与「多张合并一条」。两者都可以一次选择多张图片，区别是每张图片各成一条采集，还是合并成一条一起整理。原型内不再保留 A/B 切换。
- 关键状态：上传中、上传失败、处理启动失败、后端 400 文案原样透传（超 5 张 / 单张超 10MB / 格式不支持）、waiting、processing、done（待确认 N 条 / 部分确认 · N 条正式知识 / N 条正式知识）、failed + 重试、改归属成功（含「正在重新路由」中间态）与两种 409、删除二次确认、空状态、列表加载失败、相册与相机权限被拒、来源详情只读、图片放大。

## 采用的页面结构

- 收集首页顺序为：说明文案 → 采集入口区（相机 / 相册 / 文本 + 一行说明）→「最近收集」标题行（标题 + 条数）→ 筛选 → 来源列表。
- 筛选是「全部 / 未归属」两个轻量文字切换，带计数与选中下划线，放在「最近收集」标题下方，不再使用带边框底色的分段控件，「全部」在前。
- 列表条目为「图标 + 标题 + 附件与时间 + 状态徽标」一行，下面是归属标签与候选副状态标签、补充说明，最后一排是图标操作按钮。
- 改归属、重试、删除都使用 34 × 34 的图标按钮，带 `aria-label` 与 `title`；删除保留危险色描边与浅红底。
- 提交状态使用全屏状态卡，不显示伪造百分比；重试沿用同一次采集的语义写在文案里，不暴露幂等键。
- 来源详情为只读全屏层：元信息 → 原始材料（图片网格 / 文字正文 + 放大）→ OCR 文本 → AI 候选（「AI 候选 / 未应用」标签、目录建议、理由）。页面不再单独写「这里只读」说明，只读通过「没有任何确认、拒绝、写入或归档操作」体现。
- 权限被拒页说明用途、列出三条数据边界，并提供「去设置」，同时说明不会反复弹窗。
- 输入框聚焦时显示平台中性键盘示意，底栏下移隐藏，提交区上移贴键盘顶边。

## 有意偏离

- 这是原生 App 产品形态的 HTML 交互原型，不是低于 1024px 的 Grove Web 业务页面，也不决定正式 App 技术栈。
- 顶部控制条、场景分支切换与 toast 提示属于原型专用，正式实现不含。
- 图片使用线稿示意图并标注「示意图」，不依赖网络素材；真实相册与系统相机不可在原型内唤起，入口点击后直接给出模拟结果。
- 候选在原型内固定为只读，不提供确认、拒绝、写入或归档；详情页不写去路说明（2026-09-22 用户决定），需要确认候选时仍按产品规则到桌面工作台处理。
- 方案 A（四个动作平铺）与 A/B 切换已按用户决定移除；如需重新比较，可从本次提交前的历史版本取回。

## 验收结果

- 横向溢出：三个视口的 `documentElement.scrollWidth` 分别等于 360 / 390 / 412，`docOverflow` 均为 false；应用内无越界元素。
- 列表左留白：来源图标左边界从修改前的 58px（`ul` 默认 40px 内边距）回到 18px（390/412 视口；360 视口为 15px），标题左边界为 62px，条目内容与入口区、标题行左对齐。
- 筛选位置与尺寸：三个视口下筛选行高 28px，位于「最近收集」标题下沿与列表首条之间（390/412 视口标题下沿 377、筛选 385–413、列表 415 起），顺序为「全部 6 → 未归属 3」，默认选中「未归属」。
- 条目操作：改归属 / 重试 / 删除均为 34 × 34 图标按钮，可访问名称为「改归属」「重试处理」「删除来源」；失败条目同时显示重试与删除，不换行。
- 入口：三个视口均为三个动作横排（相机 / 相册 / 文本），说明行为「相册进入后再选「每张一条」或「多张合并一条」：前者每张图片各成一条采集，后者合并成一条一起整理。」；页面内已无 `[data-variant]` 控件。
- 相册下钻：Sheet 文案为「每张一条 · 选 1–5 张图片，每张单独作为一条采集」与「多张合并一条 · 选 2–5 张图片，合并成一条采集一起整理」。
- 每张一条：表单显示 3 张缩略图与「这 3 张将分别作为 3 条材料提交」，提交后列表新增 3 条来源，标题分别为「墙面涂刷范围」「管根加强层」「闭水水位标记」，各自独立处理。
- 多张合并一条：表单显示 4 张缩略图与「这 4 张将作为一条材料一起整理」，提交后只新增 1 条来源。
- 上传中：多图提交显示「正在上传 3 张图片…」与本条材料的事实信息，无百分比文字或进度数值；提交中不提供返回入口。
- 上传失败与重试：「提交未成功」说明材料未保存、已填内容保留、重试沿用同一次采集；重试成功提示「重试成功：沿用同一次采集，没有生成重复采集（共 3 条）」，列表只增加对应条数。
- 处理启动失败：「来源已保存，但处理启动失败」，提供重试处理、查看来源与返回收集；列表对应条目为「处理失败」并带具体原因。
- 后端文案透传：400 场景显示服务端原文「一次最多上传 5 张图片」，并说明以上是服务端原文、材料没有保存。
- 列表状态：刷新后条目由「处理失败 / 处理中」推进到「提取完成」并出现「待确认 2 条」，顶部条数与状态一致。
- 改归属与删除：处理中来源显示「来源正在处理中，不能修改归属」；成功路径先显示「正在重新路由」再落到目标项目；删除前提示「「地漏周边补刷后照片」有 3 条待确认候选，删除将一并移除这些候选。确认删除？」，确认后条目移除。
- 列表加载失败：显示「来源列表加载失败」与「重新加载」；空状态显示「还没有来源」与「从相册采集」。
- 来源详情只读：详情层内 `.readonly-note` 元素数为 0，按钮只有「放大」一个；候选统一标注「AI 候选 · 未应用」并显示目录建议与理由，滚动到底后页面以最后一条候选结束。
- 权限被拒：相册与相机两种情况均显示用途说明、三条边界与「去设置」；原型内点击「去设置」只提示「原型不跳转系统设置」。
- 键盘态：三个视口下聚焦输入框后底栏 `translateY` 隐藏，提交区底边与键盘顶边对齐（360 视口 530 / 530，390 为 574 / 574，412 为 645 / 645），被聚焦字段完整可见。
- 控制台：三个视口全程无 error、无 warning、无未捕获异常。
- 本轮截图：69 张，覆盖 `home`、`album-sheet`、`form-separate`、`form-merged`、`form-camera`、`form-text-keyboard`、`form-keyboard`、`form-400`、`submit-uploading`、`submit-upload-failed`、`submit-retry-done`、`submit-process-failed`、`home-after-submit`、`detail`、`detail-bottom`、`lightbox`、`move-409-processing`、`move-ok-pending`、`delete-confirm`、`list-empty`、`list-failed`、`permission-album`、`permission-camera`，每类均为 360 / 390 / 412 三个视口。
- 剩余差异：无未解释的视觉偏差；toast 在列表页会短暂覆盖底部条目、在表单页位于原型演示区之上，属于原型提示位置。

## 已知限制

- 原型内的图片、OCR 文本、候选与项目计数均为静态示例数据，不代表真实处理结果。
- 系统相册、系统相机、系统设置跳转只在原型内模拟，未与任何真实系统能力对接。
- 下拉刷新使用触屏拖拽事件模拟，桌面鼠标拖拽不触发，走查时可使用顶栏刷新按钮。
